Transformer：架构、训练、推理与应用综述

通用架构与序列建模

原创研读与整理 · 原创综述 · 更新于 2026-10-15

引用文献与图示遵循各自原有许可与权利要求。

出处与说明

本篇是围绕输入表示、交互计算、学习目标与应用接口组织的原创综述。主要方法证据包括原始 Transformer、BERT、ViT、MAE、CLIP，以及 MoE、GQA、MLA、DeepSeek DSA、MiniMax MSA、LoRA、偏好优化、投机采样、GPTQ、DETR、Whisper、PatchTST 和蛋白质语言建模的原始来源；DSec 作为智能体训练基础设施案例，相关综述提供分类与系统线索。训练／推理框架部分另依据固定提交的 FlashAttention 及本地框架源码，区分算子、训练执行、引擎调度与服务；不将旧研读笔记的性能比较当作实测。语言、视觉、音频、时间序列及蛋白质序列按各自输入、目标和评价条件讨论，不作全领域覆盖或跨任务性能保证。

预训练、后训练与 KV 管理按具体任务辨认，不作为所有模态的共同流程。一般容量公式与假设数字是机制解释，不是实测结果；引用实验与生产经验属于原作者报告，未进行训练、系统部署或独立复现。

token 词元（token） 序列处理单位；文本中可为词、子词或其他离散单位
tokenization / tokenizer 词元化／tokenizer 输入划分过程／相应工具；不默认以单词为边界

query / key / value 查询／键／值（Q／K／V） 注意力的匹配与汇聚分工，不指数据库字段
self-attention 自注意力 查询、键和值来自同一输入序列的表示

multi-head attention (MHA) 多头注意力（MHA） 多组投影并行计算，之后拼接和投影；标准形式中各头有独立 K／V

DeepSeek Sparse Attention (DSA) DeepSeek 稀疏注意力（DSA） 用轻量索引器选择历史词元，主分支在入选集合上计算
MiniMax Sparse Attention (MSA) MiniMax 稀疏注意力（MSA） 每个 GQA 组独立选历史块；与多头自注意力、多序列比对同名不同义

attention mask 注意力掩码 限定位置可见性；不等同输入中的 [MASK] 词元

residual connection 残差连接 将子块输出与旁路输入相加

Mixture of Experts (MoE) 混合专家（MoE） 本篇重点是以稀疏路由专家替换逐位置 FFN，不是多个完整模型投票
routed expert / shared expert 路由专家／共享专家 按输入选择的分支／每词元始终执行的公共分支
router / gating weight 路由器／门控权重 决定调用分支／控制返回输出的混合幅度，二者的分数未必相同
capacity factor / token dropping 容量因子／词元分支丢弃 专家槽位余量／溢出时跳过专家计算，不等于删除整个序列位置
total / activated parameters 总参数／激活参数 保存的全部参数／单词元调用的参数；两者均不能直接替代 FLOPs
floating-point operations (FLOPs) 浮点运算量（FLOPs） 与 FLOP/s 速率、访存字节和端到端时延区分
encoder / decoder 编码器／解码器 按职责辨认；重建解码器不一定自回归
image tower / text tower 图像编码器／文本编码器 tower 指相对独立的编码分支，不是特殊网络层
dual-encoder / two-tower architecture 双编码器／双塔架构 两个分支分别编码输入，再比较投影后的表示
pretraining / post-training 预训练／后训练 训练安排，不是所有任务的固定生命周期
fine-tuning 微调 在目标任务下更新指定模型参数

low-rank adaptation (LoRA) 低秩适配（LoRA） 分解权重增量，基座权重本身不必低秩
supervised fine-tuning (SFT) 监督微调（SFT） 用条件输入与目标输出训练，目标角色与损失范围需区分
reinforcement learning from human feedback (RLHF) 人类反馈强化学习（RLHF） 用偏好等反馈建立奖励并优化策略
reward model / Bradley–Terry model 奖励模型／Bradley–Terry 模型 标量代理评价／由奖励差表达成对偏好的模型
proximal policy optimization (PPO) / advantage 近端策略优化（PPO）／优势 控制局部策略更新的算法／动作相对条件基线的收益
direct preference optimization (DPO) 直接偏好优化（DPO） 以参考校正的策略概率比拟合偏好，无须显式奖励优化循环
reference policy / behavior policy 参考策略／行为策略 整体偏离基准／实际产生样本的策略，不自动是同一模型
masking / reconstruction 遮挡／重建 交代遮挡对象和预测目标
contrastive learning 对比学习 对相对匹配施加监督，不自动生成文本
masked language modeling (MLM) 掩码语言建模（MLM） 预测选中位置的原词元，目标选择与输入替换比例不同
next sentence prediction (NSP) 下一句预测（NSP） 原版 BERT 的片段连续性二元判别，不是下一词元生成
cross-entropy / KL divergence 交叉熵／KL 散度 条件预测风险／分布差异；KL 一般不对称

linear probing 线性探测 冻结表示模型、训练线性任务头
zero-shot 零样本 限定目标任务适配协议，不否认已有预训练监督

1. 基础原理与架构演进

Transformer 将序列建模分解为输入表示、位置关系、内容交互和特征变换，并通过任务目标组织这些组件。本节先从基本计算说明这些分工，再分析局部连接、累计状态和输入粒度怎样改变信息传播与资源需求。原始方法论文提供模型定义，架构综述提供比较视角。[1–4, 6, 9, 10]

序列表示、位置与输入组织

Transformer 拿到的输入是一个矩阵。设序列长度 N、隐藏维度 d，矩阵 X∈ℝN×d 的每一行是一个处理单位。文本词元、图像块、音频片段、时间观测都能占这个位置，划分规则决定了哪些细节先被合进同一个向量、哪些关系留给后面的层去学。[2, 6, 9]

从离散单位到可学习表示

文本一侧的起点是词表。嵌入矩阵的每一行对应一个词元，取表示就是选行，再叠加位置和片段信息。BERT 用 WordPiece 切分，把词元嵌入、位置嵌入、片段嵌入三者相加，两个文本片段用分隔词元拼在同一条序列里，双向注意力可以直接在片段之间建立联系。[1] 同一词元在不同位置得到不同表示，靠的是后续层的上下文交互——词表向量只是起点，不携带"这个词是什么意思"的固定定义。

视觉一侧的起点是连续像素。对高、宽分别为 H、W、通道数为 C 的图像，取边长 P 的不重叠图块，空间尺寸可整除时序列长度和图块向量为：[2]

N=HWP2,xi∈ℝP2C,zi=xiE+pi

代入 224×224 的输入和 16×16 的图块：序列长度是 224×224/162=196，每个图块向量 16×16×3=768 维，投影矩阵 E 的形状是 768×d。E 在图块之间共享，所以每个图块都用同一套局部特征提取规则，区分它们出现位置的是位置向量 pᵢ。把 P 减半，序列长度涨到四倍，后面每一层的交互成本随之变化；图块边界由网格决定，与对象边界无关，横跨两个图块的物体会被切开，需要在上下文里重新组合。

置换等变性：顺序为什么会丢

不含位置信息、掩码或任何位置相关偏置的自注意力，对输入行的重排是等变的。设 Π 为置换矩阵，F 表示一层内容自注意力。线性投影共享，于是 Q′=ΠQ，键与值同理，分数矩阵的行列被同时重排：

S′=ΠSΠT,softmax(S′)=Πsoftmax(S)ΠT

右式成立的理由是 softmax 按行归一化：重排列只改变求和项的顺序，重排行只改变哪条查询落在哪一行。再代入 ΠTΠ=I，得到

F(ΠX)=ΠF(X)

输入内容换个顺序，输出跟着换个顺序，网络无法仅凭数组下标获得新的顺序关系。逐位置共享的前馈层和归一化同样保持这一性质。在上述条件之外再加上对称池化（取平均、取最大这类聚合），连整体的置换不变性都出现了：打乱行得到的表示和原来完全一样。于是语言中的先后、图像中的空间布局必须显式进入计算。[6, 9]

加性位置嵌入的做法是改变这个对称性：只重排词元时，ΠX+P 与 Π(X+P) 一般不相等。相对位置方法换个入口，把位置差做进查询与键的匹配，表达的是"相距多远"。两者施加的结构不同：前者要求模型自己从绝对坐标里推关系，后者把关系直接写进打分。原始 ViT 用可学习的绝对位置向量，换分辨率时按二维图块布局对这些参数做插值。[2] 位置表示让模型有条件辨认布局，局部窗口与层级结构这类先验仍由后面的层负责。

缩放点积注意力、多头注意力与交叉注意力

一个位置要看全部历史，就需要一次可微的、权重随输入变化的加权平均。注意力用三个投影把这件事拆开：一个投影决定"我在找什么"，一个决定"我有什么可供匹配"，一个决定"匹配上之后我给出什么"。对输入 X∈ℝN×d，单头自注意力先做三次投影：[6]

Q=XWQ,K=XWK,V=XWV

再用键维度 dk 归一化点积，加可见性掩码，按行 softmax，最后汇聚值：

S=QKTdk+M,Aij=exp(Sij)∑texp(Sit),Y=AV

掩码在可见位置取零、不可见位置取负无穷，softmax 之后这些位置的权重正好是零。每行至少有一个有效键时，权重非负且和为 1，输出落在值向量的凸组合里。权重本身依赖输入，整个映射因此随输入变化，注意力与固定卷积核的分工正在这里。

缩放项处理的是方差量级

原始 Transformer 用点积的方差解释这个除以根号的操作。[6] 假设查询和键的各分量相互独立、均值为零、方差为一，点积是 dk 个独立乘积之和，方差随维度线性增长：

Var(qTk)=dk,Var(qTkdk)=1

代入具体数字更直观：dk=64 时点积的标准差是 8，比单个分量大一个量级；dk=128 时是 11 左右。分数拉开之后，softmax 会把大部分质量堆到最大的那个分量上，一行 softmax 的分量 aj 的导数说明了后果：

∂aj∂st=aj(δjt−at)

当某个权重逼近 1、其余逼近 0 时，这些导数一起趋向零，改动多数分数几乎挪不动分配结果，梯度就此变得稀疏而弱。除以 dk 把初始量级拉回 1，缓解的是这个饱和倾向。训练之后的查询与键可以高度相关，上述独立假设随之失效，因此缩放只解决初始化的量级问题，最终分布仍由尺度、归一化和训练共同决定。

多头在投影子空间里分工

多头注意力分别计算每头的输出，拼接后再做一次输出投影：

MHA(X)=Concat(Y1,…,YH)WO

单头对每个查询给出一组位置权重，多个头允许不同子空间采用各自的分配，再各自携带汇聚到的值；输出投影负责把这些通道重新混合。容量来自可学习的差异：若所有头用同一套投影、产生同一份结果，拼起来只是把同一个向量重写一遍，头数增加带不来额外信息。参数总量固定时，增加头数会减小每头维度，同时改变硬件上的计算形状，因此头数存在实际的最优点。

可见性与信息来源各管一件事

自注意力的查询、键、值来自同一条序列；交叉注意力让查询来自目标表示、键与值来自源表示。目标长度 T、源长度 S 时，交叉注意力的权重矩阵形状是 T×S，它学习的是目标位置如何挑选源信息，两侧位置之间不需要一一对应。[6]

因果自注意力再加一层限制：第 i 个位置只能读不晚于它的位置。这条约束针对条件依赖，与"信息来自哪一侧"互不干涉。把两者组合起来，就有了常见配置的差异：BERT 双向编码文本，翻译解码器用因果自注意力处理已生成部分、再用交叉注意力读源端，CLIP 用因果文本编码器配合图文匹配目标。[1, 4, 6] 模型最终做生成还是做匹配，取决于输出接口与目标函数，与注意力本身的结构无关。

残差连接、归一化与前馈网络

注意力沿位置轴搬运信息，前馈网络沿特征轴变换每个位置，残差和归一化把这两类子层拼成可训练的深栈。位置放错地方，输出尺度和经过的梯度算子都会变：原始 Transformer 先加残差再归一化，ViT 把 LayerNorm 放到子层之前。[2, 6]

残差提供恒等通路，归一化改写特征尺度

对一个位置的向量 x∈ℝd，LayerNorm 沿特征维取均值和方差：

μ=1d∑rxr,σ2=1d∑r(xr−μ)2

LN(x)=γ⊙x−μ1σ2+ε+β

统计量取自单个位置自身的特征，一个批里不同序列的同一特征不会相互混入，这一点让它在变长序列和小批量下都能用。可学习的 γ 与 β 把归一化后的特征重新缩放、平移，模型因此不必被迫接受单位方差。残差则把旧表示原样留下，让子层只学一个增量：子层输出为零时，未归一化的那条通路直接把输入送到下一层。

用 F 表示注意力或前馈子层，两种常见放置的映射是：

ypre=x+F(LN(x)),ypost=LN(x+F(x))

在可微点上用链式法则，两者的雅可比因子顺序不同：

Jpre=I+JFJLN,Jpost=JLN(I+JF)

各式中的雅可比在对应中间变量处求值。Pre-LN 的恒等支路不必先穿过归一化的雅可比；Post-LN 的两条支路相加之后一起过归一化。这个差别可以直接从因式分解看出来，而训练稳不稳还取决于深度、初始化、学习率和其他组件，[9] 把雅可比顺序当成稳定性的充分解释会走得太远。

归一化还有一个容易忽略的性质：对任意标量 c，LN(x+c1)=LN(x)。因为均值同样增加了 c，中心化之后完全抵消，该方向上的导数恒为零。落到模型上，这意味着沿各位置共同偏移的方向（例如"所有词元都更倾向于某类语义"）在归一化处被抹掉，要找回来只能靠后面的可学习仿射或其他子层。残差与归一化的相对位置，决定了哪些信息先被合并、哪些方向先被消去。

前馈层在特征维上扩展再压缩

逐位置前馈网络写成：

FFN(x)=φ(xW1+b1)W2+b2

第一层把 d 维输入打到通常更宽的中间空间，非线性在这里做特征选择，第二层再收回残差需要的维度。去掉非线性，两次线性变换可以合并成一个仿射映射，中间宽度就失去意义。按原始 Transformer 的配置 d=512、d_ff=2048 算参数：W₁ 是 512×2048、W₂ 是 2048×512，两层各约 105 万参数，加起来是这个块里最大的一块权重——注意力的四个投影 Q、K、V、O 合计 4×512²≈105 万，与前馈的两层相当，但在长序列下注意力的算术量会反超。

原始 Transformer 用 ReLU，ViT 用 GELU。[2, 6] 以 ReLU 为例，每个中间单元先判断一个线性组合是否为正，再决定输出多少；最终结果由被激活的那些特征重新组合。注意力把别处的信息搬到当前位置，前馈层对搬来的信息重新编码。它不扩大位置之间的可见范围，只提升每个位置处理信息的能力，代价是计算与激活占用随序列长度线性增长。

MoE：把参数容量与每词元计算分开

稠密 Transformer 里，每个词元都要过同一套前馈权重，参数涨多少，每词元的计算量就跟着涨多少。MoE 把这份权重拆成 E 个互不共享的分支（专家），再用一个学出来的路由器为每个词元挑 k 个执行。参数容量随 E 增长，单词元要付的专家算术量只按 k 计。Switch Transformer 用 Top-1 路由说明这种简化仍然训得起来，DeepSeek-V2 与 V3 在此之上加入细粒度专家、共享专家和偏置式负载均衡。[31–33]

路由器决定调用哪几个分支

设单个位置的输入为 x∈ℝd，E 个路由专家各自给出 d 维输出 Fe(x)。路由矩阵 Wr∈ℝE×d 打出 E 个分数，softmax 归一化后取 Top-k：

z=Wrx,pe=exp(ze)∑jexp(zj),S(x)=TopK(p,k)

TopK 返回的是专家索引。把入选分支的输出按门控权重相加，就得到这一子层的专家部分：

ge=pe∑j∈S(x)pj,y=∑e∈S(x)geFe(x)

每个位置独立路由，同一句话里的不同词元、同一词元在不同层，都可以落到不同专家上。稀疏发生在被执行的分支集合，专家内部仍是适合矩阵乘的稠密网络；共享专家若有，其输出另行加入 y，残差连接再加上 x。

上面这套写法在入选集合内重新归一化门控，Switch 的 Top-1 并不这么做：它保留原始 softmax 门值。这样一来，唯一入选者的门值并不恒等于 1，任务损失才能通过它对输出幅度施加影响。把 Top-1 的门值强行归一化为 1，等于切断了这条路径。离散的索引本身没有梯度，但入选集合固定时，连续门值与入选专家的输出照常可微，路由器的学习信号由此产生。DeepSeek-V3 改用了 sigmoid 亲和分数，再对入选分数归一化，并且给选择过程加了偏置。[31, 33]（分别见 §2.1、§2.1.2）

总参数、激活参数与 FLOPs 是三笔账

设每个路由专家有相同参数量 Pexp，路由器、共享专家等常开部分合计 P₀，每词元选 k 个专家，那么：

Ptotal=P0+EPexp,Pactive≈P0+kPexp

按这个口径算一个例子：保存 8 个等宽路由专家、每次调用 2 个，专家权重占用的存储是单专家的 8 倍，而每词元要做的专家矩阵乘只对应约 2 份。E 增加而 k 与专家宽度不变时，可选择的参数变多，路由、跨卡搬运和总权重存储一并增长。一批请求里的不同词元会落到不同专家上，其并集完全可能覆盖全部专家，因此显存要按总参数准备。

激活参数也替换不了 FLOPs。长序列的注意力交互不体现在专家参数计数里，嵌入层的参数用法与专家层又不一样。MoE 的容量收益来自不同数据可以用到不同的参数子集，这份分工能不能形成，取决于数据、路由与优化过程，跟专家是否恰好对应"数学""代码"这类可命名的领域没有关系。

DeepSeekMoE 把专家切得更细，并隔离出共享专家。[32]（§2.2.1）把专家宽度缩到 1/m、专家数与每次入选数同时扩大 m 倍，总专家参数和激活专家算术量大致不变，可组合的分支数却增加了。共享专家让每个词元都走一条公共变换，路由专家于是不必各自重复承担通用成分。更细的分支也意味着更碎的工作和更大的路由扇出，组合数量的增加本身不构成质量保证。

负载均衡同时影响训练与等待时间

路由集中到少数专家，冷门专家拿不到训练样本，热门专家要么溢出、要么拖住整个并行组。以 Switch 的 Top-1 为例，T 个词元中真正送给专家 e 的比例为 fₑ，路由器对该专家的平均概率为 Pₑ，辅助项写成：[31]（§2.2）

fe=1T∑t𝟙[S(xt)={e}],Pe=1T∑tpe(xt),ℒbal=αE∑efePe

Pₑ 是概率统计，与前文专家参数量的符号只在各自小节内使用。fₑ 由硬分派产生，反向时把当前 f 当作固定统计，梯度经由 Pₑ 回到路由器：负载偏高的专家受到抑制压力，偏低的获得鼓励。这是一股均衡诱导的力，每一步并不严格等分，均衡本身也不证明语义分工最优。α 取大时，路由会优先照顾均衡，与"选到对当前数据有用的专家"这个目标发生竞争。

固定容量的实现按 C=⌈φTk/E⌉ 规划每个专家的槽位，φ 是容量因子，Switch 对应 k=1 的情形。φ 调大能容纳更多偏斜，代价是填充、缓冲和可能的无效计算。Switch 里溢出的词元跳过这一专家子层，经残差继续往上走，序列位置本身并未消失。改用无丢弃的变长打包，实际负载、分组矩阵乘和尾部等待就直接压在实现上，失衡的成本从丢弃逻辑转移到实现里。[31]（§2.2）

DeepSeek-V3 走的是另一条路线：给每个专家挂一个只参与排名的偏置 bₑ，按 si,t+bi 排 Top-k，过载专家的偏置降低、空闲专家的偏置升高；输出混合权重仍由原始亲和分数算，偏置不进入前向数值。[33]（§2.1.2）这样一来，负载控制与输出幅度分开了：调偏置只改变谁被选中，不改变选中后的混合比例。所谓"辅助损失自由"针对的是主要均衡手段，报告仍保留一个系数极小的序列级辅助项，用于防止单条序列内部极端偏斜。批次级均衡、单序列偏斜和实际设备负载是三个不同的统计量，它们怎么转成通信与等待，取决于专家并行的放置方式。

EP：专家怎么分布，词元怎么往返

MoE 决定用哪些参数，专家并行（Expert Parallelism，EP）决定这些参数放在哪张卡上、输入怎么送达。上万专家的权重放不进单卡，于是按专家切分到多设备，词元隐藏状态以数据的形式流动到专家所在地执行。单卡也能跑 MoE，采用 EP 也不要求一张卡只放一个专家。Switch 的并行分析和 DeepSeek-V3 的通信设计都把分派与返回当作关键成本。[31, 33]（分别见 §5.4–5.5、§3.2）

一次前向要两次重排

设一个 EP 组内共有 T 个词元、隐藏维度 d、每词元选 k 个路由专家，且不发生容量丢弃。原始词元矩阵是 X: [T, d]，路由给出 expert_ids: [T, k] 与 gates: [T, k]。本地的排列方式是"按原序列位置"，专家却要求输入按专家归组，中间必然有一次重排：

原词元、来源位置 [T, d]
    → 路由：每词元的 k 个专家编号与门值
    → 打包：按目标设备／专家重排，同时记下逆置换和有效长度
    → dispatch：把输入隐藏状态送到持有该专家权重的设备
    → 专家计算：本地专家对自己的词元批做矩阵乘
    → combine：把各分支结果送回来源设备
    → 按逆置换还原并乘门值求和，恢复 [T, d]

发送端至少要保留原词元编号、分支身份、门值和返回映射；接收端需要每个专家的有效计数与偏移，才能把零散词元拼成规整的词元批。输入先按目标分桶，到达后再按本地专家归组，逐词元的小操作才可能合并成分组矩阵乘。dispatch 与 combine 一般走 all-to-all 或等价的分层／点对点通信，只把词元送到它选中专家所在的设备。[31, 33]（分别见 §5.4、§3.2.1–3.2.2）

combine 做的是带权求和。一个词元的 k 个返回值分别乘各自门值再相加，结果才等于 MoE 的数学定义。同设备上有多个入选专家时，输入和返回值都能在本地合并或归约，网络上的实际包数因此低于 T·k，逻辑分支数仍是 T·k。

举个具体例子：设备 A 持有专家 0、1，设备 B 持有专家 2、3。位于 A 的词元 u 选中专家 1 与专家 3，门值 0.7 与 0.3。A 本地执行专家 1，同时把 u 的隐藏向量发给 B 的专家 3，返回后拼出 0.7 * F1(u) + 0.3 * F3(u)。这里跨卡移动的是激活，专家权重在前向期间一直驻留；返回映射若丢失，专家输出的数值仍然正确，却会写到错误的位置上。

反向传播沿相反的数据依赖走：输出梯度按原路回到各专家，专家输入梯度汇合，权重梯度在自己所在的设备上累积。训练整步的通信次数超出前向的两次重排，同一专家若在多个并行组里有副本，还要同步副本梯度。

EP、TP、DP、PP 各自划分什么

并行方式 划分或复制的对象 主要的数据关系
专家并行（EP） 专家分布到不同设备 词元按路由送到目标专家，再返回
张量并行（Tensor Parallelism，TP） 同一个矩阵或算子的张量维度 多设备合力完成一次计算，交换或归约部分结果
数据并行（Data Parallelism，DP） 参数副本处理不同数据 训练时同步相应参数梯度或分片状态
流水线并行（Pipeline Parallelism，PP） 不同层位于不同阶段 激活与梯度在相邻阶段流动，依赖微批调度

四种划分可以叠加：一个专家内部再做 TP，不同 EP 组互为专家副本，不同层分给 PP 阶段。每层叠加都需要单独定义通信组与参数所有权，并行度不能简单相乘。[31]（§5）

通信预算由跨设备分支数决定

设 R 为真正需要跨设备传输的词元—专家分支数，输入输出都是 d 维、每元素 b 字节。不做同目的地去重与本地归约时，一程输入加一程返回的有效载荷合计：

Dpayload≈2Rdb,0≤R≤Tk

每条跨设备消息计一次，发送端与接收端不重复累加，得到的是张量载荷；链路累计字节是另一个量。计数、索引、门值、填充、分层转发、反向通信与重传另算。代入 T=4,096、k=2、d=4,096、b=2，并假设全部分支都跨设备且不合并，两程合计 128 MiB。这个数字只说明张量本身要搬多少，不预测时延。

总专家数增多并不直接抬高这个量：k 固定时，路由扇出的上界不随 E 变化。真正变化的是别的地方——每位专家分到的词元变少，矩阵乘变碎，EP 组扩大后通信可能跨到更慢的互联层级。小批量解码同时撞上通信启动成本和小矩阵利用率，大批预填充则更容易凑出可观的专家批。

均衡要按设备看。设专家 e 的有效词元数为 nₑ，设备 r 持有专家集合 ℰᵣ，专家等宽，则设备 r 的工作量近似随 nr=∑e∈ℰrne 增长。需要等齐组内结果的阶段，时间由最慢的设备决定，平均值帮不上忙。专家宽度不一、精度不同或设备型号不同时，把词元计数换成相应工作量再比较。增加专家副本能缓解热点，代价是权重存储和副本选择、同步逻辑。

DeepSeek-V3 把节点限制路由与节点内转发配合起来：先限制一个词元的远端节点数，进入节点后再用节点内的高带宽链路分发给多个目标专家。[33]（§2.1.2、§3.2.2）"选中专家数"与"跨节点输入副本数"由此可以不同。限制路由收窄了可选专家集合；通信与计算重叠只在依赖允许、资源足够的条件下隐藏时间，要传的字节并不会因此减少。这些实现效果来自 H800 集群的具体配置，换一套互联、批量与负载分布，结论需要重新测。

编码器、解码器与编码器—解码器结构

这三个词先说清职责：编码器读输入、产出上下文化的表示；生成式解码器按已知条件给出下一个输出的分布；重建模块有时也叫解码器，但它的计算依赖可以完全两样。BERT、翻译 Transformer、MAE、CLIP 四种组合把这几种职责用得各不相同。[1–4, 6]

编码表示与自回归生成

BERT 的双向编码让一个位置同时看到两侧文本，适合产出分类、标注、跨度预测需要的表示。翻译模型的处理方式是：源序列先双向编码，目标侧再通过交叉注意力读这些表示。目标序列的联合条件概率按链式规则分解为：[6]

p(y1:T|x)=∏t=1Tp(yt|y<t,x)

训练时完整目标已知，于是把起始词元和右移一位的真实目标同时喂进去，因果掩码保证第 t 个位置的表示只依赖真实的先前目标。所有位置的条件损失因此能在一轮前向里算完。这个可行性有个前提：预测位置读不到自己的真实目标。一旦掩码失效，任务就退化成用泄漏的信息复现答案，与生成时的条件对不上。

推理阶段的处境反过来：未来目标未知，每步先得到条件分布，选出新词元再接回前缀，计算依赖只能逐步推进。训练的并行性来自"目标已知 + 可见性受限"，生成的串行性来自"目标未知 + 链式分解"，两者并不矛盾。decoder-only 结构去掉独立源编码器和交叉注意力，把提示与已生成前缀放进同一条因果序列；encoder–decoder 保留两侧表示，也保留了"读源、写目标"这道分工。

重建解码器可以同时补齐多个缺失位置

MAE 的编码器只看可见图块，解码器补入带位置的掩码词元，用编码结果重建缺失图块。[3] 缺失位置之间不存在"等前一个生成出来"的依赖，可以一次全部预测，这与逐词元自回归的依赖结构完全不同。轻量解码器专门承担训练目标，编码器则专注学可迁移的表示；下游做识别时把重建模块摘掉，留下的是编码器的能力。

结构这样安排，资源分配也跟着走：编码器不必为被移除的图块建立隐藏状态和成对交互，解码器再以较薄的结构恢复空间位置。省下的是重编码器处理缺失位置的开销，可见位置的编码、重建解码与损失计算照旧要付。

双塔把跨模态交互推迟到表征空间

CLIP 的图像分支与文本分支各自编码，再投影到共同空间做相似度匹配。[4] 编码过程里没有为每个图文配对建立逐层联合交互，同一张图像或同一段文本的表示因此可以给多个配对复用——大规模检索可以先建向量、再匹配，代价是候选之间细粒度的交互被压缩进最终的表征关系里。

把双塔、联合编码、生成式跨模态模型放在一起看，差别落在"模态在哪一阶段开始相互影响"。这个位置决定了哪些中间结果能够独立复用、配对信息能多早进入表示计算。

稀疏、局部与交互路径

稠密注意力让每个位置在一层之内读到全部可见位置。信息路径短，成本却随长度平方增长，长序列下这条路径先用不起。局部窗口与稀疏方法换掉的是这张交互图：每个查询只连到选定的一部分邻居。连接数降下来了，远距离信息就得靠别的路线传播。[6, 9, 10]

局部窗口：拿深度换连接数

考虑一维序列，每层只读半径为 r 的连续邻域，没有全局节点、膨胀间隔或下采样。一次更新最多跨过 r 个位置，经过 L 层最多跨过 Lr 个位置，于是距离为 Δ 的两个位置要建立依赖，至少需要：

L≥⌈Δr⌉

这条递推从层结构直接推出来：第一层读到的是直接邻居，第二层读的是邻居已经汇聚过的表示，依赖范围每层再扩一个半径。代入数字：r=4、文档两端相距 4096 个位置，至少需要 1024 层才能让两端的信息碰面。稠密注意力在同一层里一步到位。于是问题变成：这份连接预算该花在哪里。局部纹理只关心邻近几步，长文档的问答却要求跨越全文组合证据。

若在中间插入一个能读全部输入的全局节点，路径立刻缩短：第一层把远端信息汇入该节点，第二层再由它分发出去。这个两跳关系来自层更新的时序——某一层读到的是上一层的表示，其他位置在这一层内还拿不到全局节点刚算出的结果。全局节点提供的是通信枢纽，代价是多种信息都要经过这个有限的汇聚表示。

固定、学习与层级给出不同的偏置

固定窗口或块模式预先定好连接，规则简单、访存可预测，判断依据只有位置关系。学习得到的路由或聚类按内容组织候选，试图在有限预算内抓住任务真正需要的远距离关系，代价是候选构造、排序或路由本身。[10] 两者的差别落在"凭什么决定连接"这一点上，与稀疏比例高不高无关。

层级结构再改一次分辨率：高层在更少的位置上交互，一个高层位置因而代表更大的一块输入。密集预测任务需要细节，就得保留降采样之前的路径，或把分辨率恢复回来。局部、全局、内容路由三种方式可以叠加使用，组合的目的是同时管住成本与依赖路径。

因果掩码属于另一类约束。它排除未来信息，保留全部历史时，长度为 N 的序列仍有约 N²/2 个可见位置对。三角形只带来常数因子 1/2 的削减。想把连接数做到随长度线性，必须限制每个位置能看多远，或者换一种计算表达方式——这正是后续几节展开的内容。

MLA：把 KV 缓存压进一个潜在向量

自回归解码每走一步，都要把全部历史词元的 K 与 V 从显存里读回来。以 MHA 的配置算：128 个头、每头 128 维，一个层、一个词元就要为 K 和 V 各存 16,384 个元素，合计 32,768 个；换 2 字节存储是 64 KiB，乘以层数和上下文长度之后成为显存的主要占用，读取它又成为带宽压力。MQA 把 KV 头压到一个，GQA 折中到若干组，两者都在共享表示本身。MLA 换了个位置下手：把 K、V 先压成一个低维潜在向量存起来，用到时再展开。[32, 33]（§2.1）

MHA、MQA、GQA 先改变 KV 头的共享方式

多头注意力（Multi-head Attention，MHA）给每个查询头配一套 K／V。多查询注意力（Multi-query Attention，MQA）让全部查询头共用一套，查询头仍保留多个。分组查询注意力（Grouped-query Attention，GQA）把查询头分成 G 组，每组共享一套 KV。[36]（§2.2）"多查询"指的是 KV 只有一个，查询照旧是多份；"分组"与序列切分无关，它切的是头。

设查询头数 Hq、KV 头数 Hkv、每头键维度 dₖ、值维度 dᵥ，每层每历史词元的缓存元素数为：

机制 KV 头的组织 缓存元素数
MHA Hkv=Hq，各头独立 Hq·(dₖ+dᵥ)
GQA 1<Hkv<Hq，组内共享 Hkv·(dₖ+dᵥ)
MQA Hkv=1，全部查询头共享 dₖ+dᵥ
MLA 缓存潜在向量与位置键 d𝚌+dᵣ

GQA 省下的是 KV 的存储与读取，每个查询头照旧产生自己的注意力分布，打分的算术量并不按同样比例下降。它改变的是参数共享约束，把已有的 MHA 检查点照原样合并成 GQA 会损失质量，所以 GQA 原文的做法是均值池化后再继续预训练一小段。[36]（§2–3）

联合低维参数化保留头间差异

用列向量来推 MLA 的内容分支。输入 xₜ 为 d 维，潜在向量 cₜ 为 d𝚌 维，它由一个下投影产生；第 h 头的内容键和值各自由一个上投影展开：

ct=WDxt,kt,hC=UKhct,vt,h=UVhct

W_D 的形状是 d_c × d，U_K^h 是 d_h × d_c，U_V^h 是 d_v × d_c，dₕ 专指内容查询与键的维度。各头共享 c，展开出来的键与值却各不相同。与 MQA 的差别正在这里：MQA 直接共用一份 K／V，MLA 共用的是生成 K／V 的那份低维状态。多出来的约束是各头的展开表示都要经过同一瓶颈，因此 MLA 成立的代价是表示受限额，而它换来的是每历史位置只需保存 c。

查询同样可以压缩后再上投影。查询只服务当前这一步计算，无需像历史状态那样长期留在显存里，所以查询压缩省的是训练激活，与 KV 缓存的缩减来自不同地方。[32]（§2.1.2）

矩阵吸收：历史访问留在低维空间

设第 h 头的内容查询为 qᶜₜ,ₕ。忽略位置分支，它与历史位置 s 的打分可以重新结合：

(qt,hC)TUKhcs=((UKh)Tqt,hC)Tcs

据此，先把当前查询做一次线性变换，得到 d𝚌 维的"吸收后查询"，就能直接拿它和缓存的 cₛ 打分，无需为每个历史位置重建每头的内容键。归一化得到权重 aₜₛʰ 之后，值分支靠线性性同样可以后移：

ot,h=∑s≤tatshUVhcs=UVh∑s≤tatshcs

把输出投影按头拆成 Oₕ，最终贡献就是 ∑h(OhUVh)(∑satshcs)，值上投影与输出投影可以合成一个矩阵，挪到汇聚之后。注意 softmax 的非线性原封不动：各头的 a 互不相同，先把各头平均再共用一次汇聚会得到另一个函数。[32]（§2.1.2）

这一串变换是运算顺序的重排，实现里并不需要真的把融合后的大矩阵显式存下来。吸收之后的点积与汇聚沿 d𝚌 维进行，d𝚌 比普通单头维度大时，每头的算术量反而上升。于是取舍出现了：省下的是缓存读取，付出的是别处的开销——训练和预填充查询多，展开成多头计算更顺手；小批解码从潜在缓存里读更划算。DeepSeek-V3.2 附录 A 把这两种执行视图称作 MLA 的 MHA mode 与 MQA mode，指的是同一个已训练模型的两条计算路径。[34]（附录 A）

RoPE 为什么必须解耦

旋转位置嵌入（Rotary Position Embedding，RoPE）给查询和键施加随位置变化的旋转 Rₜ、Rₛ。若直接旋转展开后的内容键，打分里会出现：

qTRtTRsUKhcs

Rₛ 夹在中间且随 s 变化。矩阵乘法不满足交换律，把上投影吸收到查询这一侧的前提就断了：每个历史位置都得重新算一遍键，缓存的收益随之消失。这也是 MLA 与 RoPE 相冲突的具体位置，与"低维向量装不下位置信息"无关。[32]（§2.1.3）

MLA 的处理是把内容与位置分开：每头的内容查询与位置查询各走一条路，每个历史位置另存一个跨头共享、已经旋转过的位置键 kʳ，维度 dᵣ。主分数由两项相加构成：

ℓtsh=(qt,hC)TUKhcs+(qt,hR)TksRdh+dr

内容项照旧可以吸收，位置项单独算，两项相加后走同一次 softmax。缓存因此需要放下 cₛ 与 kʳₛ 两份数据。代回 DeepSeek-V2 的取值 d𝚌=512、dᵣ=64，每层每词元缓存 576 个元素；按 2 字节算合 1,152 字节。同一层的 MHA 对照值是 32,768 个元素、64 KiB，两者相差约 57 倍。这只是有效张量容量，分页、尺度、对齐与工作区另算，也不能据此推出端到端有同倍加速。[32]（§2.1.3、§3.1.2）

MLA 缩减的是每个历史位置的表示宽度，历史位置总数一个没少：新查询仍要访问全部可见的潜在状态，预填充阶段的成对计算照旧是二次规模，缓存也照旧随上下文线性增长。要让主注意力少读一些位置，需要额外一层选择机制，这正是 DSA 的切入点。

DSA：用轻量索引器挑出要读的历史

MLA 把每个历史位置的宽度压下来了，位置个数却一个没减。一个长度为 N 的序列仍有大约 N²/2 个可见位置对，主注意力要逐个打分、逐个汇聚，长上下文下这项开销重新成为主导。DeepSeek 稀疏注意力（DeepSeek Sparse Attention，DSA）在 MLA 之上加了一条轻量通道：先用低代价的索引器扫一遍历史，挑出重要的若干位置，再让主注意力只在这些位置之间做完整计算。DeepSeek-V3.2 用它把每查询的主分支读取量固定在 2,048 个 KV 词元。[34]（§2.1）

索引分数与主注意力权重各司其职

设当前查询位置 t，可见历史位置 s≤t。索引器有 Hᴵ 个头，每头索引查询 qᴵₜ,ⱼ 为 dᴵ 维，历史位置共用一份索引键 kᴵₛ，当前输入另外给出每头一个标量权重 wᴵₜ,ⱼ。索引分数是各头点积的加权和，激活函数取 ReLU：[34]（Eq.1）

Its=∑j=1HIwt,jIReLU((qt,jI)TksI)

多个索引头先合成一个位置分数，再取 Top-k，得到的是一套共享的位置集合：

St=TopK({Its:s≤t},k)

历史不足 k 时取已有的全部合法位置。这套集合由该位置的全部主注意力头共用，因为它对齐的是 MLA 的公共潜在 KV 条目：一个被选中的历史位置贡献的是一份潜在状态，各主头各自拿它算自己的分数。索引器头数少、维度小，还可以用 FP8 实现，扫描一遍全历史的代价远低于完整主注意力。它依然要看过历史，扫描量随当前历史长度增长。

选出位置之后，主分支重新用自己的 MLA 查询、潜在状态和位置项打分，走一次 softmax 并汇聚：

ot,h=∑s∈Stexp(ℓtsh)∑u∈Stexp(ℓtuh)vsh

分母只统计入选位置，所以入选者的权重会因为没选中的位置被剔除而重新分配。ReLU 索引分数只承当路由代理的职责，最终权重仍由 ℓ 决定。

选定集合上的 softmax 是精确的

稀疏注意力在给定集合上算的是货真价实的 softmax，问题在于这个集合是否装住了该装的信息。做一个局部估算：固定同一组主分数和值，设稠密分布在未选位置上的概率总和为 ε<1，各值向量的范数不超过 V。稠密输出可以拆成入选部分与未选部分两个条件均值：

odense=(1−ε)oS+εoS¯,‖odense−oS‖≤2εV

o_S 是入选集合上重新归一化的输出，ε=0 时两个输出相同，此时未选部分的均值无需定义。这个式子说明只统计选对了多少位置并不够用：遗漏的概率质量和值的尺度都会进入误差。它只覆盖固定参数下的单个注意力层，后续层、非线性以及训练本身都在范围之外。

硬 Top-k 靠辅助损失学习

Top-k 的索引选取不可微，"哪些位置值得读"这件事没法学。DeepSeek-V3.2 分两段训练：[34]（§2.1.1）稠密预热阶段冻结主模型，只练新增的索引器；主注意力各头的概率按位置求和，再沿序列做 L1 归一化，得到教师分布 pₜ，索引器用 KL 散度对齐它：

ℒI=∑tDKL(stopgrad(pt)‖softmax(It,:))

教师端取自动梯度，索引器输入也从计算图上断开，于是这项损失只更新索引器的投影，主模型由语言建模损失单独负责。稀疏阶段打开 Top-k，主模型学着适应新的连接模式，索引器转为在入选集合上对齐归一化后的主注意力分布。两段的规模在报告中写得很清楚：预热 1,000 步，每步 16 条 128K 序列，合计 2.1B 词元；稀疏训练 15,000 步，每步 480 条 128K 序列，合计 943.7B 词元。

2,048 这个数字值得单独说明：它是主分支每个查询的读取预算。把它当成上下文长度上限或者缓存容量都会算错——索引键与可供未来查询选择的潜在状态仍然全部留在显存里，不同的查询会从不同的位置拼出自己的集合。DSA 因此与滑动窗口、与按重要性永久驱逐 KV 的做法都不同。

索引项的二次规模留在那里

设序列长度为 N，主分支每查询的读取预算为 k，每条主连接的有效工作量记作 D。忽略投影、选择、逐元素运算与常数因子，预填充阶段的主要结构是：

CDSA=O(N2HIdI)+O(NkD)

第一项留在原处，只是系数小；被降下来的是第二项。对一个新查询，索引扫描的长度随当前历史增长，主分支的访问量由 k 封顶。排序、非连续 gather、索引缓存与内核启动都是新增开销，短上下文下这笔开销可能超过省下的主计算，报告因此对短序列预填充专门实现了带掩码的 MHA 视图。[34]（§2.3）

这些结论带着具体的训练条件：DSA 是在 DeepSeek-V3.1-Terminus 检查点上继续训练得到的，评测也落在相应设置内，把它当作任意 MLA 模型套用 Top-k 即可无损的依据并不成立。报告里的 H800 服务成本换算自真实部署，与另一篇论文的单内核时间不能拼成一栏排名。下一节的 MSA 用了另一套共享边界：选择在 GQA 组内共享，组与组之间可以不同。

MiniMax MSA：每个 GQA 组挑自己的历史块

把选择粒度放到单个词元，精度最好，代价是路由变得零散：每个查询位置一套索引，几十个主头各自读不同的位置，GPU 上的分块矩阵乘拼不起来。MiniMax 稀疏注意力（MiniMax Sparse Attention，MSA）退一步处理这件事：选择在 GQA 组的粒度上做，一个组共用一套索引，组与组之间互不相同；被选中的单位是词元块，粒度比单个词元粗。[35] 这样既保留了内容相关的稀疏性，又把访存整理成连续的块。这里的 MSA 指 MiniMax 的这套机制，与多头自注意力、与蛋白质主题中的多序列比对都无关。

每个 GQA 组选自己的历史块

设输入 X 为 N × d_model，主分支有 Hq 个查询头、Hkv 个 KV 头，每组包含 G=Hq/Hkv 个查询头。索引分支给每个组配一个 dᵢ 维的查询，索引键则在全部组之间共享，只保留一个头：[35]（§3.1，Eq.5–7）

Q_idx:     [N, Hkv, d_i]
K_idx:     [N, 1,   d_i]
主分支 Q:  [N, Hq,  d_h]
主分支 K、V:[N, Hkv, d_h]

这两条索引投影与主分支的 Q／K 各自独立，选择器因此可以做得比主分支轻得多。把历史按 B 个词元一块切开，块 b 的位置集合记为 ℬᵦ。对位置 t、组 r，先算每个可见词元的索引点积，再取块内最大值作为这一块的分数：

stsr=(qtr)Tksdi,mtbr=maxs∈ℬb,s≤tstsr

式中的 q、k 是索引向量，主分支另有自己的投影。看不见任何因果位置的块记为负无穷。按 m 取最高的 k 个块，其中包含当前位置的本地块固定入选，占用 k 个名额中的一个。主分支随后读取入选块里所有可见词元，按每个主查询头自己的分数做 softmax，读取上限因此是 k·B 个位置。

最大池化带来了一个可以预期的后果：块内只要有一个位置和当前查询匹配得上，整块就可能被读进来，旁边的邻居是一并捎带的。把 B 调大，读取更连续、矩阵乘形状更规整，选择精度同时下降；把 B 调小则反过来。这是硬件友好度与内容粒度之间的实际取舍，调参时两个方向都要看。

举个例子。设当前位于块 3，预算 k=2，本地块占掉一个名额。组 A 认为块 1 比块 2 重要，组 B 的判断相反，于是 A 读 {1, 3}、B 读 {2, 3}，两组在同一层里走了不同的检索路线；每组内部的多个查询头仍在这些块内形成各自的概率分布。MSA 给组以自由，但没有把自由下放到每个头，理由是后者的路由与访存会重新变得不规则。

教师分布取组内概率平均

索引选取同样不可微，MSA 用主分支当教师。在该组入选块覆盖的词元上，先让每个主头各自 softmax，再对组内 G 个头求概率平均得到教师 P；索引分支在同一词元集合上归一化，两边做 KL 对齐：[35]（§3.2，Eq.9–11）

Ptsr=1G∑h∈ℋratsh,ℒKL=1NHkv∑t,rDKL(stopgrad(Pr)‖Pidx)

ℋᵣ 是第 r 组的查询头集合，a 是各头在该集合上归一化后的主注意力概率，KL 两个分布省略了位置下标 t。教师端停止梯度，索引器输入 X 也停止梯度，辅助损失只更新两条索引投影：主分支继续由语言建模损失训练，索引器单独学"主分支会看哪里"。顺序上先跑一段全注意力做预热，等索引器大致对齐之后再切换到稀疏，训练时本地块始终强制保留。

到这里，MSA 与 DSA 的数字出现了一个巧合：两者都写着 2,048。DSA 是每个查询选 2,048 个词元、全部主头共用；MSA 是每个查询、每个 GQA 组各选 16 块 ×128 词元，并且其中一块被本地块占住。连接图不同，底座、训练数据、头数与硬件也不同，这个数字对齐并不意味着两种方法可以互相替代或直接比高低。

块稀疏没有消掉二次索引项

索引器依然要在全部因果位置上算一遍轻量分数，块最大值与 Top-k 削减的是随后主分支的读取集合。按论文的计数方式（一次乘加算 2 FLOPs，忽略投影与边界项），长序列下：

FGQA≈2HqdhN2

FMSA≈HkvdiN2+4HqdhNkB

第一项是索引分支，仍随 N² 增长，只是 Hkv·dᵢ 远小于 Hq·dₕ；第二项是主分支，固定 k·B 之后随 N 线性增长。序列继续加长，索引分支在总量中的占比会上升，这是这类两阶段结构的固有走向。

状态方面，MSA 仍然保留完整的、可供未来查询读取的主 K／V，另外多出一份索引键。当前少读一些块，与永久释放其余块是两回事：后面的查询完全可能选到它们。它降低的是主注意力的读取工作，与 MLA 那种直接压缩每个位置表示宽度的做法落在不同位置。短输入上，索引与选择的固定开销还可能盖过省下的计算。

从稀疏连接到 GPU 执行

第一步优化来自 softmax 的一个性质：它是保序的，同一行里 si≤sj 与 softmax(s)i≤softmax(s)j 等价，因此选块直接用原始索引分数即可，省掉 max／exp／求和，Top-k 的结果不变。[35]（§4.1）主注意力与训练 KL 该做的归一化照做。

接下来是循环顺序。按查询遍历，每个查询去收集自己选中的若干 KV 块，K／V 会被反复读取；按 KV 块遍历，先建一张反向索引，把选中该块的所有查询聚到一起，载入一份 K／V 就能服务多个查询和组内多个头。用论文给的一阶估计比较两种顺序的算术访存比（bf16，忽略次要项）：[35]（§4.2）

  • 查询外层：FLOPs 为 4·Hq·N·dₕ·k·B，IO 主要是 Q 与 O 的读写 4·Hq·N·dₕ 加上 K／V 的读取 4·Hkv·N·k·B·dₕ，比值约为 G。
  • KV 外层：K／V 只读一遍，Q 与局部输出缓冲按 k 倍放大，比值约为 23B。

取论文的配置 G=16、B=128，两个比值分别是 16 与 85 左右，KV 外层高出数倍，因此实现选了后者。代回的代价也具体：热门块会被大量查询选中，一个 CTA 干不完，需要沿查询方向切分并预先分配输出槽位；每个查询的输出被拆成 k 份，由不同 CTA 产生。

这些局部结果不能直接平均。若第 b 块的局部归一化输出为 oᵦ、其对数指数和为 Lᵦ，正确合并方式是按各自的概率质量加权：

L=log∑bexp(Lb),o=∑bexp(Lb−L)ob

实现里减去最大的 Lᵦ 以免指数溢出。这与在线 softmax 的归一化守恒是同一件事：分块计算的各部分要按自己的概率质量相加，按块数等权相加会得到另一个结果。收益是 KV 复用与更规整的矩阵乘，代价是反向索引、局部输出与 LSE 缓冲，以及一个额外的合并阶段。

论文的质量验证放在一个约 109B 总参数、每词元约 6B 激活参数的多模态 MoE 底座上：41 层，前 3 层稠密，其余 38 层为 MoE，64 个查询头、4 个 KV 头、头维 128、RoPE 维 64，每层 128 个路由专家加 1 个共享专家、每次选 4 个，训练 3T 词元；对比稠密 GQA、原生稀疏训练与从稠密检查点继续训练三条路线。[35]（§5.1–5.3）作者报告的结论支持这些设置下的可行性，换模型、换训练史仍是另一回事。本篇没有运行其内核，也没有复现这些测量。

前两者沿 FFN 与设备分布组织条件计算，后三者沿注意力状态与连接组织读取，虽然都含"路由"，作用对象相差很远。"选专家"选的是参数，"选历史"选的是数据。FlashAttention 又在另一个层面工作：它重排既定注意力的计算与中间存储，连接关系原封不动。一个模型可以同时用上 MoE、EP 和某种稀疏注意力，各自的收益也各自受限，把它们直接相乘得不到整机结论。

线性注意力与低秩压缩

线性注意力、序列低秩压缩、权重低秩近似都会出现"低秩"这个词，改的对象却不一样：权重近似动的是模型参数，序列压缩动的是可供访问的键值表示，核化注意力改的是相似性表达与求和顺序。高效 Transformer 综述把这些路线放在可交叠的分类里，读实现时仍要回到各自的代数前提。[10]

从核函数到可累计状态

设相似性能用有限维特征写开，κ(q,k)=φT(q)φ(k)，特征维度 r。配上正的归一化分母，位置 i 的输出就可以把只依赖查询的项提到对键的求和之外：

yiT=∑jφT(qi)φ(kj)vjT∑jφT(qi)φ(kj)=φT(qi)RφT(qi)z

式中的 R=∑jφ(kj)vjT 是特征与值的外积之和，z=∑jφ(kj) 累积归一化统计；值向量按列向量定义，输出公式给出它的行表示。这一步能做的原因是 φ(qᵢ) 不参与对 j 的求和，交换求和顺序因此合法。

因果情形只对当前位置及历史求和，两个统计量可以增量更新：

Ri=Ri−1+φ(ki)viT,zi=zi−1+φ(ki)

代数字看规模：特征维度 r=128、值维度 dᵥ=64 时，状态是 128×64+128=8320 个元素，与历史长度无关；同一模型若存显式 KV 缓存，8192 个历史位置需要 8192×64=524,288 个元素，相差约 63 倍。每步的更新与读取量也不再随历史增长，总工作量因此可以随序列长度线性增长。提高 r 以换取精度、或者特征构造本身较贵时，这笔账要重新算。

有限维特征装不下指数点积矩阵

标准注意力用指数点积核，再按查询归一化。有限维特征给出的未归一化相似性矩阵是 Φ(Q)ΦT(K)，秩至多为 r。指数点积矩阵的秩上界要高得多：在维度为一、缩放为一时取 qi=i−1、kj=logtj，各 tj 互异且为正，分数矩阵就是一个 Vandermonde 矩阵：

Bij=exp(qikj)=tji−1,det(B)=∏1≤i<j≤N(tj−ti)≠0

行列式非零，矩阵满秩。按行除以正的行和相当于左乘一个可逆对角矩阵，秩不变。于是序列长度超过固定特征维度 r 时，这个标准 softmax 注意力矩阵写不成该有限维特征分解。反例证明的是"对任意输入、任意长度都等价"这个说法不成立；换到特定输入分布上，近似核或别的核照样可以训出有效模型。[10]

状态压缩与序列低秩压缩的取舍

可累计状态把过去的键和值压进几个统计量，查询只能通过这些统计量访问历史。序列低秩方法换一条路：把多个位置投影成较少的键值表示，查询再去访问压缩结果，归一化形式可以保留，压缩是否够用同样取决于任务。两条路都在缩小历史表示的规模，丢信息的方式不同。

完整 KV 缓存保留每个历史位置的独立键值，用更大的存储与读取换取逐位置可寻址的选择能力；固定大小的累计状态省空间，代价是拿不回同样的寻址粒度。长上下文里的精确证据检索与持续状态建模，因此可能偏好不同的表示。判断一种线性结构适合什么任务，需要把渐近复杂度、历史访问方式和训练目标放在一起看。

输入组织与计算复杂度

问一个 Transformer 块的时间花在哪，答案随形状变化。把所有耗时归到注意力的二次项上，会漏掉隐藏维度宽时的投影与前馈；只看参数量，又看不到长输入带来的交互与状态增长。原始 Transformer 的复杂度讨论和 ViT 对理论计算量与设备速度的对照，分别对应"数学工作量"与"实际执行"这两个层次。[2, 6]

二次交互什么时候成为主项

设序列长度 N、隐藏维度 d，多头的查询／键总维度与值总维度都取 d，前馈中间维度 dff。忽略偏置、归一化、激活与 softmax 的逐元素开销，矩阵乘的乘加对数为：

Cprojection=4Nd2,Cpair=2N2d,CFFN=2Nddff

第一项是 Q、K、V 与多头输出四次投影，第二项是 QKᵀ 与 AV，第三项是前馈的扩展与收缩。换成一个具体配置：N=1024、d=512、d_ff=2048，三项分别约为 1.07×10⁹、1.07×10⁹、2.15×10⁹ 次乘加，总计 4.3×10⁹。此时成对交互只占四分之一，前馈一项独占一半。成对项与其他两项的比值是：

CpairCprojection+CFFN=N2d+dff

代入上例即 1024/(1024+2048)=1/3。阈值就写在式子里：序列长度超过 2d+dff 之后，成对交互开始占多数。取 d=512、d_ff=4d=2048，这个门槛是 3072；短于它的序列上，投影和前馈才是大头。这里是既定形状下的稠密算术比较，真实耗时还要看访存、并行度、融合和硬件原语。

若把乘加按两次浮点运算计，所有数字翻倍，比值不变。

输入粒度决定成本涨在哪一项

ViT 中把图块边长减半，图像尺寸不变时序列长度变成四倍。代回上面三项：投影与前馈随 N 线性增长，涨到约四倍；成对交互随 N² 增长，涨到约十六倍。细化输入颗粒度因此要额外付出交互成本，把更多资源压到位置之间的交互上。[2]

MAE 走的是反方向。编码器之前先扔掉被遮挡的图块，编码器只看剩下的部分。设保留比例 ρ，序列长度按 ρ 缩放，投影与前馈约按 ρ 缩放，成对交互约按 ρ² 缩放；分类词元、固定开销和后面的解码器另计。[3] 这条关系解释了非对称编码器—解码器结构为什么能把主要表示学习集中到可见部分，但它只覆盖编码器这一段，全流程的加速比要看解码器占多少。

算术与存储可以分开优化

直接保存各头注意力权重，中间状态包含与头数、序列长度平方成比例的元素；算术量则由成对项决定。以 N=8192、16 个头、2 字节为例，一份完整权重矩阵是 16×8192²×2 字节，约 2 GiB，需要落到显存里；FlashAttention 通过分块与在线归一化避免把这张矩阵整体写回主存，它动的是中间量的存储与搬运，稠密注意力的算术量一点没变——仍然是精确注意力。这部分实现细节在框架章的 FlashAttention 小节展开。

局部窗口、序列压缩、线性累计状态和精确注意力内核，因此在资源图上各占一个位置：前三类改变的是可见连接或表示，后一类重排同样的计算。讨论效率时把三件事分开说清——计算对象是什么、状态有多大、信息怎么被访问——某种设计在缓解哪项压力、又留下哪些工作，就一目了然。

架构变体的作用层次与设计约束

改一层注意力只是架构调整的一部分。Lin 等把修改分成两级：模块级的注意力、位置表征、归一化、前馈，以及架构级的跨块连接、递推、层级与计算深度。[9] 分开看的好处是避免把训练目标、网络结构和执行内核混成一种"改进"。位置编码解决顺序怎么进表示，局部窗口解决哪些位置直接交互，层级下采样解决后续层以什么分辨率工作；三者都在降成本，接口和适用条件却各不相同。

长序列成本与结构先验

Lin 等概括的注意力挑战有两个：序列长度带来的计算复杂度，以及缺少输入结构先验时的数据需求。[9] 全连接的交互图让任意两个位置直接联系，代价是模型得从数据里学出哪些联系有用。数据本身带有明显的空间邻域、时间顺序或层级关系时，毫无约束的连接未必是最合适的起点：局部性先验能直接缩小需要学习的关系范围，在数据有限的场景下尤其划算。

先验也要付账。关键信息一旦跨越局部边界，就必须另铺路径——全局节点、跨窗口连接，或者靠层层传播慢慢把距离拉近。窗口注意力的设计因此在做两件事：减少参与计算的矩阵元素，同时把邻域假设写进网络，并把远距离交互转交给其他连接或层级。长文档的跨段问答和图像的局部纹理对交互图的要求不同，前者要显式保留远程证据通路，后者可以充分吃空间邻域。这个区别比比较渐近复杂度更能解释结构选择。

高效方法改动的是哪个对象

Tay 等的综述把高效 Transformer 分成固定或学习得到的交互模式、记忆、低秩、核化、递推、下采样与条件计算等路线，并说明这些分类彼此交叠。[10] 按"哪个对象被缩小或重组"来看，路线之间的边界就清楚了：

路线 改变的对象 解决的主要压力 需要保留的限制
局部／稀疏模式 直接连接的位置对 全局两两交互的计算与中间量 被删连接上的信息需经其他路径传播
低秩／序列压缩 键、值或注意力的表示维度 长序列的表示与交互成本 压缩假设可能丢掉任务需要的细节
核化／线性形式 注意力表达与求和顺序 显式二次矩阵的形成 与标准 softmax 的关系依具体方法而定
分段递推 跨段状态的传递方式 整段同时处理与跨段上下文 状态大小、历史可访问性与更新规则改变

这张表把资源策略按作用对象分开。降低交互规模的算法在改模型能看见什么；FlashAttention 保留稠密注意力的数学定义，改的是它的存储与执行。前者要回答表示能力与任务适配，后者要回答数据搬运与硬件契约，两者都有 "efficient attention" 的名头，结论却无法互换。

2. 预训练阶段

预训练通过数据中可构造的预测关系学习表示。输入可见性、预测对象与误差度量决定学习信号，数据分布决定这些信号出现的频率，优化与迁移协议则决定有限预算内怎样形成和使用表示。本节以自回归语言建模、BERT、ViT、MAE 和 CLIP 连接这些环节，区分目标的数学性质与具体模型的实验结果。[1–4, 17]

目标函数与监督信号

预训练把数据中的某种关系转化为可优化的预测任务，再用学到的参数或表示支持其他任务。原始 ViT 主要利用类别标签，BERT 预测被扰动的词元，MAE 重建缺失图块，CLIP 判断图文配对。[1–4] 这些方法共享表示学习的目的，却选择了不同的条件信息、预测对象和误差度量。目标函数因而不仅规定“怎样算损失”，也规定哪些差异会推动参数更新。

条件预测决定模型需要保留的信息

把模型可见的信息记为 C、预测对象记为 Y。对离散目标，条件交叉熵的总体风险为：

R(θ)=𝔼C,Y[−logpθ(Y|C)]

固定一个条件 c，设数据条件分布为 P，模型分布为 Q，并假定 Q 在 P 的支持上为正。加减数据分布自身的对数，可将该条件下的风险展开为：

−∑yP(y|c)logQ(y|c)=H(P(·|c))+KL(P(·|c)‖Q(·|c))

熵项由数据和条件决定；KL 项非负，其非负性可由对数不等式 log u ≤ u−1 得到。在模型能够表达相应分布的理想条件下，最小风险对应恢复数据的条件分布；输出一个确定答案在一般情况下会抬高风险。有限容量和有限样本下，模型则在可表达的分布族内逼近这个目标。

这个分解也解释了可见性的重要性：条件中若已经包含真实答案，任务可以通过读取答案完成；条件删除了全部相关线索，剩下的又可能只是无法进一步降低的条件不确定性。有价值的预训练任务在两者之间组织信息，使预测需要利用可迁移的关系。类别监督、缺失内容预测和配对判别分别要求保留不同关系，没有一种损失天然覆盖全部下游需求。[1–4]

自回归目标与双向表征的不同条件

自回归语言模型按链式规则建立序列概率，并最大化真实序列的似然：[17]

ℒAR=−∑tlogpθ(xt|x<t)

每个位置的目标是下一个真实词元，条件只包含其前缀。共享参数必须在不同前缀上预测不同后续内容，因此语法、事实关联和篇章规律都可能成为降低损失的资源；这些能力来自数据中的可预测关系，似然目标只提供优化方向。因果掩码让训练时的可见条件与生成时对应，已知目标序列又允许训练并行计算各位置的损失。

BERT 改变的是条件：预测缺失词元时可以同时读取左、右上下文。[1] 这为理解任务提供不同的信息结构，但多个掩码位置的条件预测并不直接等于上述顺序联合概率分解。两类目标的区别由所学习的条件关系决定，与损失函数叫什么名字无关。

对以 softmax 输出词表概率的单个目标，若正确词元为 y、logit 为 z，交叉熵导数为：

∂ℓ∂zj=pj−𝟙j=y

更新降低预测分布与目标指示之间的差异。损失在哪些位置计算、预测时能读哪些输入、各目标以多大权重出现，分别决定梯度的来源、条件和相对强度；后续几种预训练设计正沿这些因素展开。

遮挡预测：双向上下文与输入扰动

双向编码器允许每个位置读取两侧内容；若原词元仍完整可见，并要求输出该位置的词元，模型可以沿直接或间接路径复制输入。BERT 用随机扰动打破这一捷径，使选中位置在多数情况下需要根据上下文恢复内容，同时保留双向信息流。[1]

原版 BERT 先选择 15% 的 WordPiece 位置作为目标；选中位置中，80% 替换为 [MASK]，10% 替换为随机词元，10% 保持原样。原序列为 x、扰动序列为 x̃、非空目标位置集合为 M 时，平均损失为：

ℒMLM=−1|M|∑i∈Mlogpθ(xi|x~)

15% 决定哪些位置接受直接预测监督，80／10／10 决定这些目标以什么输入形式出现。未被选中的位置不直接计算该项损失，却作为上下文参与其他位置的预测，梯度仍能通过注意力传回它们。目标采样稀疏只影响直接监督落在哪些位置，参与计算的输入表示和位置数量都没有减少。

[MASK] 在下游自然输入中通常不存在，因此全部使用掩码会造成输入形式的偏移。随机替换与保持原样让预测也发生在普通词元表示上，缓和这一偏移。[1] 保持原样的目标确实含有可复制信息；它是扰动混合中的一部分，模型在其他被替换目标上仍需利用上下文。损失监督始终指向原词元。

遮挡比例同时改变两个因素：直接目标的数量，以及剩余上下文的信息量。更高比例提供更多预测位置，也移除更多线索；文本中的低冗余标识、否定或数字一旦被删，条件预测可能具有较高不确定性。因而，比例在控制训练效率之外，同时决定任务难度。BERT 使用 15% 是其方法设置，MAE 的高比例图块遮挡则来自不同模态与计算设计。

原版 BERT 还以 [CLS] 表示预测两个文本片段是否连续：一半真实后续，一半来自随机语料，形成二元交叉熵。平均 MLM 损失与平均下一句预测损失相加，使词元恢复和片段关系共同影响参数。[1] 这一目标为聚合表示提供特定监督，而它学的是构造出的连续性判别，随机片段之间的主题差异也可能成为线索。

像素重建：非对称计算与条件均值

MAE 把遮挡安排在编码器之前：随机移除图块，较大的编码器只处理可见子集，再将带位置的掩码词元补入较轻的解码器。解码器恢复完整位置集合并预测被遮挡图块。[3] 与 BERT 用替换词元维持完整输入长度相比，MAE 同时改变了学习任务和较重模块的计算规模。

图像相邻区域通常具有空间冗余，较少遮挡时可能通过局部纹理延续完成预测。MAE 作者据此提高遮挡比例，使任务更依赖分散的可见区域及整体关系，并在其设置下发现 75% 遮挡有效。[3] 比例进一步增大，又会减少用于区分多个可能图像的证据。这是可见信息与预测难度之间的取舍，最佳比例由实验确定。

设被遮挡图块集合为 M，每个目标图块有 q 个像素分量，像素均方误差为：

ℒMAE=1|M|q∑i∈M‖x^i−xi‖22

只监督缺失图块使直接误差集中于恢复未知内容。可见图块作为条件仍参与梯度传播，但不需要在该损失中重复承担复制自身像素的任务。原文把这个选择带来的识别收益交给实验结果判断，推广到其他去噪目标要另行验证。[3]

均方误差为何可能产生平均化预测

固定可见条件 c，把缺失像素向量记为随机变量 X，且假定条件二阶矩有限。令 μ(c)=E[X|c]，模型输出为 a。展开平方并利用 E[X−μ(c)|c]=0，可得：

𝔼[‖X−a‖22|c]=𝔼[‖X−μ(c)‖22|c]+‖a−μ(c)‖22

第一项是给定可见内容后仍剩下的不确定性，第二项在 a=μ(c) 时最小。因而，无容量限制的平方误差预测器选择条件均值；若同一可见区域允许多个不同补全，最优均值可以位于这些补全之间，并不一定对应一幅自然图像。这个数学性质说明重建误差、视觉逼真度与语义识别各自衡量不同的量；有限网络的实际结果还受模型和数据限制。

目标归一化改变被奖励的像素差异

MAE 还比较按图块均值和标准差归一化的目标。[3] 省略数值稳定项，并假定图块方差非零时，目标为 z=(x−μ)/σ。若整块像素变为 ax+b，其中 a>0，则均值变为 aμ+b、标准差变为 aσ，归一化目标保持不变。这使目标降低对图块共同亮度与正尺度变化的敏感性，而保留图块内部的相对结构。

这种不变性属于重建目标，不自动扩展为整个编码器的光照不变性：输入仍可包含原始亮度，位置与上下文也继续影响表示。预训练后移除重建解码器，用编码器完成识别；其价值需要在这一迁移接口上评估，而不由像素损失的最小化单独确定。

配对判别：相对竞争与跨模态对齐

图文描述包含大量细节、表达方式和措辞差异，逐词复现描述要求模型同时解决视觉理解与文本生成。CLIP 选择另一种代理任务：判断整段文本与哪幅图像配对，让双塔表示直接服务于跨模态匹配。[4] 原文比较了生成、词袋预测与对比目标的零样本迁移效率；其结果对应这些具体设置，机制上的变化则在于监督从复现全部文字转向区分候选关系。

对 B 个图文对，投影后单位向量为 uᵢ、vⱼ，分数 sᵢⱼ=αuᵢᵀvⱼ，其中正尺度 α 采用指数参数化。图像到文本的概率与对称损失为：

pijI→T=exp(sij)∑kexp(sik),ℒ=−12B∑i(logpiiI→T+logpiiT→I)

反向概率按固定文本对所有图像归一化，即对分数矩阵的列归一化。两个方向同时约束检索关系，输出是一组相对候选分数，供检索与排序使用。

负候选为什么改变表示学习

仅要求配对向量接近时，把所有输入映射到同一向量也可以满足相似性要求。对比分类加入候选竞争：对单行损失 ℓᵢ，查询单位向量的导数为：

∂ℓi∂ui=α(∑jpijvj−vi)

高概率错误候选对更新影响较大，梯度不仅拉向正确配对，还反映当前竞争分布。这里把归一化后的 uᵢ 视为中间变量；传回归一化前特征时，还要经过 L2 归一化的雅可比，更新受到单位球面约束。

全部表示相同时，每行概率均为 1/B，损失为 log B。作为损失空间中的对照，把各样本嵌入视为可独立选择的向量。若嵌入维度至少为 B，并令每对图文使用同一组相互正交的单位向量，正配对分数为 α，其他分数为零，单行损失成为：

ℓ=log(1+(B−1)e−α)<logB

该构造在 B>1、α>0 时说明目标偏好可区分的匹配。这是损失几何的比较；优化能否逃离所有坍塌状态要另行论证；完全相同的表示仍可能形成特殊驻点，实际学习依赖初始化、参数化和数据。

归一化、尺度与候选组成相互作用

L2 归一化去除向量长度对点积分数的直接影响，使模型主要通过方向表达关系；α 则集中控制 softmax 的竞争强度。对一个查询，记余弦为 cᵢⱼ，有：

∂ℓi∂α=∑jpijcij−cii

正确配对比竞争候选更相似时，增加尺度可让分类更确信；若高分候选反而错误，扩大尺度会放大相应损失。尺度与向量方向共同更新，固定尺度和学习尺度因而具有不同的优化过程。[4]

批内其他配对承担负候选角色，但这个标签来自配对索引，与现实中语义是否相互排斥无关。两段描述可以指向相近内容，一幅图像也可能适配多种文本；重复或近义样本会改变候选竞争。批大小既决定梯度估计，也改变每个查询面对的候选集合，因此不能仅以独立样本平均的逻辑解释其全部影响。

单模态与多模态数据组织

监督信号依赖原始数据保留了什么关系。BERT 的连续文档提供双向上下文和真实后续片段；ViT 的图像类别标签定义判别任务；MAE 在图像内部构造可见与缺失部分；CLIP 依赖图文对应关系。[1–4] 因而，数据不能只用样本数或文件大小描述：文档边界、版本、标签空间与配对来源也参与定义训练问题。

文档边界与任务条件

BERT 使用 BooksCorpus 与英文 Wikipedia 的连续文本。片段采样利用文档顺序构造下一句预测，并在 WordPiece 后采样掩码位置。[1] 若语料只保留成随机打散的独立句子，词元恢复仍可在短句内进行，真实后续关系却已丢失；把不同文档直接串接，又会引入原文不存在的邻接。边界处理因此改变条件分布，而不仅影响读盘顺序。

自回归训练中的序列打包同样涉及边界：打包提高固定长度张量的利用率，是否允许注意力跨文档、如何放置结束标记和计算损失，则决定模型实际学习了哪些连续关系。物理上位于同一张量的片段，可以在逻辑上保持隔离；这种区分延续到推理框架的变长打包和边界表示。

标签、像素与配对提供不同粒度的监督

ViT 的主实验利用 ImageNet、ImageNet-21k 和 JFT-300M 等带标签集合，类别定义把许多不同图像映射到同一目标。[2] MAE 的重建目标来自图像自身，不使用类别标签预训练，但后续识别微调仍利用标签。[3] 前者强调类别相关的压缩，后者要求恢复缺失像素中可预测的信息；数据量相同也不意味着相同的学习信号。

CLIP 从互联网构造约四亿图文对，文本提供开放的概念描述，不局限于固定类别表。[4] 这种开放性同时带来描述粒度不一致、配对噪声和来源偏差：短描述可能只提及图像的一部分，多个图像可能共享近似文本。目标学习的是数据中实际出现的配对关系，覆盖哪些概念、哪些语言和哪些视角，仍由采样与筛选决定。

预训练与评测重叠还会改变迁移结果的含义。同一图像、近重复文档或答案模板在训练中出现，会让评估混合记忆与泛化。CLIP 原文对重叠和开发过程作了分析；这些数据关系与适配协议一起构成结果解释的条件。[4]

数据准备：有效分布、过滤与训练课程

数据准备决定训练目标在哪个分布上求期望。Zhao 等的 LLM 综述将其组织为来源、预处理与调度，讨论去重、质量过滤、隐私处理、数据混合和课程安排。[17] 对语言语料而言，这些操作不仅改变可用文件，也改变内容在参数更新中出现的频率和顺序；视觉与其他模态则按各自的样本结构建立相应分布。

重复实际上重加权了经验风险

设互不相同的内容 xᵢ 在数据集中重复 mᵢ 次，给定该内容时对输入扰动等随机因素取平均的损失为 ℓᵢ。均匀采样文件或记录时，对应的经验风险为：

R^=∑imiℓi∑imi

重复内容的权重由重复次数增大，并未按同样比例增加独立证据。模板或转载页面大量出现时，训练预算会反复作用于相近关系。文档级、句子级和近似去重分别针对不同重复来源，粒度也影响哪些差异被保留。[17]

去重与领域覆盖之间存在真实取舍。两版业务规则可能只改变一个日期、阈值或否定词，表面高度相似却具有不同适用条件；相同术语也可能在不同语境中表达不同关系。去重策略因此要区分内容冗余与关键差异，相似度高推不出信息价值低。

过滤改变支持范围，隐私是另一项条件

若原始分布为 P(x)、保留概率为 f(x)，并且平均保留概率非零，则过滤后的分布为：

Pfiltered(x)=f(x)P(x)𝔼P[f(X)]

质量规则在移除噪声的同时，对数据分布重新赋权；若某类内容总被过滤，它会从可学习的支持范围中消失。语言、领域和表达形式的覆盖因此可能随过滤条件变化。去重控制重复权重，质量过滤控制保留内容，隐私处理限制可使用的信息，三者解决不同问题。[17]

混合权重决定目标，课程还改变更新路径

不同来源的分布为 Pₖ、混合权重为 wₖ，权重非负且和为一时，总体风险与梯度分别为：

R(θ)=∑kwkRk(θ),∇R(θ)=∑kwk∇Rk(θ)

较小但重要的专业集合可以通过混合权重获得更多更新机会，同时会改变通用与专业目标的相对作用。当不同来源的梯度方向冲突时，权重改变就会改变合成更新方向；容量有限时，改善一个来源的风险未必同时改善全部来源。

课程进一步改变来源在什么阶段出现。即使两种安排各使用一次来源 A 和 B，有限步优化也未必到达相同参数。以相同步长 η 的两次普通梯度更新为例，在初始 θ 处记梯度为 gₐ、gᵦ，Hessian 为 Hₐ、Hᵦ。若损失足够光滑、邻域中的相应导数有界，Taylor 展开给出：

θAB−θBA=η2(HBgA−HAgB)+O(η3)

原因是第二步梯度在第一步更新后的参数处求值。这个局部分析说明数据顺序可以改变学习路径，而不据此确定哪一种课程最优。混合比例、课程和领域继续训练分别控制目标权重、更新顺序与分布变化，最终还要结合旧能力保持和目标任务表现解释。[17]

优化、训练稳定性与规模扩展

目标函数定义学习方向，优化过程决定有限预算内怎样接近它。模型深度、序列长度、批大小和数据分布共同改变梯度、状态与每步成本。BERT、ViT、MAE 和 CLIP 的结果都包含具体训练配方；这些配方是方法产生结果的组成条件，与架构名称同样重要。[1–4]

批大小降低哪些随机性

设 B 个独立同分布样本的梯度估计具有相同均值 g 和有限协方差 Σ，则批平均梯度满足：

g^=1B∑i=1Bgi,Cov(g^)=ΣB

协方差缩减来自独立交叉项为零。一个序列中的词元共享上下文，重复文档也相互相关，因此把词元数或重复次数直接代入 B 会误解这一关系。CLIP 中候选集合还随批大小改变，每个样本损失不再只是独立的固定任务；增大批次同时改变随机性与对比问题本身。

固定训练词元或样本预算下，更大的批次意味着更少的参数更新。单步估计更平稳与更新次数更少同时发生，吞吐提高也可能来自矩阵形状和并行度；这些因素不能由方差公式单独判定。梯度累积可以形成较大的有效批次，但仍保留微批执行的时间和通信安排。

学习率控制的是局部变化尺度

对梯度在相应邻域中具有 L-Lipschitz 连续性的可微风险 R，下降引理给出普通梯度步的上界：

R(θ−η∇R(θ))≤R(θ)−η(1−Lη2)‖∇R(θ)‖22

在梯度步仍处于该邻域、且 0<η<2/L 时，上界中的减小项非负。推导来自对参数位移的一阶展开与二阶余项界：步长太大时，曲率项可以抵消沿负梯度方向的收益。深网络中的有效曲率、随机梯度和参数尺度随训练变化，这个局部结论说明学习率与稳定性之间的联系，非凸训练能否达到全局最优是另一个问题。

BERT 与 ViT 使用学习率 warmup，让初期步长逐渐增加；二者报告的相应训练设置包含 10,000 步 warmup。[1, 2] 这段过程限制早期位移，同时允许表示与优化器统计形成。随后衰减学习率则减小后期更新尺度。具体长度与峰值学习率依赖批次、目标和模型，不能从一个局部曲率界直接算出统一配方。

自适应统计与裁剪处理不同因素

Adam 以梯度的一阶、二阶指数移动统计调节各坐标更新。[18] 令 t 为步数、逐元素平方为 gₜ²，统计从零初始化，两个衰减系数均在 [0,1) 内，其统计与偏差修正为：

mt=β1mt−1+(1−β1)gt,vt=β2vt−1+(1−β2)gt2

m^t=mt1−β1t,v^t=vt1−β2t

零初始化会使初期统计偏小，例如恒定平均梯度 ḡ 下有 E[mₜ]=(1−β₁ᵗ)ḡ。修正抵消这一初始化因素，随后更新沿 m̂ₜ/(√v̂ₜ+ε) 进行逐坐标缩放。其中 ε 是正的数值稳定项。一阶统计平滑方向，二阶统计提供相对幅度；二阶量是未经中心化的平方矩，与减去均值后的方差相差一个均值平方项。逐坐标缩放与前述普通梯度步的整体学习率不同，因此其稳定性也不能直接由同一个欧氏下降界确定。[18]

全局范数裁剪则在梯度过大时按共同系数缩小向量：g←g·min(1,c/‖g‖₂)，零梯度保持不变。它限制送入后续步骤的梯度范数，与优化器的逐坐标缩放分工不同。ViT 的 ImageNet 设置使用全局范数阈值 1 的裁剪；该取值属于 ViT 的原始配方，换模型规模要重新确定。[2]

扩大规模同时扩大哪些成本

参数容量增加需要足够数据与优化机会才能被利用。ViT 在较小数据设置中受泛化与正则化影响，较大的预训练集合使大模型容量更充分发挥；原文的对照还包含训练时长和具体配方。[2] 重复曝光增加优化次数，但不会等量增加新的原始场景；随机掩码可以生成更多条件组合，也仍依赖相同图像或文档。

长序列扩大注意力交互和激活，较宽模型扩大投影、前馈与状态。BERT 先大量使用较短序列，再用较长序列学习更长位置范围；MAE 则以减少编码器可见图块改变每步工作量。[1, 3] 这两种安排分别改变训练阶段的输入长度与单样本计算图。规模收益、每步成本和有限预算内的更新次数由此相互制约，资源更大同时改变多项量。

预训练评估与跨任务迁移

预训练损失衡量所构造的任务，迁移评估衡量表示在新目标下怎样被使用。BERT 微调任务模型，ViT 更换分类头并适配，MAE 移除重建模块后评估编码器，CLIP 以文本描述构造分类接口。[1–4] 这些协议固定和改变的部分不同，因此首先暴露的是不同的表示性质。

线性可读性与信息保留是两件事

线性探测冻结表示 h(x)，只学习线性头 Wh(x)+b；全量微调则允许 h 的参数一起变化。前者测试现有特征能否通过线性组合读出目标，后者测试表示能否在新监督下继续适配。MAE 原文比较线性探测与部分、全量微调，发现两类结果的趋势可以不同。[3]

一个四点例子可以说明这种区别。设输入和二元目标为：

x∈{−1,1}2,y=x1x2

相同符号的两点属于正类，不同符号的两点属于负类。若线性分数 w₁x₁+w₂x₂+b 能严格分开两类，两个正类不等式相加要求 2b>0，两个负类不等式相加又要求 2b<0，矛盾。因此原坐标中的目标线性不可分。

现在采用表示 z=(x₁,x₁x₂)。它在这四点上可逆，因为 x₁=z₁、x₂=z₁z₂，所以没有丢失输入信息；目标却可以直接由第二坐标读出。两个表示保留相同信息，却有不同线性可读性。这个示例解释了线性探测只度量一种读法，全量微调能否恢复被预训练丢弃的信息需要另作论证。

重建误差又衡量另一种性质。像素目标需要保留可预测的细节，分类目标可能忽略一部分背景或亮度。能够降低重建损失的因素不一定改善类别分离；目标函数与适配接口共同决定哪些预训练信息成为下游收益。

文本如何成为零样本分类器

CLIP 用类别描述的文本向量与图像向量比较。给定候选类别集合 C，相应分数归一化为：[4]

p(c|I,C)=exp(αuTvc)∑k∈Cexp(αuTvk)

文本编码器把类别概念映射为分类方向，目标训练样本并未用于拟合这些方向；这就是该协议的零样本适配。预训练仍利用图文监督，类别名称、上下文模板和描述组合也参与决定方向。模板一换，输入文本及其嵌入跟着变，相当于换了一个分类器。

类别集合还改变概率分母。新增候选即使不改变任何旧分数，也会降低每个旧类别的归一化概率；旧类别两两概率之比仍保持原值，最终赢家则可能被新增类别改变。由此，归一化分数依赖候选空间，不能仅因其和为一就解释为经过统计校准的真实类别概率。

评估协议决定结论的外延

冻结表示、部分微调、全量微调与零样本接口分别具有不同的适配容量和监督预算。它们之间的差别可以帮助定位表示可读性、适配潜力和任务描述能力，但分数不能脱离协议合成统一排序。目标集大小、训练样本、分辨率与开发中的模板选择又进一步改变条件。[2–4]

CLIP 原文承认开发中反复观察验证集，并讨论专业任务、类别设计、偏差和数据重叠；MAE 的识别评估使用标签并移除重建解码器。[3, 4] 因而，迁移结果应对应实际使用的信息和参数变化。保持评估边界清楚，才能辨认预训练贡献来自已有表示、目标监督下的重新学习，还是任务接口本身。

3. 后训练阶段

后训练将预训练能力接到更具体的任务、领域和行为目标。任务微调改变输出职责，参数高效方法限制更新空间，持续学习处理新旧目标的干扰；示范与偏好提供不同监督，蒸馏与校准又分别改变承载知识的模型和概率解释。本节沿这些机制展开，把预训练之后发生的各类操作分开讨论。[1–3, 15, 19–23]

任务微调与领域适配

预训练建立可迁移的参数与表示，后训练则把它们接到更具体的目标分布和输出职责。任务微调改变要预测什么，领域适配改变主要面对什么输入，两者可以同时发生。BERT、ViT 和 MAE 的迁移接口展示了这一分工：文本分类、词元标注、答案跨度和图像类别需要不同的输出结构，重建解码器也不必进入识别模型。[1–3]

输出接口怎样定义监督

对编码表示 hθ(x)，分类头以 softmax(Whθ(x)+b) 建立类别分布，交叉熵把错误类别与正确标签区分开。序列标注对每个位置输出分布；BERT 的抽取式问答则分别对起点和终点位置建立分布，解码还要选择满足位置约束的跨度。[1] 共享的是表示计算，预测空间与有效输出条件由任务决定。

冻结编码器只优化任务头，相当于在固定特征上选择读出规则；全量微调允许特征本身重组。设初始化为 θ₀，任务目标为：

minθ,W,b𝔼(x,y)∼Ptask[ℓ(Whθ(x)+b,y)]

冻结时 θ 被限制为 θ₀；部分微调则只允许一组参数变化。它们定义不同的可优化函数族，也承担不同的估计与计算成本。更多可变参数能够表达更多适配，但小数据下也会增加拟合偶然相关的机会，原有表示未必需要全部改变。

领域继续训练与任务微调改变不同分布

专业文本可能具有新的术语、组合关系和文档结构。用领域语料继续语言建模，仍可保留原预测形式，却把期望风险更多放到领域分布；用标注数据微调分类或生成任务，则进一步改变目标关系。[17] 前者帮助模型接触领域表达，后者规定这些表达如何服务于具体输出，领域熟悉度与任务正确性因而是两个层次。

ViT 在目标类别上更换输出头，MAE 移除重建模块后适配编码器，都把预训练关系转换为新的判别目标。[2, 3] 参数初始化降低从零学习表示的需求，最终收益却仍取决于目标数据、允许更新的模块和监督预算。后训练方法的比较要落在这些条件上，"微调"这个共同名称提供不了可比性。

参数高效适配与持续使用

全量微调为每个任务更新与基座同等规模的参数。任务数增加时，梯度、优化器状态和任务模型副本分别扩大训练与维护成本。参数高效适配以较小的可变部分编码任务差异，保留共享基座；其节约首先出现在更新状态与任务增量上，整个模型的规模保持不变。[7, 19]

LoRA 约束的是增量

设原权重 W₀ 的形状为 dₒ×dᵢ，LoRA 用秩 r 的分解表示增量，并冻结 W₀：[19]

h=W0x+sBAx,A∈ℝr×di,B∈ℝdo×r

原版缩放 s=α/r。增量 BA 的秩至多为 r，但 W₀+sBA 仍可以是满秩矩阵；适配只把增量限在低秩，原模型的秩不变。可训练参数由 dₒdᵢ 减为 r(dₒ+dᵢ)，只有 r 足够小时才有明显节约。论文以适配增量的低内在秩作为假设，并在所研究任务中给出证据；其他任务的最优更新是否低秩要另行检验。[19]

若某个理想单矩阵更新具有奇异值 σ₁≥σ₂≥…，其最佳秩 r 近似的平方 Frobenius 误差为尾部平方和：

minrank(Δ)≤r‖Δ*−Δ‖F2=∑j>rσj2

截断奇异值分解的前 r 项可以达到这个误差。其下界也来自子空间容量：任意秩 r 近似的列空间至多 r 维，令 P 为该空间的正交投影，则近似无法恢复 (I−P)Δ。平方误差至少为 Δ 的总平方能量减去该子空间捕获的能量。将 P 放到左奇异向量基中，其对角权重各在零与一之间、总和至多为 r；对递减的平方奇异值加权，最多捕获前 r 项的能量，余下尾部因此不可消除。

若重要变化集中在少数方向，低秩限制可以保留主要增量；若尾部仍很大，限制就会排除一部分变化。网络损失衡量的是输出差异，该关系讲的是表示约束，尾部误差与任务性能之间还隔着别的环节。

初始化决定第一步梯度流向

原版 LoRA 随机初始化 A、将 B 初始化为零，使初始增量为零。[19] 对一层、一个样本，记输出梯度为 g，则：

∂ℓ∂B=sg(Ax)T,∂ℓ∂A=sBTgxT

B 为零时，A 的初始梯度为零，B 则可以利用随机 A 产生的特征开始更新；随后 A 也获得梯度。若两者都为零，两个数据损失梯度都为零，这条乘积分支无法由普通梯度开始学习。零增量与非零可学习路径因此需要同时安排。

训练状态、合并与多任务服务

冻结权重不需要自己的参数梯度与优化器矩，但前向仍要执行基座计算，梯度也可能经过冻结层传向更早的可训练模块。激活、基座权重和生成 KV 仍存在。少量可训练参数主要缩小训练更新状态和每任务检查点，总显存不会按同一比例下降。

线性增量可以合并为 W=W₀+sBA，让单任务部署保留原矩阵乘结构。[19] 多任务并发若各自使用不同增量，共享一份已合并权重就不再足够；未合并的动态分支保留任务选择，却引入增量计算和批内路由。论文也指出这一合并与多任务批处理之间的取舍。

其他参数高效路线改变不同对象：适配器在表示路径中增加小模块，连续提示或前缀向计算提供可训练条件，LoRA 改变既有权重的增量。[19] 模块参数很少仍可能处于串行关键路径；可训练前缀还增加被注意力访问的状态。训练参数数目、前向形状和任务共享方式共同决定成本。

持续适配：学习新任务与保留旧能力

后训练不一定只有一次。新领域、任务和类别持续出现，模型需要学习变化，同时保留已有职责。持续学习综述将这种稳定性与可塑性的矛盾组织为不同设置，并区分离线与在线、已知或模糊任务边界，以及域、任务和类别增量。[15] 设置差异决定可访问哪些旧数据、是否知道任务身份、推理时怎样选择模块。

旧能力为什么会随新目标下降

记旧风险为 Rold、新风险的梯度为 gnew。对一个小的普通梯度更新 θ′=θ−ηgnew，在足够光滑的局部邻域中：

Rold(θ′)−Rold(θ)=−ηgoldTgnew+η22gnewTHoldgnew+O(η3)

两梯度方向冲突时，内积为负，一阶项会提高旧风险。即使已经接近旧目标的局部极小点、一阶梯度接近零，新方向仍可能穿过旧风险的正曲率区域，引起二阶增长。这里的 Taylor 分析指出共享参数更新的干扰来源可以不止一种：一阶冲突与二阶曲率各自贡献一部分。

领域表达变化但任务不变，更接近域增量；新增任务接口或判别类别，则改变监督与输出空间。[15] 有明确任务身份时可以选择独立适配器，任务身份未知时还需要识别和路由。模块化适配因此把一部分学习问题转为模块选择问题。

回放、约束与隔离分别回应哪种干扰

回放让旧数据继续产生梯度。新旧风险的混合 R=λRold+(1−λ)Rnew 改变合成更新方向，避免只有新目标控制参数；它消耗保存和采样预算，也受旧数据可用性与隐私限制。[15]

正则化可以用重要性矩阵 F 限制偏离旧参数：

Ω(θ)=12(θ−θ0)TF(θ−θ0)

对称半正定 F 使不同方向具有不同偏离成本，梯度为 F(θ−θ₀)。这个一般二次约束把“保留重要变化方向”写进目标；重要性估计、局部近似和新任务需求决定实际取舍。输出蒸馏则在给定输入上保持旧分布，限制的是行为关系，不一定逐参数保持相同值。[15]

参数隔离把新知识放入独立模块。若旧路径的全部参数、输入处理和路由均保持不变，其确定性函数也可以保持不变；共享模块仍被更新或选择发生变化时，这个条件就不成立。LoRA 降低更新规模，但低秩增量依然能改变输出，参数高效性与无遗忘是不同性质。

持续更新的评价对象

最新任务收益、旧任务保持、跨任务迁移和模块成本需要共同描述。只评估最新任务，会看不到长期能力是否退化；只限制参数位移，又可能掩盖新技能未被学到。可检索事实与业务状态可以在外部更新，稳定技能与决策关系可能需要参数适配。检索、参数更新和隔离模块分别改变信息获取、共享行为与任务路径，适用范围由变化对象决定。

语言及交互任务中的指令、偏好与对齐

预训练语言模型学习数据中的续写关系，用户请求则通常要求选择一种有用的行为：回答问题、遵守格式、使用工具或在依据不足时保持谨慎。InstructGPT 将示范学习、偏好建模和策略优化分开，用不同数据提供这几类信号。[20] 指令微调改的是概率学习的目标条件：用任务条件和目标回答去替换原始的续写关系。

指令微调学习什么条件分布

设输入 x 包含指令、背景和历史，对应目标回答为 y。监督微调（SFT）的基本损失是：

ℒSFT=−𝔼(x,y)∼D[∑t=1|y|logπθ(yt|x,y<t)]

它仍是条件似然，但训练分布由普通网页续写转为任务与示范回答。共享参数在多种任务上学习指令到行为的映射，示范中的措辞、推理组织和格式也会进入目标分布。[20] 没有被示范覆盖的可靠性条件，不会仅因数据被称为“指令数据”就获得保证。

多轮数据可只在需要模型生成的回答位置计算损失。用户输入和工具返回仍作为上下文影响梯度，但不必被当作模型要模仿的输出。角色边界同时定义谁提供信息、谁执行动作；把所有角色内容无差别作为目标，会改变所学习的条件关系。

按全部回答词元平均，较长回答占据更多目标项；先按每条回答长度归一化、再对样本平均，则更接近均匀对待回答。两者赋予样本不同权重，可能改变长解释与短结果的相对训练强度。损失掩码和归一化因此也是任务定义的一部分。

示范与偏好提供不同信息

SFT 提供一个应当复现的回答，却通常没有明确说明其他候选为何较差。偏好数据提供两个回答的相对选择，适合表达难以给出唯一标准文本的质量差异，例如完整性、相关性或表达方式。[20, 21] 这种比较不需要把偏好者变成逐词作者，却依赖候选质量和评价标准。

训练时 SFT 使用真实目标前缀，生成时使用自身输出。一旦生成偏离示范轨迹，后续上下文也随之改变。策略采样与评价可以提供当前模型实际生成路径上的反馈，而固定示范只覆盖其数据中的条件。两者在监督来源与覆盖范围上互补，偏好优化也仍受评价者和样本分布限制。

奖励模型与受约束的策略优化

InstructGPT 先训练示范策略，再让标注者比较模型候选，用奖励模型预测偏好，最后通过 PPO 优化策略。[20] 这条链把难以直接求导的人类判断转为可用于学习的信号，同时引入奖励估计、策略采样和更新稳定性三个问题。

相对偏好怎样变成奖励

对同一输入 x，优选回答为 y₊、较不受偏好的回答为 y₋。Bradley–Terry 模型用奖励差表示优选概率：[21]

P(y+≻y−|x)=σ(rφ(x,y+)−rφ(x,y−))

其中 σ 是 logistic 函数。最大化比较数据的似然，使观测到的优选回答得到较高相对奖励。对某个输入，把全部奖励都加上相同常数不会改变比较概率；相对标签因此不能唯一确定绝对奖励基准。这个奖励只是偏好的代理，事实正确率与安全属性另有各自的度量。

固定奖励 r 与参考策略 πref，策略目标可写为：

J(π)=𝔼x∼D[𝔼y∼π(·|x)r(x,y)−βKL(π(·|x)‖πref(·|x))]

β>0 时，KL 项惩罚相对参考分布的偏离。它限制只为代理奖励而大幅改变原行为的激励，却不保证代理奖励本身正确。InstructGPT 还混入预训练似然更新，以缓和其报告的部分原任务退化；这是额外的能力保持目标，与 KL 约束作用不同。[20]

为什么策略采样需要专门的梯度估计

对固定 x 与不依赖 θ 的奖励，若允许交换求和与微分，有：

∇𝔼y∼πθr(y)=𝔼y∼πθ[r(y)∇logπθ(y)]

这来自 ∇π=π∇log π，避免对离散采样动作直接求导。减去只依赖条件的基线不改变期望梯度，因为概率总和的导数为零，却可以改变估计方差。多步任务进一步使用状态价值与优势估计，把动作相对其条件下常见结果的收益用于更新。[24] 此式只解释固定奖励部分，KL 等依赖策略的项还需按相应定义处理。

PPO 在旧策略采集的样本上优化替代目标，概率比 ρₜ=πθ(aₜ|sₜ)/πold(aₜ|sₜ) 修正当前与采样策略的动作概率差异。其裁剪目标为：[24]

Lclip=𝔼^[min(ρtA^t,clip(ρt,1−ε,1+ε)A^t)]

正优势样本的概率提高到比值上界后，这一项不再提供继续提高的收益；负优势样本的概率降低到下界后，也不再奖励继续降低。方向相反的恶化仍计入目标。裁剪作用在替代目标的激励上；实际概率比不因此被锁进区间，全局 KL 也没有硬保证。

πold 随采样批次更新，用于控制局部策略步；πref 通常固定为对齐前的参考模型，用于约束整体偏离。两种比较的时间尺度不同，即使都涉及概率比或 KL，也不承担同一职责。

DPO：从最优策略到直接偏好损失

奖励建模加策略优化把偏好拟合与模型更新分成两个阶段。DPO 利用受 KL 约束目标的解析关系，把奖励差重新参数化为策略的对数概率比，直接在固定偏好对上学习。[21] 它省掉的是训练中的显式奖励模型和在线策略采样循环，数据收集与参考模型计算照旧。

受约束目标为什么具有指数加权解

固定输入 x，在参考策略支持内考虑回答分布，设 β>0、奖励有限且配分函数 Z(x) 有限。定义：

π*(y|x)=1Z(x)πref(y|x)exp(r(x,y)β)

将其对数代入前节的奖励减 KL 目标，得到：

Jx(π)=βlogZ(x)−βKL(π(·|x)‖π*(·|x))

第一项与待优化的 π 无关，第二项在两分布相等时为零，其他情形非正，因此 π* 是该分布空间中的最优解。参考概率保留原分布的基准，指数项按奖励重加权；β 相对奖励尺度越大，重加权越弱。这个证明针对给定奖励和分布空间，参数化网络未必能表达其精确解。

配分函数为何从成对比较中消失

反解奖励可得 r(x,y)=βlog[π*(y|x)/πref(y|x)]+βlog Z(x)。同一输入下两回答的奖励相减时，最后一项消失。代入 Bradley–Terry 偏好模型，再用 πθ 表示待学习策略，定义：

δθ=β[logπθ(y+|x)πref(y+|x)−logπθ(y−|x)πref(y−|x)],ℒDPO=−𝔼Dlogσ(δθ)

训练只需计算优选与非优选回答在策略和参考模型中的序列对数概率，不需要枚举全部回答估计 Z。原始序列概率是各词元条件概率的乘积，对数后为求和；改成按长度平均会改变这一目标及其推导关系。

更新强调尚未满足的相对偏好

单对样本损失的边际导数为：

∂ℓ∂δθ=σ(δθ)−1=−σ(−δθ)

校正后的相对排序错误时，梯度权重较大；已经具有很大正间隔时，权重减小。SFT 只拟合示范回答，DPO 则比较两条完整回答，并以参考策略校正初始概率关系。它约束相对变化，不保证每次共享参数更新都单独提高优选回答的绝对概率。

DPO 的联系依赖偏好模型、参考支持和数据覆盖。固定数据方便优化，也可能缺少新策略会产生的错误或优质回答；标注冲突和分布偏移还会影响可拟合关系。在线 RLHF 与离线 DPO 的区别在采样反馈链、计算状态和拟合对象，在有限数据上把偏好损失压到最小，与在所有真实任务上表现最佳是两回事。

DeepSeek DSec：智能体学习中的环境生命周期

文本回答可以视为条件下的一次输出，工具型智能体则反复观察、行动并改变环境。轨迹包含观测、动作、工具结果和奖励；环境状态还包含文件、进程、会话与外部连接。DSec 的报告说明训练基础设施怎样保持这些状态，并处理长期 rollout 与可抢占 GPU 作业之间的冲突。[5]

文本轨迹与执行状态为何需要同时保留

同一段命令文本在不同文件版本、工作目录或进程状态下可以产生不同结果。保存模型对话只能保存智能体已看到什么，不能重建全部实际环境；从头重放动作又可能重复写入、发送请求或启动程序。恢复因而涉及“动作是否已经发生”和“结果是否已经提交”的对应，而不仅是生成到了哪个词元。

DSec 早期命令日志方案在恢复时复用已经完成的操作结果，避免再次执行非幂等操作。后续方案将控制流程放在 worker 容器，将工具执行放在智能体沙箱，两者都在可抢占 GPU 池之外，共同保留 rollout 状态。[5] GPU 作业恢复后重新连接这些状态，使模型计算资源的生命周期与环境执行的生命周期分离。

这种分离保住的是交互进度，代价包括持续状态占用与跨组件交接。报告进一步利用容器暂停和内存回收，或 microVM 内存与执行快照，减少挂起阶段的资源占用。恢复需要重新获得可用工作集，也会进入请求等待路径。[5] 训练采样还需关联实际使用的策略版本；环境存活只说明进程还在，保留轨迹是否来自最新策略要单独核对。

奖励有效性与可获得信息

若正常解题和读取泄漏答案都得到相同奖励，单独的奖励最大化无法区分两条路径。环境允许访问什么，因而参与定义学习问题；隐藏参考答案、评测内部日志或非预期外部实现可改变最容易获得高奖励的行为。

DSec 报告了通过日志、内部通信与任务预期之外的信息源获取答案的风险，并将环境构建和运行账号分离，清除打包残留，使用 AppArmor 与按沙箱配置的 eBPF 策略限制部分文件、套接字和网络访问。[5] 这些措施分别约束可见信息与可执行操作；防止答案泄漏、隔离不可信执行和限制资源破坏仍是不同职责。

这组案例把奖励学习连接到状态和权限：最终输出通过评测，既可能源于预期能力，也可能源于额外信息路径。只有把任务允许的信息与实际执行轨迹纳入解释，成功奖励才具有相应的能力含义。报告中的控制措施针对的是具体风险，覆盖范围以报告所述为限。

蒸馏、校准与适配效果评估

蒸馏：传递输出关系

教师可以是更大模型或模型集合，学生则具有不同容量和部署成本。Hinton 等把知识传递理解为输入到输出的映射：除了最高概率类别，其他类别的相对概率也反映教师学到的相似关系。[22] 蒸馏用这些关系训练学生，不要求两者具有相同内部参数或网络宽度。

软目标比单个标签多提供什么

硬标签只标出一个正确类别，软分布还告诉学生教师容易混淆哪些候选。设教师与学生的 logits 分别为 v、z，温度为正数 T，软概率为 softmax(v/T) 和 softmax(z/T)。将它们记为 pT、qT，一个常见混合目标为：

ℒ=λT2KL(pT‖qT)+(1−λ)CE(y,q1)

教师保持固定、0≤λ≤1。KL 的教师熵不依赖学生，因此其学生梯度与软目标交叉熵相同；硬目标在温度一的分布上计算，使真实标签仍能影响学习。数据覆盖与教师误差同样被传递，软目标不会自动变成更可靠的真值。

温度平方因子从哪里来

对软目标交叉熵，学生 logit 的导数为：

∂ℒsoft∂zj=1T(qj−pj)

第一个 1/T 来自 logit 缩放的链式法则。若类别数为 K、教师和学生 logits 各自中心化，并且温度相对 logit 幅度足够高，指数的一阶展开给出 qⱼ≈1/K+zⱼ/(KT)，教师同理，于是：

∂ℒsoft∂zj≈zj−vjKT2

另一个 1/T 来自概率差随温度缩小。乘 T² 因而近似保持软目标梯度相对硬目标的尺度；这个近似只在相应温度范围内成立，换温度要重新校准尺度。[22] 高温极限接近匹配中心化 logits，有限温度则对不同候选赋予不同权重。

生成模型中的两种传递接口

语言模型可以在给定前缀下匹配教师的词表分布，也可以利用教师生成的回答做监督训练。前者保留逐位置候选概率，要求对应输出空间与教师计算；后者只需文本样本，有限样本中没有逐位置保存完整软分布。两者共享教师信息来源，却有不同的数据对象和覆盖条件。[17]

学生容量有限时，多个目标关系可能需要取舍。蒸馏的价值来自任务相关关系能否以较低成本进入学生，评价则同时涉及任务结果、教师错误的继承和真实部署成本。低秩适配动的是任务增量，蒸馏动的是整个学生模型，两者作用对象不同。

校准：正确决策与可信概率

分类正确率只关心最高分标签，概率质量还关心模型表达了多大的确信。Guo 等在图像与文档分类网络中观察到准确率与校准可以分离，并研究了后处理校准。[23] 这一框架解释概率的评价对象，不能直接把分类实验结论推广为生成答案的真实性保证。

校准是分布上的频率关系

记预测标签为 Ŷ、其置信度为 Ĉ。理想的最高类置信度校准要求，在分布支持内相应条件成立：

P(Y^=Y|C^=p)=p

例如，置信度接近 0.8 的一组预测应有接近 80% 正确；这一对应关系针对一组预测，单个样本的成败无法由此判断。有限样本常按置信度分箱，比较每箱正确率与平均置信度。仅计非空箱 Bₘ 时，经验 ECE 为：[23]

ECE=∑m|Bm|n|acc(Bm)−conf(Bm)|

分箱数量与样本组成改变估计，箱内平均还可能掩盖更细粒度差异。因此 ECE 是汇总近似，涵盖的概率关系以所选分箱为限。负对数似然又对错误真标签被赋予极低概率特别敏感，提供与最高类正确率不同的信息。

温度缩放为什么可以不改变分类结果

固定模型 logits z，温度缩放只学习一个正参数 T，输出 softmax(z/T)。对任意两个类别，zᵢ>zⱼ 当且仅当 zᵢ/T>zⱼ/T，所以精确算术下 argmax 集合不变。概率幅度却随 T 改变，校准可以改善而分类标签完全相同。[23]

固定 logits 时，输出熵的温度导数为：

dHdT=Varq(T)(z)T3≥0

该式可由 H=log Z−E[z]/T 对 T 求导得到。温度增大使分布更平缓，但更平缓是否更符合真实正确率，仍由数据决定。Guo 等用保留验证集最小化负对数似然选择 T，假定相关数据来自相同分布；一个共享温度也不能任意修正每类或每个输入的特殊误差。

分类温度、蒸馏温度与生成采样温度

蒸馏温度塑造教师提供的软目标，校准温度拟合概率与标签的关系，生成采样温度则改变实际输出的采样分布。形式相似，作用阶段与目标不同。分类 argmax 不变的性质，也不意味着采样生成得到相同回答。

语言模型的词元概率表示给定前缀下某个词元出现的概率；回答事实正确与否是另一事件。整段序列概率还受长度和表达方式影响，流畅的错误陈述可以具有高语言概率。生成任务中的可靠性因而需要明确评价事件、证据与目标分布，把任意 softmax 数值直接当作答案正确率会出现错位。

适配收益、行为保持与系统成本

后训练方法分别改变目标分布、可变参数、监督来源或概率解释，评价也沿这些对象展开。任务微调关注目标输出，持续学习关注新旧任务关系，偏好优化关注观测比较，蒸馏关注学生能否承载教师的任务关系，校准关注概率与正确频率。它们可以组合，却不由同一项损失下降证明全部收益。

奖励模型打分变高，只说明策略更接近这个代理目标；独立的偏好评价、事实正确性和具体风险仍提供不同证据。InstructGPT 将人类评价与公开任务评价分开，还报告并回应部分能力退化。[20] 这种结果结构解释了为什么偏好提高与旧任务保持可以同时成为优化职责。

成本也由不同状态产生。LoRA 减少每任务增量与优化器状态，基座和大部分前向仍在；蒸馏可以换成较小学生，却新增教师数据与学生训练；DPO 去掉训练中的在线奖励优化循环，仍计算候选序列概率和参考关系。[19, 21, 22] 训练效率、模型副本大小和部署延迟之间没有单一比例。

长期系统还要承担适配器选择、版本身份、回滚和评估分布变化。旧任务的下降可能来自参数干扰，也可能来自路由、模板或标签映射变化。将模型变化与接口变化分开，归因才能落到对应机制上。

4. 推理阶段

输出接口决定推理流程

推理并不天然等于逐词生成。BERT 的分类与抽取式问答、ViT 的图像分类，都在完整输入上跑一次编码再读任务头；CLIP 分别编码两种模态然后比较向量。只有翻译和语言生成这类自回归解码器，才需要把选出的输出接回历史反复推进。[1, 2, 4, 6] 两类过程都含矩阵乘和注意力，但被重复计算的对象、状态的寿命、可并行的程度都不一样。

自回归模型表达的是一串条件分布的乘积。给定提示 x，生成序列 y 的概率是：

p(y|x)=∏t=1Tp(yt|x,y<t)

训练时目标历史已经给定，因果掩码让所有位置的条件预测在一次前向里并行算完；生成时下一个位置的输入还没被选出来，不能把未知输出当作已知条件。这个数据依赖造成了逐步解码的串行部分，与它叫 Transformer 与否无关。

KV 缓存的依据：历史表示在追加下不变

设参数、位置编号和推理设置都固定，各层历史位置只读不晚于自身的位置，其余子块也逐位置计算。第一层的历史输入没有改变；若第 l 层的历史表示不变，第 l+1 层历史查询能读到的键和值完全一样，逐位置前馈与残差同样一样。对层数做归纳，追加后缀不会改变历史位置的表示。历史 K、V 于是可以留下来，新查询读旧状态、追加新状态即可。[6]

这套论证依赖确定的推理操作：关闭 dropout，固定权重、适配器、位置变换与上下文解释方式。某种位置缩放随总长度改变，或者存在跨位置的全局归一化，历史计算的条件就不再成立。完整双向编码器让历史位置能读到新增内容，归纳前提直接失效。编码器—解码器还有一类复用：源输入固定时，编码器输出及其键值投影保持不变，目标查询逐步更新即可。

缓存省下的是历史投影及其在后续层里的重算，历史信息本身照旧要参与注意力。对一个新查询，仍要算与 S 个历史键的匹配、汇聚 S 个值，注意力工作量随上下文长度上升。生成 T 个词元时，注意力累计访问长度约为 T·S₀+T(T−1)/2，S₀ 是初始上下文长度。代入 S₀=4096、T=1024：4,194,304+523,776≈472 万次位置访问，缓存并没有把长输出的成本压成常数。[7, 14]

状态容量与执行瓶颈

设每层 KV 配置相同：层数 L、批量 B、缓存长度 S、KV 头数 Hkv、头维 dh、每元素 b 字节，只算 K 与 V 的原始容量是：

MKV=2LBSHkvdhb

代入 24 层、批量 1、长度 2048、16 个 KV 头、每头 64 维、每元素 2 字节：2×24×1×2048×16×64×2=201,326,592 字节，正好 192 MiB。请求长度不一时按长度求和，层配置不一时逐层求和；页尾空槽、块表、量化尺度、工作区与图缓冲另算。共享 KV 头把 Hkv 降下来，同时改变模型的投影结构；分页只改变分配与寻址，有效词元需要的张量元素数一个不少。[14] 这条式子针对显式保存 K 与 V 的结构，MLA 保存的是潜在向量与解耦位置键，每层每词元的有效状态是 d_c + d_r 个元素。[32] 推导见架构章的 MLA 专题。

预填充把多个已知位置组织成矩阵运算，权重能在很多行之间复用。小批量解码每步只有寥寥几行，却照样要把权重和历史 KV 从显存读一遍。用一个具体模型看这道分界：7B 参数、fp16 权重占 14 GB，显存带宽 2 TB/s 时，每词元读一遍权重至少 7 ms，算力还远没到瓶颈——这就是小批解码受带宽限制的样子。用理想化的算力 C、带宽 W、运算量 F、数据移动量 D 写，一个执行段的时间下界是 max(F/C, D/W)。C 与 W 必须对应同一条实际设备路径，融合、缓存层级与通信都会改变 D，峰值规格高于可持续速率。

增大批量能摊薄每词元的权重读取，同时抬高活跃 KV、工作区与排队等待；上下文很长时，KV 读取又可能反过来主导。由此，"单请求最快"与"总吞吐最高"往往落在不同的执行点上。优化的目标是换掉主导资源路径，笼统增加并行度并不解决这件事。[11]

内容稀疏与状态压缩还要分开记账。DSA 在 MLA 的历史里选词元，MiniMax MSA 在 GQA 的历史里按组选块，两者减少的都是主分支这一次读取的集合；索引器仍要扫过历史，未来的查询也可能选中此刻没读的位置。把访问预算当成缓存容量，会漏掉索引键与重排缓冲；MoE 的激活专家预算同样决定不了服务需要备多少总专家存储，采用 EP 时还要把 dispatch／combine 的跨设备路径算进每步成本。[33–35]

优化先定位对象：输入、模型与执行系统

Zhou 等把 LLM 高效推理分成数据、模型、系统三个层次，并把计算量、内存访问与内存占用拆成不同成本。[11] 这套分类的用处在于先认出瓶颈长在哪：输入压缩改变模型实际看到的内容，结构与数值压缩改变模型表示，引擎优化重新组织既定的计算和状态。三者可以叠加，各自的质量条件却不同，用一个"加速"盖住全部会丢掉判断依据。

省掉输入会在别处补回来

冗长的检索文档或重复提示推高预填充工作量，也留下后续生成要访问的 KV。摘要、去重、筛选、提示压缩能把输入压下来，代价是可能删掉决定答案的那段证据。[11] 文档问答里这两件事直接对立：相关材料的条件与解释链被截断之后，模型跑得更快，能支撑的回答范围同时缩小。这个代价与只调整 kernel 访存组织的情况完全不同——后者一个 token 都没删。

模型侧的量化、剪枝、蒸馏和结构设计，分别动精度、参数、知识传递和计算图。省下权重空间与省下每个请求的 KV 是两笔账；某些结构改动还要配套训练或格式转换。系统侧的融合、缓存、批处理和调度一般不以改变目标模型为目的，也拿不到"逐位相同"的保证：浮点归约顺序、随机数来源和执行顺序都有各自的契约。[11]

容量、首词元和持续输出要分开量

长提示先撞上首词元等待，长输出持续累积解码步骤与 KV，占用与排队取决于同时存活的请求数。综述分别给出首词元时延、逐输出词元时延、整段生成时延、模型大小、KV 大小与吞吐的定义。[11] 用数字感受一下预填充的形状：提示从 4K 涨到 32K，成对交互的位置对数涨 64 倍，首词元等待随之上升；而这一步一旦过去，后续每步解码只多读 32K 个历史位置。交互式应用里用户很快看到首词元、后面却卡顿，与离线批处理吞吐高、单请求等待长，是同一组量的不同组合。

于是各方案的职责可以逐条对上：分页减少容量碎片，连续批处理提高多个请求共享执行资源的机会，分块预填充限制长请求对单轮执行的影响，前缀复用省掉重复输入的计算。缺掉某个机制时出现的问题，要用碎片、空闲名额、长步阻塞、重复计算分别解释，笼统归到"GPU 利用率低"上会丢掉定位依据。后面读框架时，就沿这几条职责看实现。

量化：压缩表示与控制输出误差

量化把连续数值塞进有限网格。以仿射量化为例，整数 q=round(w/s)+z，随后被截断到允许区间；解码时算回 s(q−z)。步长 s 决定分辨率，零点 z 决定网格落在哪。取一个具体例子：权重范围 [−0.5, 0.5]、4 比特、z=0，可用整数是 −8 到 7，于是 s=0.5/8=0.0625，未截断时最近舍入的单元素误差不超过 s/2=0.03125。缩小范围能让大部分数值变细，同时把离群值截断得更狠——截断误差没有 s/2 这个界，"位数相同"因此说明不了误差相同。

权重、激活和 KV 量化分别作用于固定参数、当前中间量和随请求增长的状态。原始权重从 16 位降到 4 位，理想情况下数据量减到四分之一，尺度、零点、分组信息、未量化层和执行缓冲照旧占地方。W4A16 也不保证矩阵乘在所有硬件上跑四位整数：运行时往往先解包、反量化，再做高精度乘法。GPTQ 原论文明确区分"减少读取成本"与"拿到低位乘法硬件加速"这两件事。[26]

只缩小权重误差还不够

对线性层 Y=WX，令量化误差 E=Ŵ−W，输出误差就是 EX。按 Frobenius 范数展开，其平方等于：

‖EX‖F2=tr(EXXTET)

同样大的权重偏差，落在高频激活方向上和落在低频方向上，造成的输出偏差不一样；不同输入维度的误差还可能互相抵消。最近舍入只做逐元素的最小网格距离，完全没看这些方向和相关性。GPTQ 于是改用少量校准输入建立逐层重建目标，最小化 WX 与 ŴX 的差，把"权重接近"换成"输出接近"。[26]

二阶补偿的局部推导

看单个输出行，把它写成列向量 w，尚未固定的坐标贡献的二次误差是 δᵀHδ/2，其中 H=2XXᵀ；为了可逆和数值稳定，可以加一个正的对角阻尼。现在把第 q 个权重摁到网格值上，偏移 e=quant(wq)−wq，其余坐标允许连续调整。约束写成 uqTδ=e，u_q 是第 q 个单位向量。Lagrange 一阶条件给出 Hδ=λu_q，代回约束解出：

δ=e(H−1)qqH−1uq,Δmin=e22(H−1)qq

一次舍入的误差因此可以沿输入相关方向分摊到还没量化的权重上，这就是原论文所用逆 Hessian 补偿的来源。要注意它解的是当前这个连续补偿子问题，后面的坐标仍得落到离散网格上；它给不出全网络量化的全局最优，也保证不了下游质量。

原始 OBQ 逐行挑选贪心顺序，GPTQ 改成所有行共用一套列顺序。逐行重建共享同一份 X，剩余坐标的 Hessian 也一样，逆矩阵信息就能复用。块内逐列处理，跨块的更新延后合并成矩阵操作，低计算密度的更新因此跑得动；Cholesky 重写与阻尼应对反复消元积累的数值误差。这三处改动各自解决重复工作、访存效率和稳定性，用一句"二阶量化更准确"概括不掉。算法细节见原论文 §§3–4。[26]

校准数据限定了哪些激活方向被重视。短文本上重建风险低，长上下文、专业词汇和严格工具参数上的误差完全可能更大；逐层的局部补偿也管不住层间误差传播。困惑度、任务质量、峰值状态因此在三条轴上分别评价。低位方案的收益来自张量表示与匹配内核的组合，输入分布和实际执行路径都会改变结论。[7, 26]

采样改变分布，搜索改变决策目标

模型 logits 先被温度 τ>0 缩放，再走 softmax 得到概率。降温让相对偏好更尖锐，正温度不会改变最大 logit 落在哪个位置。Top-k 把支持集砍到前 k 个候选，nucleus 采样按累计概率圈出一个候选集合，再在集合内重新归一化。这些步骤产出的是处理后的分布。语法掩码进一步按当前解析状态过滤候选，它保证的只是输出符合形式约束，字段里的事实对错另说。

贪心每步取条件概率最高的词元，整条序列的概率未必最大。举个两候选的例子：第一步 A、B 的概率是 0.6 与 0.4，从 A 出发最好的完整后续概率是 0.5，从 B 出发是 0.9，两条最好完整路径的概率分别是 0.30 与 0.36。贪心选 A，B 那条路整体概率更高。Beam search 保留多个部分序列来缓解这种局部短视，有限的束宽仍会丢候选，长度归一化又把比较目标改了；模型概率高与任务质量高是两回事。[6]

投机采样为什么能保住目标分布

投机采样让一个小模型便宜地吐出短草稿，再由目标模型并行算出草稿各位置的条件分布。历史已知时，多个候选位置可以像预填充一样并行打分；接受却必须从左到右，一旦拒绝，后面的条件历史就不再成立。Chen 等的算法把这种计算组织与修正拒绝采样配对；直接采信目标模型排名靠前的词元得不到这个保证。[25]

以下统一用 p 表示目标分布、q 表示草稿分布，与那篇论文的符号相反。固定同一段历史和同一个词元空间，草稿 x∼q 以 a(x)=min(1,p(x)/q(x)) 被接受。q(x)=0 的词元永远采不到，那里不必算比值。接受分支对 x 贡献的概率质量是 min(p(x),q(x))，总拒绝概率 Z=1−∑xmin(p(x),q(x))。拒绝之后从 r(x)=[p(x)−q(x)]+/Z 采样，这里 [u]+=max(u,0)。两条路加起来，最终输出的概率恰好是：

q(x)a(x)+Zr(x)=min(p(x),q(x))+[p(x)−q(x)]+=p(x)

Z=0 意味着两个分布完全相同，拒绝分支永不触发。对每个已接受前缀重复这步单步关系，条件概率的链式法则就把整段序列的分布还原回目标分布。若 K 个候选全部接受，目标模型在最后一个位置的 logits 还能多生成一个词元。整套证明依赖真正用于生成的那个条件分布：用了温度、截断或语法约束，接受与残差就必须改用处理后的概率；量化与浮点实现差异则在精确实数证明的范围之外。参见原论文 Algorithm 2 与 Theorem 1。[25]

平均单步接受率可以写成 α=∑xmin(p(x),q(x))=1−TV(p,q)，TV 是总变差距离。举例：p=(0.7,0.3)、q=(0.5,0.5)，α=0.5+0.3=0.8，总变差 0.2。这个式子说明有用的草稿要贴近目标在真实历史处的分布，在某个独立测试集上准替代不了这一点。在各位置接受率都近似 α、条件变化可以忽略的简化模型下，一轮输出数的期望是 1+α+⋯+αᴷ；这个期望值依赖上述简化假设，推广到一般情形要重新验证。

设一轮草稿、验证和管理的时间分别是 Kt_d、t_v(K)、t_o，理想情况下平均每词元时间约为 [Kt_d+t_v(K)+t_o]/E[N]。它低于普通目标解码时间才有净收益。α 变大提高有效输出，K 变大同时带来更多草稿开销、更宽的验证形状和额外状态；批量已经摊薄权重读取时，验证更可能加计算压力。原论文的小批量 Chinchilla／TPU 结果支持的是那套执行条件，推不出任意框架的倍数。[25]

分布校正还得配上一套状态校正。首个拒绝之后，目标 KV、草稿进度和语法状态都属于报废路径；只换输出词元继续用这些状态，下一步的条件就和证明对不上。投机执行因此是一段"暂存候选—确认有效前缀—回收无效后缀"的状态事务，框架层的页保护、回滚和多 rank 同步与概率算法同样重要。

端到端服务：计算时间之外的状态与等待

一个请求的首词元时间由排队、输入处理、预填充、采样和回传共同构成，词元间隔还受后续调度与通信影响。吞吐描述单位时间完成多少工作，尾时延描述慢请求等多久，两个数不能互相替代。对满足稳定性、边界一致和有限均值的系统，Little 定律给出平均在途请求数 N¯=λW¯，λ 是完成率、W̄ 是平均驻留时间。代个数：λ=100 请求/秒、W̄=0.5 秒，平均有 50 个请求在途。它是流量守恒关系，推不出硬件吞吐：服务能力不变而到达率上升，多出来的请求只会堆进队列。

模型服务与工具执行走的是两条路径。智能体可能交替调用模型、程序、检索和有状态沙箱。DSec 报告的容器、microVM、完整 VM 与 FnCall 各自有不同的功能与隔离边界；镜像层按需读取作用于环境准备，暂停与快照作用于闲置资源回收。[5] 它们减少的是端到端流程里的环境等待与占用，与 Transformer 的注意力运算量无关。

按需读取省掉了搬运完整镜像，没读到的数据仍可能在程序访问时触发等待；暂停回收降低常驻内存，恢复状态要重新付访问与同步的成本。这一点和 KV 缓存形式相像——都是把"能否再次使用"变成状态问题，收益取决于命中率与恢复成本。对象却完全不同：环境快照保存程序与文件系统状态，KV 保存特定模型的历史注意力状态。恢复程序重建不出模型缓存，保存 KV 也保不住工具进程。

于是完整任务时间可以按模型执行、队列、工具执行、环境创建与恢复、数据传输逐段分解，再看其中哪些段能重叠。串行部分直接相加，重叠段的耗时由依赖路径决定；把各个局部加速率相乘会漏掉没优化的阶段。取固定工作量分析：某段占总时间的比例是 f，它即使被加速到无穷快，整体加速比也不超过 1/(1−f)。代入 f=0.3，上限是 1.43 倍。这解释了为什么模型内核提速之后，工具与调度仍可能占掉用户的大部分等待。

设备端还多一层散热与功率边界。每任务能量是既定边界内功率对时间的积分，时延缩短不必然降低能量，峰值功率也代替不了平均功率。冷启动、暖缓存、持续运行和节流之后是几个不同状态。[7] 质量、内存、时延、能量一起划出可用执行点，各取一项的最好值拼成排名没有意义。

5. 训练／推理框架

从模型计算到系统执行：三种不同的优化对象

Transformer 的架构规定了表示如何交互，训练与推理框架则决定这些计算怎样映射到设备、内存和请求。这里需要区分三个层次。算子层执行矩阵乘、注意力、归一化和量化；引擎层组织模型前向、状态分配、批处理与采样；服务层处理协议、连接、排队、路由和模型生命周期。FlashAttention 属于训练与推理都可使用的注意力加速技术，vLLM、SGLang 等主要组织推理执行，Ollama 则把执行引擎连接到模型分发与本地服务。它们各占一层，彼此没有替代关系。

训练还要保存或重算激活、计算梯度并更新参数。推理通常不执行反向，却可能为每条活跃序列长期维护 KV cache。因而“模型装进显存”、“能够训练”、“能够同时服务很多长请求”是三件事。本节先从 FlashAttention 的前向和反向算法解释算子层，再沿训练执行、云端调度、端侧部署、异构硬件和服务组织展开。框架的共同机制与不同设计在同一条数据流上比较，不按功能名堆成排名。

FlashAttention：减少注意力中间量的存储与搬运

瓶颈常常出在矩阵乘之外

对一个注意力头，令查询、键和值分别为 Q、K、V，缩放系数为 s，掩码为 M。标准计算是：

S=sQKT+M,P=softmaxrow(S),O=PV

若将 S 和 P 完整写入高带宽显存（HBM），其元素数随查询长度与键长度的乘积增长。自注意力中两者都为 N 时，这两份中间矩阵是二次规模；Q、K、V 与输出则通常是长度乘头维度的规模。朴素多算子实现不仅要计算分数，还要把分数写出、为 softmax 读入、把概率写出，再为 PV 读入。张量核加快了矩阵乘，这些往返并不会自动消失。

FlashAttention 原始论文的关键是 IO 感知：把查询、键和值切块，利用片上共享内存和寄存器，只保留当前块及少量行统计量，不在 HBM 中物化完整的 S、P。它计算的仍是给定可见性下的稠密注意力，没有为了降成本删掉任何键。浮点计算顺序、低精度转换和近似指令会产生数值差异；“精确注意力”描述算法对象；与参考实现逐位一致是另一个要求。

这项技术适用于训练和推理，但收益条件不同。长序列训练需要消除巨大的概率矩阵及其保存成本；预填充也可受益于分块和融合；单词元解码没有同样大的查询维度，此时并行度、KV 读取及启动开销更突出。更换注意力算子不会同步解决优化器状态、服务排队或权重加载。

前向算法：在线 softmax 的不变量

一行 softmax 的分母需要整行信息，却不必把整行分数保存下来。扫描过一部分键之后，维护三个状态：已见分数的最大值 m、以 m 为基准的指数和 ℓ，以及以同一基准加权的值向量和 u。u 尚未归一化，不应与最终输出 O 混用。

ℓ=∑j∈AeSj−m,u=∑j∈AeSj−mVj

新块 B 到来后，选择新的基准，并把旧状态换到这个基准：

m′=max(m,maxj∈BSj),α=em−m′

ℓ′=αℓ+∑j∈BeSj−m′

u′=αu+∑j∈BeSj−m′Vj

最后才计算 O＝u／ℓ，并保存 log-sum-exp（LSE）＝m＋ln ℓ。α 同时作用于分母和加权输出，是因为两者都使用同一指数基准。只缩放分母而不缩放 u，会改变不同块的相对权重。对查询方向也分块后，一个执行单元只需维护若干行的状态，而不需要保持全部 N 行。

下面是说明不变量的伪代码，与 CUDA 实现对应但做了简化。scores 已包含缩放与掩码；全掩码行需要单独约定输出，不能直接计算负无穷减负无穷。

for query_tile in query_tiles:
    m, denom, numerator = -inf, 0, zero_vector
    for kv_tile in visible_kv_tiles(query_tile):
        scores = scaled_qk(query_tile, kv_tile) + mask
        next_m = maximum(m, row_max(scores))
        alpha = exp(m - next_m)
        p_unnormalized = exp(scores - next_m)
        denom = alpha * denom + row_sum(p_unnormalized)
        numerator = alpha * numerator + p_unnormalized @ kv_tile.values
        m = next_m
    output = numerator / denom
    lse = m + log(denom)

repos/flash-attention/flash_attn/cute/softmax.py 的 Softmax、SoftmaxSm100 承担这些统计量的更新；block_info.py 和 mask.py 则确定可见块与块内边界。因果注意力可跳过完全位于未来的块，对完全可见的块省掉逐元素掩码，只在边界块处理坐标。但“对角线上方／下方”依赖矩阵坐标约定，应直接以查询和键的位置关系判断；图形里的上下方向不可靠。

数值问题：全掩码、指数基准与低精度

全掩码行没有有效键。若 m 和新块最大值都是负无穷，重缩放中的差会变成 NaN。实现需要对这种行作安全基准处理，并在最终分母为零时按接口约定返回输出和 LSE。测试应明确覆盖空序列、局部窗口完全排除一行、变长边界与因果不等长输入；随机的方阵测试不足以暴露这些条件。

GPU 实现常利用以 2 为底的指数，通过缩放中的换底系数计算同一数学量。这样可以使用硬件指数指令及融合乘加，但不能把“使用 exp2”本身视为额外的算法近似；近似来自具体指令和精度。LSE 在前向保存与反向读取时必须约定对数的底，否则概率重构会出错。

SoftmaxSm100 的 rescale_threshold 路径会在条件满足时继续使用旧基准，并令重缩放因子为 1。旧基准不一定仍是最大值，但在实数运算中，只要分母和 u 始终用同一基准，归一化仍等价；变化主要在指数动态范围、舍入及实现成本。它与“忘掉新最大值、留下不一致统计量”是两回事。调节阈值应检查输出与梯度误差，耗时只是其中一个指标。

反向算法：重算概率，避免保存二次规模张量

训练需要对 Q、K、V 求梯度。令 G 表示损失对 O 的梯度，以下先考虑没有 dropout、掩码不含可训练参数的单头注意力。反向利用前向保存的 LSE 重构当前块的概率，省去再作一次完整的 softmax 归约：

Pij=eSij−LSEi

先由 O＝PV 得到 dV＝PᵀG、dP＝GVᵀ；softmax 的反向为逐行去掉概率加权均值：

Di=∑jPijdPij=∑rGirOir

第二个等号来自展开 dP＝GVᵀ，再把对键的求和重新组合为 O＝PV，不需要错误地假定 G＝dP Vᵀ。因此 D 可以在预处理 kernel 中用已保存的输出和上游梯度作行内点积；它只有每行一个数。

预处理内核已经把 O 与 dO 的片段读入寄存器；这段无输出残差的分支先转换到 Float32，逐元素相乘并归约，后续代码再归约跨线程的部分和并写出每行统计。它在反向结构中的位置是“预处理 D 与必要统计 → 主循环重构 P 并计算梯度 → 合并／转换输出”；额外保存整张概率矩阵是它要避免的做法。

可以逐步拿掉这些选择来理解设计。若先形成所有 P 与 dP，再求行内和，数学仍可成立，却重新引入与序列长度平方相关的中间量；利用上面的恒等式，D 的这一步只读取已经需要的 O 与 dO。进一步若在每个键块都重新计算相同的 D，又会重复行归约；单独预处理让多个键块读取同一结果，但增加一次 kernel 调度和一份行统计缓冲。若删去 Float32 转换，则改变归约的舍入路径，必须重新做误差验证，不能因公式相同便判定低精度实现等价。

dS=P⊙(dP−D),dQ=sdSK,dK=sdSTQ

这里 D 按行广播，⊙ 表示逐元素乘；缩放 s 在 Q、K 梯度中都不能漏掉。反向主循环包含重算 QKᵀ、计算 GVᵀ、PᵀG、dSᵀQ 和 dS K，共五类矩阵乘；概率重构和 softmax 梯度是逐元素运算与归约，不应算成额外 GEMM。

这种计算多做了一次分数矩阵乘，却省掉前向保存与反向读取完整 P 的成本。前向保留 Q、K、V、O 以及行统计量，反向在片上重算每个概率块。具体路径还可能保存小规模辅助状态。dropout 路径必须重建相同随机掩码，不能重新抽取；若 LSE 参与损失，反向还多出相应梯度项。flash_bwd_preprocess.py 的文件头明确说明可将 D 替换为 D−dLSE，把这项并入主反向公式。

反向的并行归约与确定性

前向按查询块并行容易让一个执行单元完成输出的一部分；反向既要沿查询方向累加 dK、dV，又要沿键方向累加 dQ。常见路径让一个 CTA 负责一个键块，遍历相关查询块，在本 CTA 中积累 dK、dV，却要把 dQ 的不同键块贡献合并。flash_bwd_preprocess.py、flash_bwd_sm90.py／flash_bwd_sm100.py、flash_bwd_postprocess.py 分别对应预处理、主计算和累加结果转换。

累加缓冲通常使用 FP32，然后转换到目标精度。原子加或异步块归约可以减少临时缓冲和归约步骤，但浮点加法的到达顺序可能变化。确定性模式需要固定写入顺序或采用分开的部分和与确定归约，增加同步或存储成本；具体方案随 kernel 路径而变。GQA 中多个查询头共享同一个 KV 头，dK、dV 也必须合并这些头的贡献，不能按一头一份直接覆盖。

实际训练若在长序列或稀疏路径出现梯度异常，首先应对齐缩放、mask、LSE 底数、dropout 状态和累加精度，再比较最早出现误差的张量位置。只比较最终 loss，可能掩盖错误来源。部分稀疏 MLA 路径额外保存输出舍入残差，使 D 的计算接近更高精度输出；这是用线性规模附加状态控制误差；保存整个概率矩阵是另一条路线。

从算法到 GPU：FlashAttention 的硬件组织

GPU 的并行与存储层级

CUDA 中线程以 warp 执行，CTA 是协作线程块；CTA 共享片上共享内存，寄存器通常由线程持有，HBM 则承载权重和大张量。更大的 tile 能增加数据复用，却同时增加共享内存、寄存器和累加器占用。超过资源预算可能导致 spill、减少驻留 CTA，甚至无法启动。occupancy 存在最优点：少量 CTA 若能充分使用张量核，也可能比高 occupancy 的低效内核更快。

PTX 是虚拟指令层，SASS 是目标架构上的实际机器指令。源码中的一次矩阵乘会展开为多条指令，异步操作又可能跨越局部代码边界。因此，计算完成、数据可读与缓冲区可覆盖是不同事件；同步建立的是这些事件间的依赖。删去等待可能缩短指令路径，也可能让后续运算读取未完成的数据，性能与正确性的联系由依赖关系决定。

FA2：查询块并行与 warp 内分工

FlashAttention-2从非矩阵乘成本、序列方向并行度及 warp 分工改进执行组织。它改的是执行组织，涉及的不止一条 GPU 指令。沿查询块扩大网格能改善小 batch、少头时的并行度；将不同查询行分给不同 warp，可以减少同一输出的跨 warp 合并。

在 csrc/flash_attn/src/kernel_traits.h、flash_fwd_kernel.h 和 softmax.h 中，tile 大小、线程数、共享内存布局及矩阵乘原语一起决定执行路径。Ampere 路线用 cp.async 把全局数据异步搬入共享内存，ldmatrix 按矩阵乘需要的布局读取数据，mma.sync 执行 warp 级矩阵乘。搬运 K／V 与计算可部分重叠，但拷贝完成只说明数据已经到达，其他线程能否安全使用还要看协作同步，CTA 内的同步仍须满足。

矩阵乘累加器的布局决定 softmax 行内归约该由哪些 lane 参与。某些 m16n8k16 布局下，同一行的片段分在四个 lane，局部归约后用 shuffle 合并；能否使用 Allreduce<4> 取决于具体布局。P 转成较低精度后若能直接作为下一次 PV 的寄存器操作数，可以省掉共享内存往返，否则需要重排或共享内存中转。

头维度增大时，同一查询 tile 的输出累加器和相关操作数需要更多空间。如果寄存器占用限制驻留 CTA，或者中间值溢出到本地内存，扩大 tile 带来的复用就可能被并行度下降和额外访存抵消。缩小 tile 或重叠深度可以减少同时存活的状态，却又降低复用或延迟隐藏能力。kSmemKVSize 中的两份空间对应 K 与 V；流水级数则描述这些缓冲怎样按时间复用，是另一项资源因素。反向还包含梯度累加状态，其容量约束与前向不同。

FA3：Hopper 的 TMA、WGMMA 与生产者／消费者

FlashAttention-3利用 Hopper 的异步搬运与矩阵乘，把加载与计算交给不同 warp group。TMA 通过张量描述符处理 tile 搬运、布局和边界；WGMMA 由 warp group 协作发起异步矩阵乘。关键文件是 hopper/mainloop_fwd_sm90_tma_gmma_ws.hpp、flash_fwd_kernel_sm90.h，以及 CuTeDSL 对应的 flash_attn/cute/flash_fwd_sm90.py。

生产者等待某个环形缓冲 stage 空闲，再发起搬运；消费者等待该 stage 的事务完成，发起矩阵乘，并在不再读取后释放。屏障不仅记录到达次数，还要与预期传输字节数、stage 编号和 phase 对齐。多级缓冲隐藏了 HBM 延迟，却增加了共享内存占用；生产者的低寄存器需求可以让出配额给计算角色，但仍受 CTA／SM 的总资源限制。

WGMMA 的异步性允许在一个操作未结束时做独立的 softmax、输出重缩放或发起下一操作。wait_group 等待的是已提交组的完成程度，与单份数据是否就绪无关。使用其结果或覆盖其源操作数之前，必须确认相应组已完成。ping-pong 调度让不同 warp group 错开矩阵乘与标量运算，减少张量核等待 softmax 的空档；其收益依形状和流水线而变。

这类流水线针对的是矩阵乘与非矩阵乘阶段的速度失衡：张量核完成一次乘法后，仍可能等待概率归一化或下一块数据。角色分工与异步重叠使这些独立工作同时推进，但消费者数量增加也会分摊 CTA 的寄存器预算，并增加同步成本。FP8 降低操作数位宽，同时引入缩放、排布和误差控制，整体吞吐取决于完整流水线。FA2 可以在兼容旧指令的后续架构运行；FA3 的变化在于主动采用 Hopper 的专属执行能力。

FA4／CuTeDSL：Blackwell 的 TMEM 与更细角色分工

固定源码中 flash_attn/cute/ 包含 CuTeDSL 路线及多个架构实现，不宜把整个目录都等同于一种 Blackwell kernel。flash_fwd_sm100.py、flash_bwd_sm100.py 承担 SM100 路线，SM90、SM120 另有实现。Python 在这里描述待编译的设备程序，逐元素计算发生在编译后的设备程序里。

Blackwell 的 tcgen05.mma 将累加结果放到张量内存（TMEM），减少长期累加器对通用寄存器的挤压。加载、矩阵乘、softmax、输出校正、写回和 tile 调度可由不同 warp 角色负责。S 完成后 softmax 角色从 TMEM 读取、计算 P，再交回矩阵乘角色执行 PV；输出校正角色同时保证旧的输出累加器已按新基准缩放。一个阶段的“完成”因此不只表示数据已经加载。

pipeline_s_p_o 表达的正是这个握手：S 就绪；P 写好且 O 校正完成；随后才能执行 PV。S 与低精度 P 的空间复用依赖位宽和生命周期，必须先读完 S 再覆盖。更多并行角色可以重叠 softmax 与矩阵乘，也增加 TMEM 读写、屏障与布局转换。对短输入，这些成本可能压过收益。

2CTA 路线让 cluster 中两个 CTA 协作完成更大的 tile，但 tile 坐标、远端共享内存、参与者数量和事务字节数必须在 cluster 范围一致。tile_scheduler.py 还包含 Cluster Launch Control（CLC）相关调度，通过领取工作改善不均匀 tile 的负载。CLC 解决的是工作分派，不改变在线 softmax 的数学。只有 leader 领取 cluster 工作，再把一致的坐标交给协作者，才能避免两侧处理不同 tile。

SM100、SM103、SM120 对应不同后端能力组合，架构名称不能替代具体接口契约。interface.py 以形状检查、启发式分派和编译键连接调用与 kernel；归约读、SplitKV、确定性反向和专用头维度的可用性随具体分支变化。这个分派层使硬件差异显式进入计算路径，不同设备因此可以走不同实现。

SplitKV：解码时用键方向补足并行度

单词元解码的查询方向很短，网格可能没有足够 CTA。SplitKV 将键区间分给多个 CTA，各自计算局部输出和局部 LSE，然后合并。若局部输出 Oₐ 已归一化，最终输出必须按各分片的概率质量加权，不能直接平均：

z=maxLSEa,wa=eLSEa−z,O=∑awaOa∑awa

flash_fwd_combine.py 负责这种部分结果合并。分片越多，独立工作越多，却需要额外部分和、写回与合并 kernel；短 KV 时可能更慢。空分片必须由各角色一致处理，否则某个消费者会等待根本不会产生的数据。确定性反向与 SplitKV 前向的归约组织也不能混为一谈。

数值、寻址与异步状态的不同失效路径

错误可以发生在数学定义、输入寻址或执行时序三个层次。因果边界或头映射错误改变参加计算的元素；归一化与缩放错误改变概率及梯度；缓冲提前复用则让公式正确的程序读取错误代次的数据。这些失效路径需要不同解释，单一的“精度问题”不能概括它们。

失效层次 相关状态 机制关系
输入与寻址 掩码、长度、头映射、块表 决定每个查询实际读到哪些键和值
数值与反向 LSE、D、缩放、累加顺序 决定概率重构、梯度尺度与舍入
搬运与同步 事务字节、参与者、完成事件 决定消费者何时可以读取新数据
缓冲复用 stage、phase、释放事件 区分同一地址的不同使用代次
资源与性能 寄存器、共享内存、驻留、spill 决定复用收益是否被容量与访存抵消

以使用两相位屏障、含 S 个 stage 的抽象环形流水线为例，第 t 次工作的缓冲编号与代次可写为：

s(t)=tmodS,φ(t)=(φ0+⌊tS⌋)mod2

缓冲编号在一次完整轮转后重复，相位则翻转。只保存编号无法区分旧数据完成事件与新一轮使用；生产者和消费者对相位的解释不同，就可能出现提前读取或永久等待。这个状态关系说明了为什么容量正确、事务字节正确仍不足以保证异步执行正确。

仓库的 AI/DEBUG_METHODOLOGY.md、DEBUG_2CTA.md 和 RACECHECK_TMA_HAZARD.md 提供了时序变化和同步诊断的具体案例。插入输出语句既改变执行时机，也可能改变编译产物，错误随之消失无法单独区分竞争、布局和工具链因素；racecheck 的报告同样需要结合目标指令的同步语义解释。案例的价值在于展示失效条件与证据之间的关系；把一种历史故障推广成所有异常的原因会误判。

内核开发工具：Triton 与 CUTLASS／CuTe

频繁变化的算子：先建立块级实现

Triton 以程序实例处理一块张量，program_id 确定块坐标，arange 建立元素索引，load、store、dot 和归约表达计算。线程映射、布局转换与部分流水线由编译器处理。python/triton/language/core.py、runtime/jit.py、compiler/code_generator.py 分别是语言、JIT 和前端生成的入口；后续通过 IR、目标后端和 LLVM 等阶段降级，不应概括成“先生成 CUDA 源码”。

这段 load 把可选 mask、越界替代值和缓存策略转换到语义层可处理的对象，不会展开成 Python 逐元素循环，再交给 _semantic.load 参与编译。块级程序描述索引和边界，编译器负责后续布局与指令生成；二者通过这里的类型和参数约定连接。

尾块只有 100 个有效元素而 tile 有 128 个位置时，没有 mask 的直接读取会访问无效位置；只有 mask 却没有为后续计算选择合适的替代值，又可能使被屏蔽元素的值破坏归约。显式的掩码与 other 把“哪些地址有效”和“无效元素如何参与运算”分开，代价是额外谓词以及边界路径。具体替代值取决于算法，求和可用零，最大值或 softmax 则不能照搬；这段包装代码只建立参数契约，正确性仍取决于调用者。

当新模型引入新的掩码、低精度格式或 MoE 路由，工程难题往往落在快速得到可验证、可维护的实现上，单个形状的最高速度是次要目标。Triton 可以先承担 RoPE、RMSNorm、量化／反量化、gather／scatter 或注意力参考路径，再根据真实热点选择是否下沉。num_warps、num_stages 和 autotune 配置影响资源与重叠，不能保证所有参数组合都更快。

一个边界处理错误的块级 kernel，在 GPU 上跑得很快也仍然是错误的。测试需覆盖非整块长度、非连续步长、空块和不同 dtype；解释器或 CPU 对照可检查部分张量逻辑，但不能证明 GPU 异步同步或性能。Triton 与 CUDA 的差别在控制粒度与开发成本，不存在无需条件的代码量／性能百分比。

固定热点与复杂布局：显式组合矩阵乘和流水线

CUTLASS 参数化矩阵乘、主循环和 epilogue，CuTe 用 Layout、Tensor 与 Atom 描述布局、张量视图和硬件原语。Layout 是逻辑坐标到存储偏移的映射，Tensor 是带布局的数据视图，Atom 则描述一次 MMA 或 Copy 的协作形状。include/cute/layout.hpp、tensor.hpp、atom/ 和 arch/ 对应这些层次；python/CuTeDSL/ 将相关组织暴露给 Python DSL。

Layout 的同一个调用入口区分两个动作：普通坐标由 shape 和 stride 映射到偏移，含下划线的坐标则表达切片并返回子布局。以教学布局形状 (2, 3)、步长 (3, 1) 为例，坐标 (1, 2) 对应偏移 5；改为转置视图时改变映射即可，数据无需复制。这是布局关系的算术例子；具体 MMA 指令的实际线程布局另见手册。

若每个 kernel 都手写展平与反展平，矩阵乘、行归约和异步拷贝之间就会散落不同坐标约定，一次改 tile 可能要求同步改多处地址计算。把 shape／stride 与切片组合成对象，是把这种约定集中起来；它不能自动保证带下划线的切片或共享内存 swizzle 正确，复杂模板与设备原语的兼容性仍须核对。避免拷贝的收益也不能脱离实际访存模式评估。

在 FlashAttention 中，QKᵀ 的累加器布局必须连接到 softmax 的行归约，再连接到 PV 的操作数布局。只让每个 GEMM 独立最快，未必让整条链最快：布局转换和共享内存往返可能抵消收益。CuTe 的价值是把这些关系表达成可组合对象，并仍能选择架构原语；复杂性被集中到布局与流水线契约上。

实际优化可以从一个固定热点形状入手：先统计读写量与等待，再尝试把 bias、激活、量化缩放放进 epilogue，或让 P 直接连接下一次矩阵乘。每次融合都应验证被覆盖缓冲的最后一个读者。CuTe 的纯 Python 布局工具能帮助检查映射，但不能替代真实设备上的同步测试。

训练执行：算子、梯度与参数状态的分工

llm.c：把一次训练步展开到具体张量

llm.c 将 GPT 的训练流程直接写在 C／CUDA 中。train_gpt2.c、train_gpt2.cu 连接词元嵌入、注意力、前馈、输出 logits、损失、反向和优化器；llmc/attention.cuh、matmul.cuh、layernorm.cuh、gelu.cuh、adamw.cuh、global_norm.cuh 则使各环节可分别研读。它的定位是训练实现与验证入口，在线调度交给 vLLM 那类系统。

一批输入的前向生成损失，反向将输出梯度依层传回并累积参数梯度，优化器在约定的累积边界执行更新。梯度裁剪、混合精度、权重主副本和优化器状态影响内存及数值；FlashAttention 只减少注意力相关中间量，不会消除这些状态。推理可以复用前向算子，却不用训练的优化器更新路径。

llmc/fused_classifier.cuh 展示了另一种 IO 优化：在已算好的 logits 上融合 softmax、损失和 logits 梯度生成，减少概率张量的写读。它不意味着把 LM head 的矩阵乘也装入同一个分类器 kernel。该文件的 fused_classifier_kernel5 在单线程读取目标 logit计算损失后加 CTA 同步，随后才原地覆盖为梯度；缺少这条边界会使其他线程提前改写 logits，产生错误甚至溢出。

先比较两个版本的资源关系：分离的分类器保持 logits 不变并另写梯度，较容易避免读写冲突，却增加张量和访存；融合版把同一缓冲从 logits 切换为梯度，节约存储，但必须规定最后一个旧数据读者。这里线程 0 读目标位置并计算损失，CTA 中其他线程随后更新词表的不同片段。没有屏障时，“线程 0 分支已在源码中出现”并不能保证所有线程在运行时都等它读完。

文件注释直接说明了被观察到的失败机制：旧 logit 被梯度覆盖后，损失计算把错误数值与原 softmax 偏移组合，可能出现过大的指数和无穷损失。__syncthreads() 在此建立整块线程之间的读取／覆盖边界。它是融合正确性的必要成本，为提速删掉它会破坏正确性；这里依据源码及其注释解释问题，没有把本机未运行的移除屏障版本写成实验结果。

实际问题是“大词表训练时，分类器张量和访存成为热点”。解决方案需要先区分 LM head GEMM 的成本、softmax 的成本和保存概率的成本，再决定融合哪些步骤。只有输出文本正常或 loss 大致下降不能证明正确；test_gpt2.c／.cu 与参考张量对比，dev/loss_checker_ci.py 比较损失，是两层不同验证。混合精度误差要用逐张量绝对／相对误差及训练曲线共同解释。

DeepSpeed：容量问题与推理批组织分属两侧

DeepSpeed 同时包含训练与推理能力。训练侧的 ZeRO通过在数据并行参与者之间划分优化器状态、梯度和参数来减少每卡冗余；不同 stage 划分的对象不同，参数按需聚合又增加通信。CPU／NVMe 卸载进一步将容量压力转移到搬运与带宽。这里只辨认其系统职责，不展开完整 ZeRO 训练实现。

训练内存由模型状态与动态激活共同占用。注意力 IO 优化减少大中间矩阵的存储，激活重计算减少前向结果的长期保留，状态分片则把参数、梯度或优化器状态分散到多个 rank。三者作用于不同项，组合收益也受剩余最大占用约束。分片后计算阶段需要的完整或局部参数通过通信形成，内存压力因而可能转为集合通信压力；微批、累积步数与聚合时机改变状态的复用次数和通信频率。

推理侧 deepspeed/inference/v2/engine_v2.py、ragged/、allocator.py、scheduling_utils.py 组织不规则批、状态和执行。DeepSpeed-FastGen的 Dynamic SplitFuse 把长预填充拆开，并把预填充块与增量生成词元混入预算内的一次执行。它控制的是步内工作量及生成请求的等待，作用于推理侧的批组织，与训练参数分片无关。服务封装还涉及独立的 MII 项目，不能从本地 DeepSpeed 目录推断已经拥有全部 MII 实现。

put 先做可调度性判断，再清空本轮批描述，按 UID 取得或建立持久序列状态，准备 KV 和本轮进度，最后把批元数据发往设备。结构上区分了跨轮次存活的 state manager 与每次执行重新组织的 ragged batch；后续模型准备与前向消费的是后者，原始服务请求在这一步之前已完成转换。

若把每条序列 padding 到本批最长长度，组批较直接，却在长度差异大时浪费输入计算；ragged 表达让有效词元和序列描述共同决定执行，额外承担索引与元数据成本。若去掉准入检查但没有上层等价保证，KV 或跟踪序列容量不足可能在分配／组批阶段才失败。因此 do_checks=False 把容量约束的证明责任交给已完成检查的调用方。这一推理路径的容量契约与 ZeRO 的训练状态分片是不同问题。

固定词元数有助于约束步内负载，但并不保证每步耗时相等：KV 长度、注意力模式、MoE 路由、缓存命中和通信仍会改变成本。比较 SplitFuse 与其他框架的分块预填充，应观察 TPOT 分布与首词元时延，不能只看名称是否相同。

分布式训练：容量、等待与可靠性是不同职责

Duan 等把大规模 LLM 训练的挑战分为可扩展性、效率与可靠性，并在流水线并行中具体讨论气泡和阶段内存不均衡。[12] 因而一个训练框架不能仅以“支持多卡”概括：参数与优化器状态放在哪里、激活什么时候释放、阶段间传什么、某个 rank 变慢后谁等待，都属于不同设计职责。

切开模型仍然可能留下空闲设备

流水线把不同层放在不同阶段，阶段之间传递中间张量；微批让多个阶段有机会同时处理不同的数据。若只有一批完整数据顺序经过所有阶段，后续设备在等待前一阶段时空闲，前面阶段也可能等待反向结果。模型已经分布到多台设备，与这些设备正在持续有效工作是两回事。

综述比较的 fill-drain、1F1B、交错及细粒度调度，分别改变前向、反向和梯度计算在时间线上的安排。[12] 它们在“并行程度”之外还调其他参数：更早安排反向可以缩短激活存活时间，更多交错又可能增加通信与峰值占用；按不同切分和调度组合，代价会改变。减少气泡不能只通过无限增加在途微批实现，因为活跃激活仍受设备容量限制。

层数均分不保证资源均衡

各阶段包含的算子、输入形状和激活存活时间不同，平均分配层数不能保证相同耗时或内存。某个阶段持续较慢，会使其他阶段受到其吞吐上限约束；前部保留较多在途微批时，还可能先遇到容量边界。Duan 等归纳的放置、调度、激活搬运与重计算路线，正是对这些不同压力的回应。[12] 搬运把内存压力转向互连，重计算把空间换回计算，调度则调整状态的存活与依赖，不能视为同一种优化。

长时间训练还须处理故障和慢节点。单个任务在健康设备上正确执行，与集群能够从失败中恢复是两回事；可靠性职责包含检测、保存可恢复状态和恢复后的进度一致性。[12] 这些长期训练的职责与在线推理的请求状态管理不同；仅凭某个服务推理模块，不能推断框架已经覆盖训练恢复所需的全部状态。

云端通用引擎：请求驱动的调度与状态管理

vLLM：从请求进度到实际输入批

vLLM 的一条生成请求经过协议处理、输入预处理、引擎核心、调度器、执行器、GPU worker、采样和输出处理。vllm/v1/engine/async_llm.py 的 AsyncLLM 连接前端与引擎；engine/core.py 的 EngineCore.step 串起调度、执行和状态回写；core/sched/scheduler.py 的 Scheduler.schedule 决定本步计算量；worker/gpu_model_runner.py 的 GPUModelRunner 构造设备输入和注意力元数据。

进程边界把协议解析、tokenizer、流式输出与核心执行解耦，但消息、序列化、忙轮询和错误传播都有成本。worker 消费引擎定义的调度输出，无需从原始 HTTP JSON 自行推断状态。core/sched/output.py 的 SchedulerOutput 包含新请求、已有请求增量、各请求的词元数、块更新、结束／抢占、草稿和 KV 连接器信息，是这一边界上的数据契约。

固定版本的 V1 调度注释明确不以“预填充阶段／解码阶段”作为调度主抽象，而以已完成进度追赶当前应计算的词元总数。前缀命中缩短待计算区间，分块预填充由预算截断，投机草稿增加待验证词元。这里“无阶段”只描述调度进度模型；算子层仍需识别不同查询长度和执行形状。

代码首先计算“应达到的进度减去已经计算的进度”，再分别施加长预填充阈值和本轮预算。若只保留请求数上限，一条 8192 词元的新请求与一条只需 1 个词元的生成请求会被当成相同的一个名额，执行时间却完全不同。以本轮可用输入预算 512、长预填充阈值 512 为例，前者只能推进一个块，无法一次吞掉全部输入；后续轮次继续从 num_computed_tokens 接上。这是可从状态轨迹复核的分解；时延表现要另行测量。

只加分块仍不够：没有完成进度会重复计算已经处理的区间，没有输出占位又可能在异步结果回传前错误地安排后续工作。因此三项进度与多项预算共同构成调度契约；其代价是每轮状态回写和重新组批；长请求的总计算量照旧。

下面是连接块分配的教学伪代码，函数名与变量名为解释性简化，属教学伪代码：

needed = tokens_with_spec + output_placeholders - computed_tokens
scheduled = clip_by_token_budget_and_other_limits(needed)
blocks = kv_manager.allocate_slots(request, scheduled)
if blocks is None:
    defer_or_preempt(request)

异步输出占位表达已提交但尚未回传的生成结果，不能当作已经确认的词元；采样完成后还要处理接受／拒绝、停止、取消和资源释放。真实调度受请求数、词元、编码器、草稿和模型长度等多种预算约束，不能只靠一个 batch size 解释。

分页、前缀哈希与引用计数

连续 KV 预分配容易在短请求中浪费容量，也难以在变长请求间复用空间。vLLM 把逻辑序列映射到定长物理块，KVCacheManager 管请求的块，BlockPool 管可分配块与缓存，注意力后端通过 block_table 找到数据。这是 PagedAttention 的内存管理主线；它与 FlashAttention 的片上分块属于不同层次。

同一词元段在不同上下文中通常产生不同 KV，因此前缀哈希需要串入先前块的身份。core/kv_cache_utils.py 的 hash_block_tokens 和附加键生成函数还处理 LoRA、多模态与嵌入等影响状态的上下文。缓存共享既要语义一致，也要命名空间与版本一致；不能只按一段文本的相等性共享。

引用计数防止活跃请求使用的块被随意回收。零引用块可留作缓存，待重新分配时淘汰；共享数据被修改前还要判断可写性或执行写时复制。BlockPool.touch、get_new_blocks、is_block_writable 和 KVCacheManager.free 因而分属命中、分配、写入与释放不同动作。SGLang 同样需要保护在用数据，不能把引用计数说成它独有的能力。

分页减少碎片，不减少有效 KV 元素本身。序列长度、并发和 KV 头数共同扩大占用；块大小更小可减少尾块浪费，却增加索引与管理成本。KVCacheSpec 还要描述不同层的全注意力、窗口、MLA 或状态型布局，混合模型的命中边界必须是相关组都可恢复的边界。

真实问题：长请求把短请求的输出拖慢

一条长预填充独占执行时，其他请求即使只差一个生成词元，也会等待整个长计算完成。分块预填充让长输入分多步推进，与增量生成共享预算；运行中请求优先、长预填充阈值和请求准入共同控制干扰。它通常以延长长请求的预填充完成时间，换取其他请求更稳定的生成间隔。

方案验证应同时记录首词元时间（TTFT）、输出词元间隔（TPOT／ITL）、尾分位及公平性。减小块不一定更好：会增加轮数、调度和 kernel 启动开销。vLLM 的部分分支会跳过本轮不能推进的请求继续尝试其他请求，这可提高利用率，与严格 FCFS 相比则会出现偏差；若长请求持续被跳过，需要以等待时间和优先级策略辨认饥饿。

如果 KV 块不足，V1 可抢占请求、释放状态并在之后重算。重算成本取决于被释放的上下文，恢复因此有代价。单独的 KV offload／连接器路线可以搬运冷状态，但不能把旧版调度器的 swap 描述直接套到当前抢占路径。频繁抢占应优先检查准入、最大输出、KV 预算和并发，增加词元预算可能使问题更严重。

后端接入：能力协商与元数据一致性

attention/selector.py 的 get_attn_backend 把设备、头维度、dtype、KV 精度、窗口、sink、MLA 和并行等条件交给平台选择，attention/backends/registry.py 注册实现。支持单项能力与支持所有组合是两件事；一个后端需要声明支持范围，也需要对不支持组合回退或拒绝。

执行器生成 query_start_loc／累积长度、block_table、位置和 KV 写入槽位。变长打包消除 padding 浪费，分页寻址避免 KV 重排，但序列边界必须同时传到 kernel。固定长度、变长连续 KV、分页 KV 是不同接口，FlashAttention 并不要求所有调用都使用分页或打包。

后端能力声明把数学条件与输入接口连在一起：不等长因果对齐决定查询的历史边界，GQA 映射决定多个查询头读取哪个 KV 头，窗口、dtype 和步长决定有效读取范围及数值解释。单个规则张量上的 kernel 正确性只覆盖其局部接口；多请求打包还依赖序列边界和槽位映射。若这层映射跨越请求边界，算子即使正确执行同一注意力公式，也会汇聚来自错误序列的数据。

前缀与程序型负载：SGLang 的树结构组织

RadixCache：逻辑前缀与物理页分开

SGLang 的 python/sglang/srt/mem_cache/radix_cache.py 用基数树组织前缀。节点保存一段词元及对应 KV 索引，match_prefix 返回最长可复用前缀；匹配在段中间结束时，_split_node 改变树结构以暴露边界，不需要复制整段 KV。插入把已算前缀登记进树，驱逐回收未受保护的节点。

树按词元表达逻辑关系，但物理页约束仍存在。固定源码的 match_prefix 明确在 page_size > 1 时把键截断到页边界。因此“基数树永远逐词元复用，而块式缓存永远低一档”并不成立。它的优势是自然表示分支与共享祖先，并让调度可以读到这些关系；收益依负载、页大小和缓存容量而变。

这段路径先处理模型所需的键视图，再将键收缩到物理页边界，最后沿树匹配。若页大小为 16，长度为 70 的普通词元键在这一步只能保留 64 个词元；末尾 6 个词元不能因文本相同就被当作完整的共享页。去掉对齐会让“逻辑命中长度”与可登记、恢复的物理缓存单位脱节，后续索引和所有权就必须另行支持部分页；当前路径选择保持二者一致，代价是放弃不足一页的可复用尾部。

基数树表达公共祖先与分支，物理页约束照旧存在。可依次比较“不缓存”“整条前缀精确键缓存”“公共片段组成的树”：第二种能复用相同提示，却难以直接表示只共享前半段的多分支；树节点分裂暴露共享边界，但又引入结构变更、查找和引用保护。对这些操作的 CPU 成本，需要单独观测，不能由命中词元数直接推出服务加速。

RadixKey.extra_key 为适配器或其他不应共享的请求划分命名空间；inc_lock_ref／dec_lock_ref 保护正在使用的节点。缓存匹配也会更新时间戳。树查找是带副作用的动作，节点分裂、引用保护与驱逐需要保持一致。

缓存感知排序与 PrefillAdder 准入

managers/schedule_policy.py 的策略包括最长前缀匹配、按树结构排序及不依赖缓存的 FCFS 等。排序回答“优先尝试谁”，PrefillAdder 则回答“预算是否允许接纳”。命中长前缀减少本轮新增计算，但后续生成仍需要增长空间；锁定前缀也使一部分缓存暂时不可驱逐。

过长队列会使前缀匹配和排序本身成为 CPU 热点，固定版本在部分缓存感知策略的等待队列超过阈值时回退 FCFS。阈值属于这个版本的工程条件，适用范围以该版本为限。缓存感知也可能牺牲公平性：无共享前缀的请求不能因命中率目标而无限等待。

文档问答中的公共系统内容和重复文档可以形成共享前缀，用户问题则成为分叉后的私有部分。Radix 查找在首次不同的位置结束，因此放在开头的随机请求标识会使后面的相同文档也无法按前缀复用；相同文本位于不同位置，还会处于不同的注意力上下文。缓存容量和实例路由进一步决定已经计算的公共状态能否继续被后续请求访问。公共内容的顺序同时属于模型输入语义，缓存组织与答案质量由此相互约束。

DSL、多分支与普通服务请求

python/sglang/lang/api.py、ir.py 和 interpreter.py 用 gen、select、角色和分支等接口表达语言模型程序。连续生成与分支会自然形成共享前缀，使程序结构与缓存结构相接。但 RadixCache 并不只服务 DSL：普通 HTTP 请求只要拥有相同有效前缀，也能复用；vLLM 同样可以作为外部程序的执行引擎。

结构化程序的收益来自可以明确传递重复的上下文、控制生成边界及组织分支，与“一个框架只认识程序、另一个只认识请求”这种分界无关。选型时要看应用是否需要这样的前端接口，还是只需要通用生成服务。两者都必须处理模型状态、调度预算和采样。

HiCache 与重叠调度

mem_cache/ 将批分配、allocator、设备 pool、主机 pool 和外部 storage 分开；HiCache 的 L1／L2／L3 分别承载设备、主存和外部存储中的状态。l2_transfer.py、storage_prefetch.py、hicache_storage.py 连接搬运、预取与后端。缓存命中在慢层时仍需把数据搬回或按相应路径使用。

实际问题是“共享前缀很长，但 GPU 放不下所有热门上下文”。可将较冷状态留在主存或存储，提前预取，比较搬运时间与重算时间后决定是否恢复。读取失败、版本不一致或恢复代价过大时，需要降级重算；不能让一个逻辑命中永久阻塞请求。分层扩大可保留的容量，却增加额外状态机和 IO。

scheduler.py 的普通与重叠事件循环，以及 batch_overlap/，把结果处理、元数据准备与设备执行错开。重叠需要保证上一批仍在读取的张量和页表不会被下一批覆盖；这比多开一个线程更重要。并行 rank 间也必须对批组成、候选与状态更新保持一致。

专用云端路线：执行后端、量化与服务分层

TensorRT-LLM：引擎构建与动态执行路线

固定版本同时保留 TRT 引擎与 _torch/ 路线。经典路线经构建生成 engine，将部分图优化、精度和内核选择提前；PyTorch 路线在 _torch/attention/、pyexecutor/、speculative/、compilation/ 组织执行与优化。两条路线把专门化放在不同阶段：预先构建能够固定一部分执行决策，动态路线则在运行组织中保留更多形状与调度处理。所需构建产物、启动路径和适配条件因此不同。

cpp/tensorrt_llm/kernels/ 将上下文融合注意力、解码注意力、weight-only 矩阵乘、MoE、采样和通信等分开。预填充与解码的不同形状由不同内核承接，低比特格式与特定硬件原语紧密耦合。_torch/attention/ATTENTION_DEVELOPER_GUIDE.md 与后端接口提供了新注意力实现的接入边界。

实际场景是“模型和硬件长期固定，需要降低延迟并纳入现有 NVIDIA 部署栈”。可分别评估 engine 与 PyTorch 路线，固定模型、硬件、精度和形状范围，考察构建／预热、峰值内存、请求尾延迟以及升级重建成本。模型频繁变化或形状范围很宽时，特化收益可能被构建和维护成本抵消；不存在由厂商身份推出的性能第一。

pyexecutor/cuda_graph_runner.py、breakable_cuda_graph/、KV 管理、连接器与卡死诊断说明优化对象不止单个 kernel。多节点还要同时维护通信拓扑、专家映射和状态传输；一次局部快速矩阵乘未必改善端到端延迟。

LMDeploy：双引擎与权重格式的连接

LMDeploy 的 TurboMind 由 lmdeploy/turbomind/ 与根目录 src/ 连接 Python 接口和 C++／CUDA 执行，PyTorch 路线则在 lmdeploy/pytorch/ 拆出主循环、分页、缓存、后端、投机与连接器。模型适配需要先辨认使用哪条引擎，不同路线支持的组合不能互相代替。

W4A16 表示权重用 4 位存储、激活保留 16 位。相对 16 位权重，理想原始权重数据缩小到四分之一，但尺度、分组、元数据与未量化张量仍占空间；参与计算时还需对应内核的解包和缩放。AWQ 的校准和权重排布必须连接到实际执行格式，不能把“做过量化”当成“这个后端能直接运行”。

turbomind/converter.py 与 weight_format.py 把抽象量化网格落实为执行器需要的权重排布；PyTorch 的分页与 cache engine 则管理请求增长的状态。前者降低固定参数占用，后者控制动态上下文，两者分工不同。长上下文并发受 KV 限制时，权重量化只是腾出一部分预算；大批量计算中，解包与缩放又可能抵消部分带宽收益。引擎区分的必要性因此来自格式、算子与状态管理的共同契约；两个入口名字互换不了这些契约。

serve/ 的协议适配、代理和输入处理降低应用迁移成本，却仍要将流式输出、取消和错误接到实际引擎状态。外部请求字段相同，只说明接入形式相似，不说明各后端对工具参数、多模态输入或中断的内部语义完全一致。

TGI：Rust 接入与执行协议

TGI 用 Rust 组织 HTTP 接入、校验和部分批调度，通过 Protobuf／gRPC 与 Python 等执行后端连接。router/src/validation.rs、router/src/infer/、proto/ 和 server/text_generation_server/ 说明边界上的请求与批状态如何表达。其后端还可适配其他执行栈，不能把所有批处理策略都归给一个固定的 Python 循环。

协议边界让接入层可以独立处理连接、输入验证、限额和回压，执行层则集中组织批量与设备状态。代价是一次业务请求可能对应多个内部消息：接入端停止回传不代表执行端已经取消，超时也不说明某批从未执行。请求身份与完成语义必须穿过 gRPC 边界，否则会出现重复执行或残留状态。Rust 的并发组织提供的是实现手段，尾时延仍由排队、tokenizer、序列化、设备执行与流式回传共同决定。

对既有 HuggingFace 模型与云端接入流程，TGI 是检查协议与后端分离的案例。选型还应核实当前上游维护状态、部署后端的能力和依赖版本；这个固定源码快照不构成长期支持承诺。

LightLLM：词元级分配与逐模型内核

LightLLM 的 TokenAttention 以词元为粒度管理 KV 位置，lightllm/common/kv_cache_mem_manager/ 与 req_manager/ 分离物理分配和请求映射。它减少固定页末端未用槽位，却增加细粒度索引、分配和搬运组织；“没有块内碎片”只说明碎片这一项，服务内存利用率另受其他因素影响。

模型目录中的 Triton 内核及 autotune 配置体现逐硬件、逐形状调优。细粒度分配使不同长度请求的最后几个词元不必独占一整页，却使注意力内核读取更多位置映射，并可能降低连续访问程度。若一个词元的 KV 数据很大，索引字节的相对占比可能较小；若请求本来很长，尾部浪费占比已经很低，细化粒度的容量收益也随之下降。因此词元级与块级方案的差异同时落在碎片、间接寻址和访问组织上，分配粒度越小也会带来间接寻址与访问组织的代价。

server/ 的路由、多级缓存、PD 分离和 RL 接口连接更高层的执行。Windows 检出对带冒号的调优配置路径存在限制，本地工作树不完整；因此这部分以固定提交中的 Git 对象为来源，不能把检出缺失当成框架没有内核，也不能在当前机器声称完成部署验证。

端侧与单机：内存格式、计算图与模型生命周期

llama.cpp：模型层、ggml 与工具层

llama.cpp 的 include/llama.h 定义公开 API，src/ 组织模型、上下文、图、批、缓存和采样，ggml/ 提供张量、量化和硬件后端，tools/ 提供 CLI、server、转换和评估。运行时不需要 Python／PyTorch，但构建工具、可选后端和第三方组件仍有依赖，不能把“无需 Python”写成“完全零依赖”。

GGUF 保存模型元数据、张量及其类型；加载器读取架构、tokenizer 和张量布局。ggml_type 中的量化块格式直接影响字节数与可用点积内核。K-quant、i-quant 和不同浮点低比特格式属于不同方案，校准、分组和混合精度选择都影响质量。

ggml_gallocr 依据计算图中张量的生命周期规划缓冲，后端调度器划分图并插入设备间拷贝。mmap 可以把文件映射接入加载，但后端可能还需重排或复制，GPU 权重也不会仅因 mmap 就无需设备内存。冷启动缺页和暖页缓存应分别测量。

逻辑批、物理批与序列状态

一次 llama_decode 提交的是逻辑 batch，llama_batch_allocr 根据记忆状态与 n_ubatch 拆成物理批。调大 n_batch 增加一次可提交的输入，调大 n_ubatch 才直接改变某次执行的工作区和形状。两者不能互换解释。

接口把拆批和缓存适配交给 memory 实现，返回可检查状态的上下文；逻辑批与一次设备执行分属两个层面。假设一次输入有 2048 个词元、物理批上限为 256，逻辑提交仍可保持完整，执行则需要按合适边界分成多轮。这样减小的是某一轮的工作区和计算形状，这条输入的总 KV 与模型权重不受影响。

如果只允许“一个逻辑批对应一个物理批”，应用要么自行拆提示并处理位置／序列状态，要么承受大批的峰值需求；前者把内部契约泄漏到 API 使用者，后者限制容量。上下文接口集中承担准备、推进和应用状态的责任，不同 memory 类型实现相同调用边界。代价是更多子批执行与状态管理；init_batch 的返回值仍需检查，任意拆分未必都能成功。

src/llama-memory.h 的 seq_rm、seq_cp、seq_add 等接口按序列与位置操作状态，支持分支、删除和部分模型的位置调整。缓存快照和 slot 内公共前缀提供另一类复用，与 vLLM 的块哈希、SGLang 的基数树不同。位置平移是否有效仍取决于模型和相应实现，能否无损改位置要看具体结构。

长输入的内存峰值由常驻权重、KV 与当前算子工作区共同形成。逻辑批描述一次请求组织的数据，物理微批描述一次实际执行的切片；减小物理微批可以降低工作区峰值，却增加切片和执行次数。更多层放到 GPU 会改变 CPU 计算、显存容量和设备间传输，权重文件大小只覆盖其中一项。仓库的 tools/fit-params/、llama-bench 与 perplexity 分别对应配置选择、速度测量和部分质量评估，这些工具的职责也反映了容量、性能和输出质量的不同约束。

llama-server：共享批与状态线程

tools/server/README-dev.md 描述 server context、slot、请求／结果队列与 HTTP 层。多个兼容 slot 将提示词或上一轮生成词元放入共享 batch，再调用 llama_decode，因此它已经包含连续批处理。批组成仍受配置相容性和容量约束。

模型状态由专用执行路径维护，JSON 解析、模板和响应格式化放在 HTTP 处理侧。把可并行的格式化移出状态热路径，能减少多序列生成互相干扰。流式重连若使用保留缓冲，需要限制会话容量并保持所有者隔离；它恢复的是输出传送，模型状态容灾是另一回事。

router 和 sleep 路线分别处理多模型入口与空闲资源释放。若偶发请求服务长期占内存，卸载上下文可以节约常驻量，但下一请求承担恢复成本；健康检查应避免意外触发模型重载。模型生命周期和每词元计算是两种优化对象。

exllamav2：消费级 NVIDIA 的低比特执行

exllamav2 将线性层、注意力、缓存和生成器直接组织在模型部件周围。conversion/、linear.py、exllamav2_ext/ 连接 EXL2 权重转换与 CUDA 执行，cache.py 包含基础、8 位和 Q4／Q6／Q8 等缓存类型，generator/dynamic.py 则组织动态生成与页管理。这些路径支持的格式以本版本实际实现为准，不将 EXL3 自动归入 exllamav2。

混合比特转换在目标平均容量下为敏感部分分配更多精度，校准语料影响误差评估。权重低比特与 KV 低比特仍是两条独立轴；Hadamard 相关实现也需要按具体路径辨认用途，不能仅凭目录名断言所有权重转换都执行同一种旋转算法。

固定平均位数允许不同权重组获得不同精度，等于把有限表示预算从不敏感部分转移到敏感部分；敏感度由校准输入与误差准则定义，随校准条件而变。低位权重降低固定驻留和读取，低位 KV 则作用于每次历史访问。二者组合可能容纳更长上下文，但注意力后端要能读取匹配布局，额外尺度和转换也进入热路径。小批量解码的带宽收益与大批量矩阵计算的收益因此可能不同，个人生成器与多租户服务不共享一个固定速度结论。

Ollama：分发与本地运行时

Ollama 的 Go 服务、API、模型清单和内容寻址 blob，把下载、配置、加载、执行与卸载组织成一个本地运行时。server/download.go、模型创建相关文件和 api/ 承载这一层；执行后端则与 llm/、llama/ 等实现连接。它复用已有模型执行能力，增量价值主要在分发、配置和生命周期，不能笼统称为更快的 llama.cpp。

这里的四类 channel 表达请求到达、请求结束、模型过期和卸载完成等不同事件；loaded 记录已经存在的 runner，activeLoading 标记正在进行的加载。锁保护的是这两份模型生命周期状态，与注意力中的 KV tile 无关。源码注释还说明：加载串行组织，已加载模型的新请求仍可继续处理；是否真的及时推进，还取决于后续事件循环与执行资源。

没有共享的驻留模型表，每条请求独立启动 runner 会重复加载权重，并难以共同判断显存容量。仅加缓存表也不够：两个请求发现同一模型未就绪后同时加载，会产生重复占用；正在加载的状态把这段空窗纳入调度。代价是新模型加载可能排队，卸载与请求引用必须协调。因而更短的 keep-alive 会带来新的代价：它降低空闲驻留，却可能把同一模型的下一次请求重新送入加载队列。

Modelfile 把模板、系统提示和参数连接到模型条目，清单描述实际层；只有完全相同的数据层才能内容去重，两个不同微调的全部权重并不会天然只需增量下载。模型标签可以改变，复现应同时固定内容身份、模板与采样设置。

多个模型之间的切换涉及驻留数量、空闲卸载与加载失败后的状态恢复。短 keep-alive 减少空闲驻留，却可能使连续交互反复经历加载；长保留降低暖启动延迟，同时挤占其他模型和应用的内存。这是加载成本与共享容量的时间分配。客户端接口还可以连接本地执行或云代理，两种路径的计算位置和数据边界不同，离线属性由实际路由决定。

MLC-LLM：将平台差异提前到编译流程

MLC-LLM 用 python/mlc_llm/model/、quantization/、compiler_pass/ 和 interface/ 连接模型定义、量化和目标编译，cpp/ 运行时加载产物并组织缓存、采样，android/、ios/、web/ 展示跨端接入。TVM 子模块未完整检出，静态研读范围不包含完整 TVM 编译器本体。

编译式部署可以把解量化、布局与融合接到目标后端，同时仍需运行时处理请求和动态 KV。固定的是产物约定的能力与布局，不意味着每条序列长度都在编译期不变。修改模型、量化或目标条件时，可能需要重新生成产物。

编译将一部分后端选择、布局转换与融合从请求路径移到产物生成阶段，降低运行时反复决策的需要；代价是模型库、权重、量化方案和目标设备之间形成版本契约。编译图不能独自管理每个用户何时结束生成，动态缓存和采样仍属于运行时。手机、浏览器和桌面还具有不同内存与散热条件，统一上层模型表达有利于复用流程，却不意味着同一产物或同一性能配置能够直接覆盖所有设备。

异构与稀疏：把容量问题转成放置问题

ktransformers：MoE 专家与主存旁的计算

MoE 为一个词元选择少量专家，但全部专家权重仍须可访问。权重总容量可能远大于某次执行的激活量。ktransformers 的 kt-kernel/、ktransformers/ 及历史实现，探索把部分专家权重留在主存并用 CPU 内核计算，把其他热点留在 GPU。具体放置随模型与配置而变。

它利用的是模型 router 给出的专家级选择，不需要像神经元稀疏方案那样猜测全部激活。CPU 计算可以避免每一步把完整专家权重搬入 GPU，却要传递激活和路由结果，受主存带宽、CPU 矩阵运算、NUMA 与同步限制。MoE 的瓶颈随 batch 与专家集中程度变化，容量之外还可能是算力或通信。

设一次路由所需专家权重为 We 字节、对应输入与输出激活合计为 A 字节。在专家留在 CPU 的组织下，跨设备传输主要趋向激活规模 A；先传输 We 再在 GPU 执行是另一种组织方式。容量收益来自总专家权重驻留主存。这个数据移动比较只覆盖搬运量与放置，时延还取决于 CPU 计算与同步。批量增加后，多词元访问同一专家可能更适合集中矩阵运算，热点分布变化也会改变放置收益。瓶颈从显存容量移到 CPU／主存之后仍然存在，这解释了容量门槛下降与全 GPU 吞吐之间的差异。

PowerInfer：神经元级热／冷划分

PowerInfer 利用适用模型的激活稀疏性和激活分布偏斜，把经常访问的神经元权重放 GPU，较冷部分放 CPU，并用预测机制组织稀疏计算。其 powerinfer/、相关模型与预测资料提供这种放置的研究案例。固定目录中的后续模型路线不应与原始论文实验配置混写。

关键条件是激活确实足够稀疏，预测与异构协作成本小于省下的计算／读取。ReLU 类结构和稠密激活模型不能默认共用收益结论，预测遗漏还要评估质量影响。它与 ktransformers 的 MoE 路由稀疏是两个不同来源，也与稀疏注意力的键选择不同。

稀疏程度决定可跳过多少工作，热度偏斜决定有限显存能覆盖多少常用权重，两者是不同条件。若激活很稀疏但访问均匀，热／冷放置不易形成稳定热点；若热点明显但每次几乎全部激活，跳过冷部分的空间又有限。预测器还可能产生假阳性与假阴性：前者增加无用计算，后者漏掉应参与输出的贡献。方法必须同时处理运行成本和遗漏误差。PowerInfer 的实验支持特定模型和硬件配置，不将该结果推广为对任意稠密模型添加预测器就能获得的加速。

vLLM-Ascend：框架接口之外的硬件适配

vLLM-Ascend 用 vllm_ascend/platform.py 对接平台，attention/、quantization/、worker/ 与 csrc/ 承担实际执行，CANN／ACLNN 和通信相关实现替代 CUDA 路径。这里迁移的是设备、内存、算子、图、状态布局和分布式契约，规模远超一个 Python 函数。

平台接口把设备差异集中起来，实际 kernel 仍要实现与上层相容的掩码、精度、布局和缓存更新语义。数学公式相同，归约顺序与低精度舍入也可能不同；换一个注意力后端又会改变哪些形状或 KV 格式可以执行。patch/ 的覆盖实现说明部分行为仍依赖上游内部约定，内部对象和调度生命周期改变时，适配代码也可能需要同步修改。

后端迁移因此具有三层相容性：单算子的数值与边界、缓存及图执行的状态契约、分布式和服务的请求契约。相同 API 只覆盖最外层形式，不能证明页复用、异步取消或多 rank 采样仍保持一致。专用后端的价值在于把通用框架组织接到实际硬件能力，维护代价则来自这些跨层约定的持续耦合。

KV 状态的三类压力：有效信息、分配与共享

KV cache 以存储历史键和值换取增量解码时的复用，省去对过去位置的重复投影，却使状态随序列长度和活跃请求数增长。Shi 等的综述分别讨论架构设计、部署管理以及驱逐、合并和量化，说明这些方法压缩的对象各不相同。[14] Zhou 等进一步将缓存的容量与访问成本放到推理效率分析中。[11]

有效状态与预留空间分别占用容量

对具有相同标准 KV 布局的 L 层、Hkv 个 KV 头、每头维度 D、每个标量占 b 字节的模型，若请求 i 当前保留 Ti 个位置，未压缩的有效 KV 数据量为：

MKV=2LHkvDb∑iTi

系数二来自键和值。不同层类型、MLA、量化尺度和索引结构需要另按其实际布局计入。这个关系把主要压缩路线分开：改变 KV 头数或表示维度作用于模型结构，低比特存储作用于每元素字节数，历史选择作用于保留位置数，而请求准入和共享改变同时存活的独立状态总量。

若为每个请求预留完整最大长度，实际使用量之外还存在未用容量；分页可以按增长分配物理块，让请求不再要求一段足够长的连续空间。分页减少的是这种空间组织浪费，并未删除公式中的有效元素。有限的尾块空闲、块表和引用计数仍占资源。[14]

共享相同状态与压缩不同信息

相同有效前缀的请求可以共享尚未被修改的 KV，减少重复计算和重复存储。共享成立的前提包括模型、位置、适配器及输入内容等语义条件一致；共享后还要维护引用和可写性。该机制保留共同前缀的信息，与删除被认为不重要的历史位置不同。

方法 主要改变 保留的信息关系 相应代价

驱逐、合并与量化的分类来自 KV 优化综述。[14] 长文档中的历史重要性可以随后续问题变化，因此“过去注意力较低”并不直接等于“未来没有用”。管理层的缓存回收通常针对可释放或可重建的物理状态，信息层的历史压缩则可能改变模型实际能读取的上下文；这两类操作的正确性条件不同。

优化需要与注意力后端衔接

容量下降只有通过对应布局和内核被执行器利用，才会改变服务能力。分页的块表需要进入注意力寻址，低比特缓存需要匹配数值格式与缩放，选择或合并需要维持位置和序列边界的含义。框架的设计因而连接了逻辑历史、物理所有权和计算接口，作用不止于增加一个压缩函数。其收益与代价分别沿存储、信息和执行路径产生。

贯穿框架的机制：资源预算与状态一致性

各框架的差别不仅在 kernel 的速度，还在“请求如何变成一次设备执行”。调度器选择下一批的位置，缓存管理器提供物理槽位，模型执行器写入新的 K、V，采样器选择输出，最后控制层提交状态并回收完成或取消的请求。vLLM、SGLang、FastGen 与极简框架分别给出不同规模的组织，但这一链上的词元进度、页所有权和输出顺序必须相容。

连续批处理：按步组合

固定请求批中，短请求结束后，其位置可能闲置到整批完成。连续批处理在生成步之间让完成请求退出、新请求加入，使设备批组成随时间改变。它复用的是空出的计算与状态预算，不意味着每个请求都更快：新增请求可能扩大本步工作，排队策略也会改变已有请求的词元间隔。

调度至少同时受两种约束。若第 i 个请求本步处理 ti 个位置，计算预算要求 Σti≤Tbudget；若缓存页容量为 q、有效历史长度为 si，不考虑共享时页需求近似 Σceil(si/q)，不能超过物理页预算。一个只有少量新位置的解码请求仍可能持有很长历史，因此词元执行预算与 KV 容量预算不互相替代。vLLM 的 scheduler.py 以及 nano-vllm 的调度摘录分别展示这种进度与块分配的连接。

长预填充具有大量当前工作，增量解码具有少量当前工作却反复占用历史状态。直接把一个很长提示插入解码批，会增加其他请求本步等待。分块预填充把长输入切成多步，降低单步干扰并给解码留预算；代价是新请求需要更多调度轮次才能完成全部预填充，首词元时间不一定下降。公平性不会自然出现：始终优先解码可能延迟新请求，始终追求大块矩阵效率又可能拖长已有请求间隔。

调度策略因此在利用率、首词元时间、持续生成间隔和饥饿风险之间取舍。代码中的预算表示具体资源代理，与统一的“每词元成本”不同：相同 ti 下，短上下文与长上下文的注意力读取不同，模型或适配器切换又有额外成本。固定版本中一次选批的正确性只覆盖该次决策，最优服务策略还要看到达分布。

分页与共享前缀：分配对象与计算对象

分页 KV 用块表把逻辑位置映射到物理页，避免每个请求预留连续最大长度空间。页尾未用位置仍存在：对独立长度 si，一个请求的原始槽位浪费为 q·ceil(si/q)−si。减小 q 降低最坏尾部浪费，却增加块表条目、寻址和管理频率；词元粒度分配把这一取舍推到更细，未消除索引和预留成本。

前缀共享进一步让不同请求引用同一批有效历史页。共享后的总容量取决于唯一物理页；把所有逻辑长度直接相加会高估。但每个新查询仍需读取相关历史。前缀缓存减少重复预填充，级联注意力等路径则尝试组织一批查询对共享前缀的读取，作用点分别是避免重算与复用访问。长公共系统提示、有路由局部性且命中状态仍驻留时，二者可能组合；短共享区或额外归约成本较高时，收益也可能减弱。

状态身份包含模型权重、适配器、词元前缀、位置约定以及相关非文本输入；原始字符串相似度提供不了这类身份。租户或权限命名空间还影响可否共享。SGLang 基数树的匹配与分叉负责逻辑前缀，物理页对齐决定哪些边界能够安全复用；vLLM 块哈希则将身份映射到块级对象。未填满页的后续写入需要独占或写时复制，否则一个请求会改动另一个请求仍依赖的历史。

图重放：稳定执行骨架与动态内容分离

小批量增量解码包含许多短 kernel，提交间隙可能占可见比例。CUDA Graph 将可捕获的执行段重放，减少主机反复构造提交序列。它节约的是控制开销，不能直接减少长上下文 KV 数据量。固定地址缓冲允许其内容每步更新，形状分档和 padding 让不同有效批量映射到已有图；分段图则把部分动态操作留在图外。

因此分页本身不与图重放矛盾：物理页的选择可以通过稳定地址上的块表内容变化表达。真正约束是后端是否允许这些元数据更新，以及重放中的 kernel 是否遵循捕获契约。nano-vllm 的图执行和状态摘录、SGLang 的 piecewise 路线、TensorRT-LLM 的图 runner 分别体现这一动态与稳定的划分。

为不同档位保留图会增加捕获时间和持久缓冲；将有效批量补到较大档位则增加无效工作。若主导限制是主机提交，图重放有直接作用；若已被 KV 带宽或通信限制，减少提交间隙只能改善剩余部分。图档位选择因此同时影响内存预算与可利用形状；档位越多，捕获时间与持久缓冲也越多。

重叠执行：事件证明完成，引用证明归属

主机准备下一批、设备执行当前批、CPU 处理上一批输出可以重叠，但它们不共享同一时间点的状态。下一批若覆写上一批仍在读取的块表，数据值本身即使完全合法，也属于错误的请求映射。双缓冲避免写读同一缓冲，事件确定设备完成点，引用或锁定状态则保证物理页在完成前不被回收；这些职责不能由一个 non_blocking=True 标志替代。

取消请求尤其暴露这一差别。业务状态可立即标记取消，物理内存却要等在途访问完成后才能释放。页先释放再被新请求分配，会形成地址仍有效、语义已改变的错误。投机执行同样把临时候选状态与已确认状态分开：接受的前缀提交，被拒绝后缀回滚，异步参与者在统一完成点后回收。调度重叠带来的收益，正是以更复杂的状态生命周期为代价。

采样、结构化输出与多 rank 一致性

投机解码的概率校正在上一章推导，这里关注执行接口。草稿器、目标验证器和采样器分别消耗时间与 KV；候选长度增加，使一个请求在确认前持有更多临时位置。高接受率不保证收益，因为小模型执行、额外验证形状和管理成本仍可能超过省下的目标调用。框架的 proposer、worker 或双 context 路线必须把接受决定与实际状态进度连接。

结构化输出维护请求级语法状态，在采样前生成合法词元掩码。批量 logits 的行与请求、语法状态必须对应，选中的词元被确认后才推进解析状态。合法 JSON 仍需类型和业务语义判断；在生成时执行语法约束是另一回事。

张量并行 rank 分别拥有模型分片，却共同表示同一条序列。若 rank 独立采样或独立接受草稿，就可能形成不同后缀，使随后的集合通信在语义上失配。输出选择、取消与状态版本因此要在约定边界一致；专家并行和流水线并行还引入路由与在途微批的对应关系。并行减少某种单设备压力，同时扩大必须同步的参与范围。

PD 分离：减少队列干扰，增加状态传输

预填充与解码的资源形态不同，把它们放到不同实例可以分别组织批量，降低长输入与持续生成互相干扰。交接时，解码端不仅需要输入词元，还需可继续使用的各层 KV。若有效状态大小为 M、持续有效带宽为 B，无压缩的纯传输部分至少受 M/B 约束；协议、排队和确认增加等待，计算重叠则改变传输对关键路径的贡献。

同样的张量字节形状并不说明状态相容。两端权重、适配器、位置、精度和布局必须对应，发送端页在传输期间受保护，接收端在数据确认前不能执行依赖该页的查询。连接器超时可能触发退化重算，重算与已在途传输还需避免重复提交。分离的净收益因此来自减少的干扰减去新增交接成本；短提示、低并发或弱互连未必需要这一组织。

分层缓存把冷状态移到主存或存储，PD 把状态移到另一执行实例，两者都属于数据移动，但目标不同。前者降低高成本驻留，后者分离计算负载。多加一层状态位置就多加一层身份、命中、恢复与故障语义，容量增加也不意味着读取时延消失。

训练与 rollout 交替：权重版本是一致性边界

RL rollout 与训练共享资源时，引擎的 sleep／wake 和权重安装负责资源交接，不构成训练优化器本身。权重更新改变历史层表示，旧 KV 一般不能继续作为新模型的历史，因此必须按版本失效或重算。安装前还要结束或隔离在途批，避免同一轨迹混入两个参数版本。

训练状态分片、推理 KV 分页和环境快照保存不同对象，却都涉及“谁拥有、何时有效、何时释放”。框架设计的可比之处在这些明确的不变量；把所有内存机制合并成一个“缓存”功能名会丢掉它们。

精简实现：把完整机制压缩为可检查的状态机

nano-vllm：分页与请求进度的最小链路

nanovllm/engine/sequence.py、block_manager.py、scheduler.py、llm_engine.py 与 model_runner.py 串起请求、缓存、调度、执行和回写。链式块哈希防止不同前文中的同一片段错误共享；引用计数连接共享与释放；未被重新利用的空闲块仍可保留缓存身份。

固定版本的调度先尝试 prefill，若有批就返回，再处理 decode。因此已有分块预填充与已混合两种工作是两回事；它也保留了只允许某些请求在本批继续切块的限制。postprocess 在 prefill 未完成时不产生下一生成词元，这个条件比简单删除调度中的一个 break 更重要。调度器只在本轮计划覆盖预填充尾部时移入 running；真正完成的缓存进度随后由 postprocess 更新。扩展调度时须保持“尚缺预填充片段不能直接进入生成”的不变量。

例如输入共 2048 个词元，已计算 1536，本轮预算只能再安排 256，求和得到 1792，请求继续保留在 waiting。下一轮再计划 256，才覆盖输入末尾并转入 running。队列转换表达的是本轮安排后的阶段，而 num_cached_tokens 表达已经回写的进度，两者不能混用。

若一拿到 KV 块就移入 running，后续单词元路径可能在上下文尚不完整时执行；若仍在每个中间块后追加采样词元，又会把不完整提示的预测混进序列。调度中的覆盖检查与后处理中的未完成检查分工保护这两个边界。相比一口气处理完整输入，分块降低单轮工作量，却增加往返轮次；固定实现仍先处理 prefill，不能因此推断已有解码优先的公平性。

该版本的 model_runner.py 也有图捕获与重放，精简不意味着省掉所有执行优化。精简实现的局限应从实际异常、取消、命名空间、并行与测试范围判断。它的价值在于可以检查一条序列每步计算多少、何时多申请块、何时释放；生产框架另有职责。

mini-sglang：准入、句柄保护与在途元数据

mini-sglang 用 scheduler/prefill.py、decode.py、cache.py、table.py 分开预填充、生成、缓存和页表，kvcache/radix_cache.py 提供树与句柄，engine/graph.py 展示固定缓冲和图执行。匹配前缀后加锁，再检查可用容量，是因为锁定会使部分节点从可驱逐集合转为受保护集合，改变预算；不必先假定存在多线程竞争才能解释第二次检查。

锁定从句柄所在节点一路走向公共祖先，因为一次请求读取的是整条前缀，末端片段只是其中一段。若只保护叶节点，两个分支共同依赖的祖先仍可能被驱逐，叶子句柄就不能保证完整上下文可用。每次引用从 0 变为 1，节点长度由可驱逐容量转为受保护容量；从 1 变为 0 时才反向转回。共享祖先若还有另一个使用者，释放一个请求不会把它变回可驱逐状态。

这个设计也解释了为何匹配前的可用空间不能直接成为最终准入结果：锁定刚刚移走了一部分可回收容量。去掉第二次容量判断，即使没有并发线程，也可能用过时预算接纳请求。代价是每次锁定／解锁沿祖先链更新状态，引用必须成对释放；长期遗失句柄的后果是受保护容量无法回收，不会立刻表现为输出错误。

ChunkedReq 不允许进入解码或采样，明确表达“预填充尚未完成”的受限状态。准入还要为在途生成预留空间，页尾补量不能解释成每请求固定额外申请完整一页。严格 FCFS 与跳过放不下的请求，是公平性和预算利用率的不同取舍。

重叠执行中的 ForwardInput 保存本轮映射与位置，避免下一轮元数据改写破坏在途计算。实际扩展时应分别测试树匹配、页表填入、图缓冲和释放时序，再连接到完整服务。用一个无前缀复用的对照缓存，可以隔离缓存机制的作用；是否更快仍要以工作负载测量。

6. 下游任务

语言任务：表示、跨度与条件生成

同一个上下文化编码器可以连接不同输出对象。BERT 分类头读取序列级表示；逐位置标注头为每个位置输出类别；抽取式问答分别为起点和终点打分。[1] 表示共享不意味着任务约束共享。若起点和终点各自采用 softmax，两者的独立最大值可能形成终点早于起点的无效跨度，解码还需在允许的跨度集合内比较联合分数。该任务输出原文位置，不能产生原文中不存在的自由形式答案。

自回归翻译则建模目标序列对源序列的条件概率。目标自注意力提供已有译文历史，交叉注意力读取源表示，下一词元预测同时依赖两者。[6] 与把整个文本压成一个固定向量相比，交叉注意力允许不同输出位置访问不同源位置；但访问权重只是模型学到的分配，与人工对齐标签无关；模型似然、搜索结果和人工译文质量分别属于建模、决策与评价层。

任务风险还取决于输出可接受集合。单标签分类的标准交叉熵假设一个类别是监督目标，而摘要或问答可能存在多个语义等价答案；仅以与某一参考文本的词面重合比较，会把表达差异与事实差异混合。生成模型还可能利用文本统计填补输入中没有的细节，因此流畅性、正确性与证据支持需要分别判断。

销售预测：统计判断与干预收益

SalesRLAgent 将对话、业务信息、外部嵌入、预测组件以及强化学习组织在同一系统中。[8] 基础模型可以承担合成数据或表示提取，而最终转化判断由专门预测器完成；模块名称出现 LLM 或 RL，并不能据此推断系统对 Transformer 主体进行了领域偏好训练。

转化预测估计的是既有样本中的条件关系，建议是否带来销量增长则是干预问题。令 a 是建议动作，s 是业务状态，观测量 E[Y|a,s] 与干预量 E[Y|do(a),s] 一般不相等：历史销售员可能在最容易成交的场景采取某种动作，使动作与收益同时受未记录因素影响。预测准确因此不能单独证明建议造成收益。合成对话还会引入生成器对行为和标签的假设。这一案例的价值在于说明系统分工与评价对象；原报告的指标只作作者报告。

检索增强与智能体：外部证据怎样进入生成

语言模型参数保存的是训练中形成的统计关系，业务文档、记录和规则则持续变化。检索增强生成将外部知识引入推理时的上下文，使知识更新不必全部通过重新训练参数完成。Gao 等把朴素 RAG 的问题分为检索质量、生成质量和上下文增强三个部分，并据此讨论预检索、后检索及模块化改进。[13]

检索失误与证据使用失误需要分别定位

基本链路是文档整理与分块、索引构建、查询检索、上下文组织和生成。分块决定检索对象携带多少局部内容与上下文，索引决定查询怎样接近这些对象，生成器则把问题与取回材料共同作为输入。它们之间的接口传递的是候选证据。

没有取回关键材料时，生成器缺少回答依据；取回大量无关材料时，相关信息又可能受到噪声和有限上下文预算挤压。即使关键材料已经取回，生成器也可能忽略条件、混合不同版本或产生材料不支持的结论。这分别对应召回不足、精度不足和证据使用失误，用“模型不够大”一概而论会掩盖三者的差异。[13]

增加检索条数提高关键材料进入候选集的机会，却也占用上下文预算并引入竞争材料。较小分块有利于精确匹配局部事实，但可能截断条件和指代；较大分块保留语境，却降低每个词元的信息密度。查询改写与混合检索改善候选获取，重排与筛选改善上下文选择，来源和版本元数据则帮助识别材料适用范围。收益与误删重要证据的风险都来自这些具体接口。[13]

可以用一个条件分解说明错误链。设 R 为关键证据进入候选集，C 为它在最终上下文中被完整保留，G 为生成器正确使用这些证据。对需要该证据的受支持回答，成功事件至少要经过 R∩C∩G，因此链条通过概率为 P(R)P(C|R)P(G|R,C)。这是条件概率恒等式，阶段之间无需独立；把任意答案正确率都归结到它身上则超出范围：模型可能依靠参数记忆猜对，错误证据也可能偶然产生正确文本。分解的作用是辨认召回、组织与使用分别限制哪一类有依据的回答，用一个相似度衡量全过程质量会丢失分层信息。

更新知识库与学习能力是不同操作

资料中的事实发生变化，可以通过更新文档、索引与版本筛选，让生成器读取新的证据。任务要求变化，例如新的判断规则或输出格式，则可能需要提示、工具接口或参数适配共同处理。RAG 把事实获取放到外部，但并不独自解决模型如何可靠地应用这些事实。

检索向量相似度用于排序，未校准为“这段材料在此问题下为真”的概率。相似内容可能来自旧版本、转述或互相矛盾的来源；附上引用与生成句得到引用支持是两回事。检索命中、答案正确和证据忠实因而是不同性质。Gao 等对检索与生成失误的分解提供了分层分析基础。[13]

外部文档还同时包含事实和自然语言指令。它们作为待判断的内容进入上下文，不应因此获得更高的工具权限。恶意材料若把自身写成控制指令，检索质量和执行安全就发生跨层耦合：取回了相关文本，也可能诱导控制器偏离任务。来源身份、权限边界和工具参数验证分别管理证据与动作，RAG 增加知识入口的同时也扩大了输入信任问题。

动态检索增加的是控制层

当问题需要从一条记录找到实体，再到另一来源核对条件，一次固定查询可能不足。Agentic RAG 将何时检索、怎样改写查询、选择什么工具和是否继续寻找证据纳入控制流程。Singh 等从控制结构和协作方式讨论这类架构，也指出链式处理与资源组织的代价。[16]

动态流程让下一次信息获取依赖前一步结果。例如第一轮找到实体身份，第二轮才构造适用于该实体的时间或法规查询；这种依赖无法完全由同时发出多个独立查询替代。并行分支可以缩短互不依赖的搜索阶段，但产生重复材料、版本冲突和合并成本，串行依赖仍保留在关键路径上。[16]

继续检索的价值可以抽象为预期减少的任务损失与新增时间、资源和错误风险之间的比较。这个决策需要对未解决的不确定性有可用判断，不能只以模型口头“确信”作为终止证明。固定步数保证过程有界却可能过早结束，无限重试又可能累积噪声而不增加证据。控制器因此需要有界资源、可验证的完成条件及失败返回语义。最终评价对象是整个获取、判断与回答流程，一次生成调用只是其中一环。

视觉任务：从图块表示到集合预测

ViT 将图像切成图块并投影为序列，由全局交互形成表示，再从分类位置读取类别。[2] 输入图块只是几何划分，与物体区域无关。分类标签可以不要求网络精确区分每个像素或每个物体，因此分类表征的有效性不能替代定位和分割接口。MAE 将重建作为预训练目标，下游只使用编码器，说明预训练目标与应用输出可以不同。[3]

密集任务还要恢复空间关系。更细图块保留更多局部信息，但图块数按面积增加，稠密注意力的成对工作进一步增长；较粗表示减少成本，却可能丢失小物体细节。高分辨率改变的不仅是输入长度，还包括位置参数、空间尺度和任务头所需的信息粒度。

DETR：为什么目标检测需要一对一匹配

传统检测器常从大量锚点、候选框或中心位置产生预测，再通过非极大值抑制消除近重复结果。DETR 把检测改为固定数量的对象槽位：CNN 提取图像特征，Transformer 编码器交换空间信息，解码器用不同的可学习对象查询并行读取图像，输出类别与框。这里的查询是槽位的可学习身份，与用户文本无关，也不天然对应固定物体类别。[27]

真实物体构成无序集合。如果给每个预测槽位预先指定第几个标注对象，换一种标注排列就会改变训练目标。DETR 通过二分匹配，在预测集合与以“无物体”补齐的目标集合间选择总代价最低的排列：

σ^=argminσ∈SN∑i=1NCmatch(yi,y^σ(i))

置换预测槽位只会重新编号可行排列，最小值不变，因此该匹配目标对槽位排列不敏感。一对一关系使同一物体只监督一个匹配槽位，多余槽位学习“无物体”；与允许多个候选同时匹配一个物体再后处理去重相比，去重压力进入了训练目标。它鼓励不重复输出；训练有限、预测有误时仍可能出现重复。

匹配代价与训练损失是两个不同的函数。原版匹配使用负类别概率与框代价，确定匹配后则使用负对数类别概率，框项结合 L1 和 generalized IoU；无物体分类项降低权重以处理类别失衡。这些约定见原论文 §3.1。[27] 匹配选择是离散操作，训练按当前选中的分配优化预测，与对 Hungarian 算法本身求连续梯度是两回事。

DETR 的并行对象解码并不遵循语言生成的前词元依赖，因此不需要逐对象自回归循环；对象间自注意力帮助槽位协调，交叉注意力把槽位与图像内容连接。简化后处理并没有消除优化代价，原论文报告较长训练周期、小物体表现较弱，并使用辅助解码损失。[27] 方法改变了任务表示和监督组织；通用 Transformer 是否无须空间先验或多尺度处理，要另作论证。

多模态：独立编码与条件生成的不同接口

CLIP 图像和文本编码器独立产生向量，经过归一化后以点积比较。[4] 对检索库中的候选，可以预先计算向量，使在线查询主要承担一次编码和向量检索；跨模态交叉注意力则在位置级让一方读取另一方，其结果通常依赖具体输入对，难以用同样的独立候选缓存替代。双塔的效率来自分离编码，代价是整体向量压缩可能削弱细粒度匹配。

零样本分类把类别写成文本描述，相当于用一组候选文本定义决策边界。加入新的相似类别会增加竞争，模板改变文本向量也会移动边界；“零样本”描述的是目标任务适配协议，预训练监督照旧存在。检索相似度、分类决策与自由文本生成因此是三种不同的能力。能够比较图文向量，并不直接提供生成带证据答案的条件分布。

语音：声学证据、任务词元与语言先验

Whisper 采用编码器—解码器 Transformer，将音频对应文本作为大规模弱监督信号，省去了先做纯音频自监督、再为每个任务单独训练输出解码器的做法。[28] 原始音频转换为 log-Mel 频谱，经卷积前端压缩后加位置表示；文本解码器通过交叉注意力读取声学表示，同时通过因果自注意力读取已有文本。这种接口使输出既受声音约束，也受语言条件概率约束。

转写与翻译面对同一音频可以要求不同输出语言，时间戳与纯文本也不同。Whisper 因此以语言、任务和时间戳等特殊词元说明输出条件，将多个任务接到共享序列预测接口。任务格式见原论文 §2.3。[28] 条件标记保留了任务差异：转写目标尽量保留原语言内容，翻译目标改变语言，时间戳目标还需对应声学时间。共同输出格式节约分离流水线的接口，但依赖训练监督覆盖这些条件。

这也解释了与 CTC 类逐帧预测接口的差别：自回归文本解码器显式利用历史文字，可以帮助解析含混声音，却可能在声学信息薄弱时偏向语言上合理的续写。交叉注意力的存在并不保证每个生成词都有足够声学支持。原论文还讨论长音频分段、解码启发式及弱监督数据质量，这些环节使模型质量与完整转写流程不能分开看待。[28]

Whisper 原版将音频按 30 秒片段组织，完整片段编码与严格流式识别是两回事。流式系统的可见未来、延迟预算和分段状态需要额外设计。相同错误率也可能来自替换、删除或插入的不同组合；词错误率 WER=(S+D+I)/N 按参考词数归一，插入较多时甚至可超过 1。语言词元化、文本规范化、领域和噪声条件会改变统计口径，所以弱监督跨域结果不能直接当作任意实时产品的性能承诺。

时间序列：局部片段、跨通道关系与预测边界

一个采样时刻的向量未必具有像单词那样的独立语义，趋势、局部周期和瞬时变化往往分布在一段连续观测中。PatchTST 因而把子序列作为输入单位，将片段线性投影后送入 Transformer；这改变的是信息进入注意力的粒度，与替换稀疏注意力公式是两件事。[29]

设历史长度 L、片段长 P、步长 S。不加边界填充时，片段数为 floor((L−P)/S)+1；原论文在末尾复制最后观测值 S 次，得到再多一个片段的配置。对较长历史，N≈L/S，成对注意力图的项数由 L² 降至约 L²/S²。这个二次因子只属于注意力部分，片段投影、前馈和预测头仍有自己的成本，不能将其写成完整模型的固定加速倍数。该计数约定见原论文 §3.1。[29]

通道独立为何有效，又放弃了什么

PatchTST 将多变量序列拆成多个单变量通道，各通道独立前向，却共享嵌入与 Transformer 参数。共享使不同变量共同训练相同时间模式提取器，也允许预训练与下游具有不同通道数；独立前向减少任意通道混合的参数与拟合压力。[29] 但共享参数并不让模型显式读取其他通道的当前值。固定参数后，一个通道的输出对另一通道输入的直接偏导为零，跨通道影响只可能经共同参数学习等间接路径进入。

这一取舍在相关性稳定、数据较少或变量尺度不同的任务中可能提供有用正则化；若预测本质依赖其他变量的领先信号，纯独立接口却无法表达该条件依赖。例如 Yt+1=Xt+ε，若 Y 自身历史对 Xt 没有信息，单独读取 Y 历史的模型不能恢复所缺信号。该反例解释表达边界，不否定原论文在指定数据集上的经验结果。

重建目标与未来预测不能混同

PatchTST 的自监督配置使用不重叠片段并随机遮挡，用平方误差重建缺失片段，避免重叠观测直接泄漏被遮挡值。该配置见原论文 §3.2。[29] 同一段历史内部的双向读取适合重建；未来预测则要求所有输入在预测时已可获得。输入、归一化统计或协变量若包含未来观测，离线指标就不再对应实际预测条件。

在平方损失和无限制预测器下，最优点预测是条件均值。这有助于平均误差，却可能把多种未来模式平均为现实中不常见的轨迹；预测区间和极端事件风险需要另一个输出及评价接口。时间切分、滚动评价、季节变化和数据修订还决定泛化问题。Transformer 的长历史交互提供表达能力，片段化提供局部组织，二者都不能替代信息边界明确的预测协议。

蛋白质序列：分布统计如何携带结构信息

蛋白质语言建模把氨基酸序列作为输入，使用掩码预测从未遮挡部分推断缺失位置。Rives 等研究跨大量进化序列训练的 Transformer，并通过下游任务检验其表示是否包含结构和功能相关信息。[30] 它与自然语言共享序列预测形式，却不共享词义假设：氨基酸选择受结构稳定性、功能和进化过程约束，而训练目标只直接观察序列。

其动机可以用潜变量关系理解。若未观察的结构 z 同时约束多个位点，序列分布可看作对 p(x|z)p(z) 的混合；准确预测某个位点，就可能需要捕捉那些跨位点约束。表示因此有机会编码与结构有关的统计信息。但这是学习动机，可识别性要另作论证：多个潜在解释可能产生相同序列分布，掩码预测准确也不意味着已经求出了唯一三维结构。

这与在单一序列家族上拟合共变关系的传统路线不同。多序列比对把同源位置对齐，家族内统计能够提供位点耦合；跨家族语言模型学习的是共享参数化表示，推理时可以直接接受一条序列。两者利用的进化信息组织不同，语言模型并未因此摆脱同源数据分布或获得无条件结构预测保证。相关比较见原论文 Background。[30]

线性探测说明什么

原论文从冻结的隐藏表示读取二级结构，并对两位置表示分别作线性投影，再以点积预测接触。具体接口见原论文 Linear Projections。[30] 设表示 hi、hj，接触评分可写为 (Uhi)ᵀ(Vhj)。这是一种受限的双线性读取，有助于区分表示已经携带的信息与复杂下游网络新学到的信息；它与“注意力权重就是接触图”这一等式不同。论文还使用更复杂的监督网络评估下游效果，两类证据回答不同问题。

结构探测按家族、超家族和折叠层级划分数据，能够测试比随机序列划分更远的泛化；密切同源样本同时出现在训练与测试中，可能把识别已见家族误当作发现新结构。作者报告预训练后受限读取可以恢复更多结构信息，但这些结构任务仍包含监督标签，不能把全部结果称为无监督直接折叠。[30]

生物功能和突变效应还涉及环境、实验体系及多个分子相互作用。统计序列偏好并不自动等于生物适应度，结构相关性也不证明某个干预安全有效。这里借蛋白质建模说明同一序列架构如何学习不同领域的约束，不将其替代实验验证或外推为医学结论。

应用之间可迁移的是接口

上述任务共同包含输入组织、可见性、交互、目标与读取接口，但这些对象的含义不同：检测输出无序集合，语音输出依赖声学条件的序列，时间预测输出受信息时点约束的未来值，蛋白质探测读取结构相关表示。数学子块可以复用，监督和评价条件却不能照搬。

迁移是否成功因此取决于目标任务需要的信息是否进入输入、训练目标是否保留这些信息，以及输出约束是否与评价相容。更大的模型可能减轻表达能力限制，但不能补回不存在的证据、修复未来数据泄漏，或把观测预测变成因果干预保证。架构、训练、推理与框架最终共同服务于这些具体条件，独立的跨领域性能排名并不由此产生。
