#### 定时任务与终端会话 {#interview-engineering-ops}

<article class="qa-item" id="qa-cron-execution" data-level="scenario" markdown="1">
<p class="qa-question">Q259 · cron 的时间字段和执行环境怎样理解？定时触发等于任务完成了吗？</p>
<div class="qa-answer" markdown="1">

常见用户 crontab 用分钟、小时、月内日、月份、星期字段选择执行时刻，随后是命令；系统表通常另有执行用户字段，不能混用格式。Cronie 的日与星期限制组合还有特定规则，时区和夏令时也可能影响触发。[154]

任务以对应用户身份运行，Shell、HOME、PATH 和工作目录不一定与交互登录相同。相对路径、依赖交互提示、输出邮件或日志配置都可能使“手动成功”与“定时失败”并存。把退出状态、失败报告和必要日志纳入任务接口，比只登记表达式更可靠。

上一次未结束时，下一时刻仍可能再启动一份；需要明确跳过、排队或可并行的策略，以及超时与重试的幂等性。断电、休眠和调度器差异影响错过时刻后的行为，普通 cron 不能无条件保证补跑，更不保证每次任务按时完成。

</div>
</article>

<article class="qa-item" id="qa-tmux-terminal-session" data-level="scenario" markdown="1">
<p class="qa-question">Q260 · tmux 的会话、窗口和面板怎样区分？断开终端后继续运行能保证什么？</p>
<div class="qa-answer" markdown="1">

Tmux 的 server 管理会话，客户端附着显示；会话含窗口，窗口可分成多个面板，每个面板对应独立伪终端。分离客户端后仍可重新附着，同一会话还可有多个客户端。[155]

会话、窗口选择与面板分割组织的是终端交互，不是线程池或独立虚拟机。复制模式用于查看并选取滚动内容，终端编辑和历史搜索通常由 Shell 的按键绑定负责，不能把一份配置的所有快捷键写成任何环境的固定规则。

连接断开而 server 仍存活时，会话内程序可以继续运行；主机重启、进程被杀、资源耗尽或应用自身出错则是其他故障。Tmux 不自动提供服务启动顺序、健康检查、重启和持久化。长驻业务仍需相应服务生命周期协议，保存会话布局也不等于保存进程状态。

</div>
</article>
