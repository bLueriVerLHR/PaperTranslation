#### 内存管理 {#interview-os-memory}

<article class="qa-item" id="qa-virtual-memory" data-level="basic" markdown="1">
<p class="qa-question">Q102 · 虚拟内存、页表和 TLB 分别解决什么问题？</p>
<div class="qa-answer" markdown="1">

虚拟地址是进程使用的地址视图；地址转换将它关联到物理页或其他映射，并同时实施访问权限。页表记录映射与属性，TLB（translation lookaside buffer，地址转换缓存）缓存部分地址转换结果，减少反复遍历页表的成本。分页不仅为了“内存不够时用磁盘”，还支持地址空间隔离、共享映射及按需建立页面。[41]

TLB 未命中不等于缺页。前者可能只需要查页表并补充转换缓存；后者涉及页不存在、权限不满足等异常条件，内核需要处理或拒绝访问。虚拟空间大小、已映射范围、驻留物理内存和交换空间用量也不是同一个指标。

服务持有大地址范围，不代表已占用同等大小的物理内存；反过来，地址能够分配也不表示之后触页、物理内存压力和系统限制不会导致失败。分配与实际使用之间的差别直接影响容量分析。

</div>
</article>

<article class="qa-item" id="qa-segmentation-fragmentation" data-level="basic" markdown="1">
<p class="qa-question">Q103 · 连续分配、分段、分页和段页式各有什么碎片？</p>
<div class="qa-answer" markdown="1">

连续分配要在物理范围中找到足够大的连续空洞，首次适应、最佳适应等策略在查找与剩余碎片之间取舍。分段按逻辑区域分成可变长度段，可能产生外部碎片；分页用固定大小页及页框组织，减少对整个进程物理连续存储的要求，却可能有页内未用空间。段页式先按段组织，再按页映射，是另一层组合。

分页不是完全没有碎片：尾页、分配器尺寸类别、要求物理连续的大块及设备约束各有不同浪费。ELF 的代码／数据“段”、进程虚拟映射区和硬件分段也不是同一个对象，不能因看到 text segment 就说现代 Linux 使用传统段页式寻址。常见 Linux 架构主要依赖分页实现进程映射，具体硬件特性要按架构说明；大页减轻部分页表和 TLB 成本，同时增加分配与粒度约束。[41]

</div>
</article>

<article class="qa-item" id="qa-page-table-capacity" data-level="principle" markdown="1">
<p class="qa-question">Q104 · 页号和页内偏移怎样划分？多级页表及 32 位进程的容量怎么计算？</p>
<div class="qa-answer" markdown="1">

页内偏移由页大小确定，页号用于定位映射。例如在 32 位地址、4 KiB 页且简化为单级表的教学模型中，低 12 位是偏移，高 20 位是虚页号；若每项 4 字节且覆盖完整空间，表占 4 MiB。多级页表只为需要的分支建立下级表，节约稀疏空间的管理量，代价是更多层访问；TLB 命中能绕过部分遍历成本。[41]

32 位地址最多表示 4 GiB 字节地址范围，不等于可得到 4 GiB 堆，也不能一律减半得到 2 GiB 堆。用户／内核划分、程序映射、栈、库、地址连续性、资源限制和实际内存共同约束可用量；传统 32 位 Linux 还有 3／1 等不同划分。物理机器配了更多 RAM，可能让多个进程各自使用部分资源，却不会自动扩大单个 32 位指针的表达范围。[41]

</div>
</article>

<article class="qa-item" id="qa-page-fault" data-level="principle" markdown="1">
<p class="qa-question">Q105 · 缺页异常一定要读磁盘吗？为什么访问合法地址也可能触发它？</p>
<div class="qa-answer" markdown="1">

合法映射可能按需建立页面：首次触碰匿名页、建立已有缓存页的映射、写入写时复制页，都可能触发内核处理，而不必读取存储设备。Linux 的 minor fault 与 major fault 统计正是区分不需要加载页面的 I/O 和需要这类 I/O 的情形；它们不是“无错”和“程序出错”的区分。[24]

写时复制允许多个映射起初共享页面，修改者写入时再获得私有页面。它节省未修改部分的复制，但实际写入会增加页面分配、复制和内存压力。使用它的快照或子进程机制不能被解释为零成本。

非法地址或不允许的访问则可能导致进程收到信号；异常能否被内核修复，取决于映射与权限，而非地址数字是否“看起来在堆区”。因此既不能把所有缺页当成磁盘瓶颈，也不能把所有缺页当成可忽略的普通事件。

</div>
</article>

<article class="qa-item" id="qa-page-replacement" data-level="principle" markdown="1">
<p class="qa-question">Q106 · 局部性、页面置换与抖动如何关联？FIFO、LRU 和 Clock 为什么不同？</p>
<div class="qa-answer" markdown="1">

时间局部性使近期访问的数据可能再被用到，空间局部性使邻近数据可能随之访问。驻留预算不足以容纳活跃工作集时，页面频繁调入、回收，执行资源大量用于等待或内存管理，就可能抖动。仅增加并发任务会扩大同时活跃的工作集，不一定改善 CPU 利用率。[41]

OPT 选择未来最晚才再用的页，是知道未来的比较基准；FIFO 只看进入顺序，某些访问序列中增加页框反而增加缺页；LRU 看最近访问次序，精确维护昂贵；Clock 用访问位和轮转近似保留近期页面。Linux 回收会结合匿名／文件页、访问与脏状态、NUMA 和具体版本的机制，不能固定写成“永远用一个 Clock”。诊断要区分正常首次触页、真正需要 I/O 的缺页及回收压力，而非把所有缺页数直接当抖动。[24, 41]

</div>
</article>

<article class="qa-item" id="qa-cpu-cache-false-sharing" data-level="principle" markdown="1">
<p class="qa-question">Q107 · 寄存器、L1／L2／L3 和 RAM 有何不同？缓存一致性为什么不替代 C++ 同步？</p>
<div class="qa-answer" markdown="1">

寄存器与指令执行路径直接相连，CPU 缓存按缓存行保存部分指令或数据，RAM 提供较大容量。常见 L1 很小且接近核心，L2／L3 容量更大，但哪些层私有、共享、包含或非包含都依处理器；缓存通常采用 SRAM 等结构，不能说所有 CPU Cache 都是核心外部 DRAM。访问延迟还受依赖、命中层级和并行请求影响，没有统一的固定周期表。

硬件一致性协调缓存副本，不为有数据竞争的 C++ 程序补上语言层 happens-before。不同线程频繁写同一缓存行上的不同字段，虽可在语言规则下分别合法访问，也可能形成伪共享，让缓存行所有权反复转移。把热点状态分开、分片或批量累计可能降低这种流量，代价是空间、汇总和一致性协议；按某个固定 64 字节填充不是所有硬件的通用性能保证。[16–17]

</div>
</article>
