#### 语言基础：类型、值与表达式 {#interview-cpp-language}

<article class="qa-item" id="qa-pointer-reference" data-level="basic" markdown="1">
<p class="qa-question">Q01 · 指针和引用有什么区别？引用一定不占内存吗？</p>
<div class="qa-answer" markdown="1">

指针是保存指针值的对象，可以改指向，也可以保存空指针值；引用表示已经建立的绑定，不能通过赋值重新绑定。`int& r = a; r = b;` 修改的是 a 的值，不是把 r 改成 b 的别名。普通引用变量的定义需要初始化，引用形参在调用时建立绑定；良定义程序中没有类似 `nullptr` 的合法“空引用”。[48]

指针通过 `*p` 访问目标，`&p` 取得指针对象自身的地址；引用可直接用于访问目标，`&r` 取得的也是目标的地址。未初始化的局部指针不是合法空指针，不能读出来判空；已经初始化的指针和引用也都可能在目标销毁后悬挂。需要表达“可以没有对象”或进行数组内遍历时，指针比较自然；需要绑定一个现有对象时，引用能更直接地表达接口约束，但它不自动提供所有权或任意生命周期延长。[48]

引用一定“不占内存”是错误的绝对结论。语言没有规定引用是否需要存储；引用参数常通过地址传递，是 ABI 的实现方式，局部引用也可能被优化掉。对引用使用 `sizeof` 得到被引用类型的大小，不能测出实现中可能保存的地址。指针对象同样可能在不影响可观察行为时被优化掉，语义差异不能直接推出引用一定更快。[48, 54]

</div>
</article>

<article class="qa-item" id="qa-const-pointer" data-level="basic" markdown="1">
<p class="qa-question">Q02 · const int*、int* const 和 const 成员函数分别限制什么？</p>
<div class="qa-answer" markdown="1">

`const int* p` 与 `int const* p` 等价，限制通过 p 修改目标，但 p 可以改指向；`int* const p` 固定指针值，仍可修改非 const 目标；`const int* const p` 同时限制两者。例如目标本来是普通 `int x`，通过另一个合法的 `int*` 修改 x 不违反 `const int*` 的约束；但目标本来就是 const 对象时，去掉限定也不能授权修改它。[50, 52]

普通 const 成员函数通过其隐式对象参数把当前对象视为 const，不能据此修改普通数据成员；`mutable` 成员是例外。指针成员指向的外部对象不因此深度只读：成员指针本身不能重新赋值，目标是否可修改仍由所指类型与对象实际限定决定。const 接口若更新共享缓存，仍需要同步，不能把 const 当作线程安全标志。[52, 198]

const 数组限制相应元素的修改，`const int&` 限制经该引用修改目标；按值参数上的顶层 const 主要约束函数内的参数副本，不等于把调用方对象变成只读。返回 `const T*` 或 `const T&` 可以限制这条返回访问路径，却仍要满足所借用对象的寿命。普通 const 对象调用非静态成员时，隐式对象参数须与其 cv 限定相容；静态成员函数没有这个对象参数约束。[52, 198]

C++11 起，普通非静态 const 数据成员可以有类内初始值，例如 `const int limit = 8;`，也可以在构造初始化列表中初始化；两者不是进入构造函数体后再赋值。不能沿用“const 成员只能写在初始化列表”的旧结论。[55]

</div>
</article>

<article class="qa-item" id="qa-sizeof-strlen" data-level="basic" markdown="1">
<p class="qa-question">Q03 · sizeof 和 strlen 有何不同？空类、数组指针和 32／64 位指针有多大？</p>
<div class="qa-answer" markdown="1">

sizeof 给出类型或对象表示的字节数，其表达式操作数在标准 C++ 中不被求值；strlen 返回有效零结尾字符串中首个零字符之前的字节数，不包含终止符。`char s[] = "abc";` 的 `sizeof(s)` 是 4，`strlen(s)` 是 3；中间出现零字符时，strlen 也会在该位置停止。它不接收缓冲区容量，不能用来发现未终止缓冲区的安全边界。[54, 196]

数组本身与指向数组的指针不同。`int a[10]; int* p = a; int (*q)[10] = &a;` 中，`sizeof(a)` 是 `10 * sizeof(int)`，`sizeof(p)` 与 `sizeof(q)` 分别是相应指针类型的大小，都不是数组容量。数组参数声明会调整为指针参数，函数内对该参数做 sizeof 也不能恢复调用方的数组长度。[54]

完整空类对象的大小非零，常见实现为 1，但不是所有实现都被规定为 1；类有普通非虚成员函数也不必因此有额外的每对象成员存储。空基类优化和 C++20 的 `[[no_unique_address]]` 可以影响子对象占用，不能把每个完整对象的 sizeof 机械相加得到外层布局。[54, 192]

指针尺寸由具体实现和 ABI 决定：常见 32 位 ABI 的对象指针为 4 字节，常见 64 位 ABI 为 8 字节；运行在 64 位系统上的 32 位进程并不因此变成 8 字节指针。函数指针、成员指针也不能仅凭“系统位数”套用普通对象指针的尺寸。对指向数组的指针做 sizeof，仍应查询该指针类型本身。[54]

</div>
</article>

<article class="qa-item" id="qa-union-type" data-level="basic" markdown="1">
<p class="qa-question">Q04 · 结构体与联合体有什么区别？union 的活跃成员决定读到什么？</p>
<div class="qa-answer" markdown="1">

`struct` 的成员各有独立位置，同一时刻都存在；`union` 的非静态数据成员共享同一地址，同一时刻至多有一个成员是活跃的，而且所有成员地址相同。[282,283] 活跃成员由最近一次写入决定。

读取不是最近写入的那个成员是未定义行为，`union` 既不记录活跃成员，也不做类型检查；[282] 标准只规定共享存储这一件事，不保证读出的位组合能被解释成另一个类型的值。[283] 例外是标准布局结构体之间的公共初始序列可以按对应成员读取，以及用字符类型或 `std::byte` 检查对象表示。[284]

所以 `union` 适合“同一存储按不同类型复用、类型安全由调用方维护”的场合，例如把标签放在外面、成员放在里面做紧凑表示。需要类型安全的变体用 `std::variant`：它记录当前备选类型，错误访问抛出 `std::bad_variant_access`，并会按当前类型正确构造与析构。用 `union` 承载带非平凡构造／析构的成员时，构造与析构必须显式调用；把它当作线格式还会同时遇到填充、端序与别名规则问题。

</div>
</article>

<article class="qa-item" id="qa-floating-compare" data-level="basic" markdown="1">
<p class="qa-question">Q05 · 浮点数为什么不宜只用 == 比较？固定 epsilon 总是合适吗？</p>
<div class="qa-answer" markdown="1">

浮点 == 不是一律错误，但它判断的是所存值是否相等，不会替业务表达“误差足够小”。在基数 2 的有限精度格式中，0.1 的约分后分母含因子 5，不能写成分母只有 2 的幂的有限二进制小数；表示和后续运算都可能舍入，所以数学上等价的两条计算路径可能得到不同结果。精确可表示的值、约定哨兵或同一有限值的复制，仍可以有明确的相等语义。

近似比较首先需要业务误差模型。对有限值 x、y，一种规则是绝对误差不超过“绝对容差加相对容差乘两值幅度最大值”，其中容差非负。近零时绝对容差避免尺度退化，大数时相对容差反映量级；单位、测量误差和误差传播共同决定容差。`numeric_limits<T>::epsilon()` 描述 1 附近相邻可表示值的差，不是任意量级或业务测量的统一允许误差；直接用浮点实现误差公式时，还需要处理减法和阈值计算的溢出。[197]

特殊值需要另定规则。在采用通常 IEEE 754 比较语义的格式中，NaN 的相等比较包括与自身比较均为假，无穷值也不适合直接代入误差差值。应用可以先判定允许的精确相等，再拒绝其余非有限值，最后对有限值做误差比较；C++ 浮点类型是否遵循相应 IEC 60559 格式，不能仅凭类型名字猜测。[197]

近似相等也未必有传递性。例如只用绝对容差 1 时，0 与 0.75、0.75 与 1.5 都通过，0 与 1.5 却不通过。这是规则本身的反例，不是运行结果；把它直接用于有序容器比较器的“等价”判定，可能违反严格弱序要求。

</div>
</article>

<article class="qa-item" id="qa-value-deduction" data-level="principle" markdown="1">
<p class="qa-question">Q06 · 左值／右值怎样判断？auto 与 decltype 会保留引用吗？</p>
<div class="qa-answer" markdown="1">

值类别描述表达式，而不是变量活多久。左值和将亡值都能表达对象身份，右值包括将亡值和纯右值；不能用“有地址就是左值”或“右值一定马上销毁”作为完整定义。普通表达式中的 `x` 是左值，`std::move(x)` 是将亡值，整数常量 `42` 是纯右值；const 对象的名字、具名 `T&&` 参数的普通使用仍是左值。[13, 195]

普通 `auto y = x;` 按值推导，通常去掉顶层 const 和引用，保存一个独立的值；`auto&`、`const auto&` 则保留相应引用绑定。`auto&&` 在满足推导条件时可作为转发引用，具体类型还取决于引用折叠，不能把看到 `&&` 都解释成“必须绑定右值”。std::move 只是值类别转换，能否真正移动仍取决于重载与对象类型。[13–14, 48, 195]

例如在普通局部声明中，`int x = 1; auto y = x; auto& z = x;` 得到独立的 y 与绑定 x 的 z。`decltype(x)` 对未加括号的名字采用特殊规则，得到 `int`；`decltype((x))` 按该左值表达式的类别得到 `int&`。C++14 的 `decltype(auto)` 沿用 decltype 规则，因此 `decltype(auto) a = x;` 与 `decltype(auto) b = (x);` 分别保存值和建立引用。推导保留类型不等于生命周期安全，返回局部对象的引用仍会悬挂；这些局部声明示意不扩张为所有版本下的返回语句自动移动规则。[195]

</div>
</article>

<article class="qa-item" id="qa-macro-inline" data-level="principle" markdown="1">
<p class="qa-question">Q07 · 宏、const、constexpr 和 inline 怎样选择？虚函数能是 inline 吗？</p>
<div class="qa-answer" markdown="1">

普通常量优先使用有类型的声明，普通计算优先使用函数；宏主要用于条件编译、字符串化等预处理工作。宏替换记号，没有普通变量或函数的类型检查与作用域规则；const 限制相应访问路径，constexpr 变量要求常量表达式初始化，constexpr 函数则可以在满足条件时参与常量求值，也仍可在运行时调用。它们不是四个可以任意互换的优化开关。

宏定义独立于花括号块作用域，从定义处持续到对应的 `#undef` 或翻译单元结束，头文件中的宏也可能影响后续代码。普通 const 变量则按声明位置适用名字查找、作用域和链接规则，不能把两者都概括成“文件内常量”。[163]

函数式宏可能重复求值：`#define SQUARE(x) ((x) * (x))` 会把 `SQUARE(i++)` 展开为对同一标量的两个未排序自增，产生未定义行为。单参数平方函数接收的是一次实参求值的结果，函数体重复读取参数不等于重复执行调用方的 `i++`。[173] inline 函数仍遵守参数、重载和类型规则；inline 允许满足语言条件的跨翻译单元定义，不强制展开调用。constexpr 函数隐含 inline，也不意味着每次调用都发生在编译期。[172]

虚函数可以声明为 inline，能否去虚化并展开取决于编译器能否确定调用目标。“允许这样声明”与“本次调用是否被优化”是两个问题。[51, 53] 调试可见性也不能简单二分：GCC 的 `-g3` 可保存宏定义，由支持的调试器展开；宏仍不是运行时对象。有类型的 const 变量也可能被优化消去或传播成常量，可观察性依赖调试信息和实际构建。[159]

</div>
</article>

<article class="qa-item" id="qa-static-extern" data-level="principle" markdown="1">
<p class="qa-question">Q08 · static、extern、extern "C" 和 volatile 分别表达什么？</p>
<div class="qa-answer" markdown="1">

它们主要区分存储期、名字链接、语言链接和访问语义，而不是四种“作用域开关”。局部 static 对象具有静态存储期，名字作用域仍在块内；命名空间作用域的 static 变量或函数具有内部链接，不能借另一个翻译单元的 extern 声明绕过它。存储期说明存储持续多久，链接说明不同声明能否指称同一实体，二者都不直接规定机器上的某个数据段。[190]

类的 static 数据成员不是每个对象各带的一份普通子对象；未声明 `thread_local` 时通常由该类的对象共享，`thread_local` 静态成员则每线程一份。静态成员函数可通过类名调用，不需要一个特定对象。extern 常用于声明实体，但不是“凡有 extern 都只声明”：`extern int x;` 通常是非定义声明，`extern int x = 1;` 是定义；已有声明也可能影响名字的链接，不能只看最后一个关键字。[182, 190]

`extern "C"` 指定语言链接，常用来声明与 C 库匹配的接口，并不把任意 C++ 类接口变成可供 C 使用的 ABI。跨翻译单元共享定义通常采用头文件声明、一个源文件定义并链接，而不是包含另一个 `.cpp`；extern 本身也不是编译速度保证。[191]

volatile 访问有实现定义的语义，可服务于平台规定的特殊访问，但不是“关闭一切优化”，也不提供原子性、互斥或线程间 happens-before。给共享停止标志加 volatile 不能替代 atomic 或锁；普通数据的发布仍须建立实际同步关系。[16, 52]

</div>
</article>

<article class="qa-item" id="qa-casts" data-level="principle" markdown="1">
<p class="qa-question">Q09 · 四种 C++ cast 各自适合什么？static_cast 向下转换安全吗？</p>
<div class="qa-answer" markdown="1">

`static_cast` 适用于语言允许的显式转换，但不等于带运行时检查；`dynamic_cast` 可在适用的多态层次中检查向下或横向转换；`const_cast` 改变允许的 cv 限定；`reinterpret_cast` 只提供语言列出的低层转换，不是任意类型之间的万能转换。运行时 dynamic_cast 检查失败时，指针结果为空，引用转换抛出 `std::bad_cast`；指针和引用因此需要不同的失败处理。[49, 50, 193, 194]

static_cast 可以在满足条件时把基类指针转成派生类指针，基类有虚函数也不禁止这样做；但它不会确认对象实际包含相应派生对象，错误假设可能导致未定义行为。虚基类等情形另受语言限制。dynamic_cast 也不是悬挂指针探测器，其源对象必须满足生命周期和类型要求。[49, 193]

const_cast 去掉限定后，只能在对象本来允许修改时通过相应路径修改；原本就是 const 的对象仍不能改。reinterpret_cast 得到另一种指针类型，并不单凭这个转换就保证对齐、对象生命周期或类型访问合法。网络字节协议还涉及字节序与布局，逐字段解码或复制到适合的对象通常比直接把字节缓冲当成结构体可靠。[50, 57, 194]

</div>
</article>

<article class="qa-item" id="qa-signed-overflow" data-level="principle" markdown="1">
<p class="qa-question">Q10 · 有符号溢出和越界移位为什么会破坏整个程序？无符号溢出为什么定义清楚？</p>
<div class="qa-answer" markdown="1">

C++ 对有符号整数运算不提供回绕语义：结果不可表示时是未定义行为，[285,287] 左移在右操作数为负或不小于提升后左操作数的位宽时也是未定义行为。[286] C++20 起补码表示被明确要求，这消除了表示形式的不确定性，却没有把溢出变成回绕。[287]

未定义行为的实际含义是编译器可以假设它不发生。优化器据此做代数化简、循环归纳与条件消除，例如把 `a + 1 > a` 视为恒真；一旦输入真的触发溢出，程序执行就不再由源码语义决定，可能随优化等级、编译器版本或内联结果变化。[285] 因此“在本机跑通”不能作为溢出安全的证据。

需要模运算时用无符号类型，其运算按模相应位宽定义，结果明确；需要保留有符号语义时显式检查边界，或使用编译器提供的溢出检查内建函数。还要注意有符号到无符号的转换在标准中有定义，但负值转换后参与比较会静默变成极大值，这类缺陷与溢出同样常见。

</div>
</article>
