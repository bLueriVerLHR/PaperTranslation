## 4. PCIe 与 CXL：两种节点内互连语义 {#pcie-cxl}

节点内的数据路径由一条通用总线承担：加速器、网卡、存储与主机内存都挂在它上面。这条路径的标称速率在第 2 章的表中与一个 400 Gb/s 网口处于同一量级，因此“节点内比节点间快得多”这个印象需要修正。本章说明它的速率是怎么算出来的、哪些开销要扣掉，以及在同一条物理链路上后来加上的那套内存协议改变了什么。

### 4.1 从标称速率到可用载荷

PCIe 是一条分层协议的点对点链路：设备挂在根复合体（root complex）或交换机下，通过基址寄存器窗口暴露自己的寄存器，工作请求以事务层数据包（TLP）的形式在链路上传递。文献给出的链路速率是每 lane 32 GT/s（PCIe 5.0），16 lane 约 64 GB/s；上一代 PCIe 4.0 为每 lane 16 Gbps [20]。

把 64 GB/s 当作可用载荷会高估。载荷与链路速率之间隔着三层扣减：物理层编码、事务层头部与校验、以及请求与完成之间的往返。用算式表示：

其中 <math><msub><mi>η</mi><mtext>enc</mtext></msub></math> 是编码效率，后一项是载荷占比。占比随单次事务的载荷大小上升：同样多的头部字节，拆成更多小事务就要多付几次。具体比例取决于事务大小与设备行为，本篇不引用未经核对的取值；可核对的部分是这条关系的形式——小事务的有效带宽低于大事务，且这个差距与硬件无关。

链路上的固定延迟则是另一回事。文献引用的 PCIe 4.0 链路传输约 40 ns，与之对比的总线（DDR4）小于 1 ns [20]。这 40 ns 只是链路本身，一次设备访问还要加上控制器处理、根复合体转发与事务排队。

### 4.2 读与写不对称

同一条链路上，读与写的代价结构不同。读请求需要一次往返：请求送到设备，设备准备数据后作为完成包送回，链路上出现两次传输机会与两次排队。写请求可以被缓冲、合并，由链路与设备异步消化。于是等效字节数相同时，读对延迟更敏感，而写更依赖缓冲深度与背压处理。

这个不对称在软件接口上有对应物。Linux 的 DMA 接口把映射分成两类：一致映射用于在缓冲区生命周期内被 CPU 与设备反复访问的结构，流式映射用方向参数声明数据流向（到设备、从设备或双向），面向单次传输 [24]。方向声明让系统可以选择更便宜的同步方式，也让驱动作者必须明确数据的所有权何时转移。

### 4.3 CXL：在 PCIe 物理层上加三种协议

CXL 复用 PCIe 的物理层，在其上定义三种协议：**CXL.io** 沿用 PCIe 的协议特性用于配置与 I/O，**CXL.cache** 让设备参与主机内存的一致性，**CXL.mem** 让主机把设备附加的内存当作内存来访问 [20]。设备按支持哪些协议区分用途：只做容量扩展的设备不需要缓存一致性协议，而带本地内存或缓存的加速器会同时用到后两者；联盟的规范页把这类设备列为 Type 1／2 加速器 [20][26]。

三种协议的差别落在时延与一致性状态上。走 CXL.mem 的访问由主机侧代理（host agent）处理，对上层表现为一块可寻址的内存；除了第 4.1 节那 40 ns 链路传输，还要加上代理、控制器与一致性状态的访问开销。文献在同一平台上比较了真实 CXL 设备与用本地内存模拟的 CXL，报告真实 CXL 内存的延迟最多低 26%、带宽效率高 3–66% [20]。这两组数字说明仿真与真实实现之间存在系统性差别，因此把仿真结果当作 CXL 硬件性能的做法不可靠。

容量扩展的收益还受页迁移影响。文献报告把最多 50% 的页面放到 CXL 内存上可带来约 24% 的改善，同时指出页迁移本身有开销，且延迟敏感型应用的尾时延会上升 [20]。也就是说，CXL 提供的是“多一层可寻址内存”，而把哪一页放在哪一层是一个需要策略的问题，不是插上就能得到的加速。

### 4.4 与 RDMA 的分工

CXL 与 RDMA 都让一台机器访问另一处的内存，但语义不同。CXL 走的是加载／存储语义：远端内存在地址空间里，访问由硬件完成，程序不需要显式提交；RDMA 走的是消息语义：发送方或接收方显式提交一次操作，对端内存需要事先注册并携带访问键（第 14 章）。前者的代价藏在一致性协议与代理里，后者的代价摆在注册、提交与完成通知上。

由此可以得到一条选择规则：需要“像本地内存一样”追加容量时，一致性与可寻址性是关键，CXL 更合适；需要把一批数据交给远端计算单元时，显式提交与完成通知更重要，RDMA 更合适。两者不是同一条路径的两个版本。

统一内存是同一组代价的另一种形态。Grace Hopper 用缓存一致互连把 CPU 与 GPU 连成一体，两侧共享可寻址内存；文献研究其首触页策略与页迁移后发现，即使有硬件一致性，带宽与延迟限制仍然决定应用的收益 [23]。一致性解决的是编程模型与协议开销，不改变第 2 章那张表里的字节数与速率之比。

### 4.5 节点内路径如何进入总账

节点内的代价按跳累加，这一点在暂存路径上最明显。没有设备直达能力时，一份数据从 GPU 送到网卡要经过：GPU 内存 → 主机固定内存（一次 PCIe）→ 网卡（再一次 PCIe），中间两次经过主机内存控制器。按第 2 章的账，1 GiB 经一次 PCIe 5.0 ×16 约 16.8 ms，两段相加至少约 33.6 ms；而直连路径只需一段。这就是设备直连（GPUDirect RDMA）在系统层面对应的收益来源：省掉的不是协议，而是整整一跳 [8]。

更一般的界在第 5 章给出：一条串联路径的稳态吞吐不超过其中最窄一段的速率，短消息还要另付各段固定延迟。因此判断节点内是否会成为瓶颈，要问的是“这条路径上最窄的一段是谁、有几跳”，而不是“总线是多少代”。
