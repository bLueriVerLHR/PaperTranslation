# 源码书稿维护说明

本书按“前端抽象 → 中间表示与 Pass → 后端代码生成”三段组织，一个技术对象一章，最后用一条贯穿算子的对照与一章代价边界收尾。每章先交代该栈的结构与执行链，再依据仓库自身文档、注释和维护者材料说明它要解决的负载问题，最后解释设计回应、代价与适用范围。正文的机制解释以固定提交的静态阅读为依据；本书不编译、不启动、不部署这些上游项目，也不运行它们的测试、benchmark 或消融。

## 内容与顺序分离

- `content/*.md` 是唯一正文源，一级文件对应一章；每章通过 `{{include:...}}` 组合其下的子稿。
- 子稿按独立技术对象拆分，不按行数截断；父稿只保留章节标题、必要的过渡与阅读顺序。
- 阅读顺序由文件名前缀与 `meta.json` 的 `sections` 共同固定：前端 `02`～`05`、中端 `06`～`09`、后端 `10`～`12`、对照与边界 `13`～`14`。插入新主题时取相邻编号的字母后缀（如 `03b-`），并保持既有文件不迁移。
- 每章一级标题带稳定 ID，跨章引用使用该 ID，不使用“上一章”“下一节”一类依赖排序的说法。

## LLVM 部分的来源与体例

本书的 LLVM 部分（`content/llvm/`、`08-llvm.md`、`09-llvm-loops.md`、`10-llvm-backend.md` 三章）原为一本独立的 LLVM 编译优化教程，按决定并入本书后保持正文与锚点不变，只做两处机械调整：文件移入 `content/llvm/` 并按父稿层级把标题降一级。它原有的体例特征——带可执行检查顺序的对照实验（`llvm/practice.md`）与源码控制流走查（`llvm/source-walkthrough.md`）——保留原样，并仍然只作为验证方案，不声称已在本机运行。原书的统计口径是“五个栈”，并入 TileLang 与 LLVM 自身后，凡涉及数量的表述统一改为当前对象的实际数目，锚点不变。

## 来源与版本

- 各仓库的固定提交记录在 `meta.json` 的 `source.repositories`；正文用仓库名标识路径（如 `tvm/src/tir/...`、`tilelang/src/op/...`），检索时从工作区根 `repos/<仓库>/` 继续定位，不另建源码副本。
- 源码摘录前的可见说明包含仓库、固定提交短标识、仓库相对路径、真实行范围与符号名。行号只对该提交成立。
- 摘录前检查检出状态；工作树与固定提交有差异时以 `git show <commit>:<path>` 为准并在正文说明。
- 教学伪代码、源码摘录、机制推导与仓库中已记录的故障或实验报告必须分别标注。没有核实的历史动机不补写。
- 上游许可与归属保留在 `reader-meta.md`；片段及其分析不因进入本库而获得 MIT 授权。

## 写作与术语

- 术语单一来源为 `glossary.md`，`reader.json` 的 `show_glossary` 把它渲染进阅读页；修改用语时同步正文。
- 引用记录在 `reader.json` 的 `references`，采用 author-year 形式；新增论文先核对题名、作者、稳定标识与实际版本。
- 章节内的数值与复杂度结论保留前提；本机没有测量过的量不写成实测结果。
- 随机访问的维护索引、临时检查脚本与扫描报告保存在系统 TEMP，不进入正文源目录。

## 重建

在仓库根目录执行：

```powershell
. .\tools\dev-env.ps1
& $Python dist\dl-compiler-review\work\rebuild.py
```

规范源稿位于 ignored `dist/`，不加入 main。重建只更新本地阅读页；公开快照仍需 reader-only 导出验证与审批，且不改变上游许可状态。
