### 记法与谱系

#### 四个分开记的量

比较注意力机制先要把“省了什么”落到具体单位上，否则缓存小、显存少、时延低会被混成同一件事。四个量分开记，每个机制在这四项上各有自己的取值。

缓存元素数 E 指每层每个历史位置留下的元素数。MHA 让每个查询头各有一套键和值，因此 E 随查询头数线性增长：

<math display="block"><msub><mi>E</mi><mi>MHA</mi></msub><mo>=</mo><msub><mi>H</mi><mi>q</mi></msub><mo>(</mo><msub><mi>d</mi><mi>k</mi></msub><mo>+</mo><msub><mi>d</mi><mi>v</mi></msub><mo>)</mo></math>

取 Hq=128、d_k=d_v=128，每层每个 token 是 32,768 个元素，按 2 字节存储合 64 KiB；乘上上下文长度与层数，这个数就换到 GiB 量级。

每步读取量指解码时一次前向要搬进计算单元的元素数。显式缓存的机制每步都要读全部历史，读取量约为 <math><mi>E</mi><mo>·</mo><mi>N</mi></math>。沿用上面的配置，设 60 层、上下文 32K，每个 token 的缓存是 3.75 MiB，整段约 120 GiB；按 3 TB/s 的量级取带宽，每生成一个 token 至少也要 40 ms。这是按规格值推的量级估算，不替代具体设备上的测量；解码阶段的瓶颈因此在搬运：算术量只与当前这一个查询有关，读取量却与整段历史成正比。

每 token 乘加量决定算力需求。按一次乘加计两次浮点运算，忽略投影与逐元素开销，因果注意力的成对项在序列长度上走二次：

<math display="block"><msub><mi>F</mi><mi>attn</mi></msub><mo>≈</mo><mn>2</mn><msub><mi>H</mi><mi>q</mi></msub><msub><mi>d</mi><mi>h</mi></msub><msup><mi>N</mi><mn>2</mn></msup></math>

状态矩阵大小只对递推类机制有意义。把历史压进一个矩阵状态时，状态是 <math><msub><mi>d</mi><mi>v</mi></msub><mo>×</mo><msub><mi>d</mi><mi>k</mi></msub></math> 个元素，与历史长度无关；同样的 128 维配置下是 16,384 个元素、32 KiB，比上面一个 token 的显式缓存还小。这个对比也带出它的代价：状态不再逐位置可寻址，能同时保存多少条互不干扰的键值关联，取决于它的维数，这一点在 delta 规则一节会算成具体的容量上限。

四个量之间没有固定换算。压缩缓存宽度的机制可能抬高每头算术量，缩小状态的机制会丢掉逐位置检索能力，减少读取集合的机制要多付一份选择开销。后文每节都会交代改的是哪一项、另外三项怎么变。

#### 谱系表

下表按机制在主线上出现的位置排列，发表年份不决定次序。前驱一栏指它直接依赖的结构，代价一栏只写这一机制自身新增的开销。

| 机制 | 改变的量 | 直接前驱 | 新增代价 |
|---|---|---|---|
| MHA | 基线：每头独立 K／V | 缩放点积注意力 | 缓存与解码读取随 Hq 增长 |
| MQA | KV 头数降到 1 | MHA | 键值表示被全部查询头共用，表达能力受限 |
| GQA | KV 头数降到 G | MQA 的头共享、MHA 的多头打分 | 需要继续预训练以恢复质量 |
| MLA | 每个位置的存储对象改为潜在向量 | GQA 的共享思路、低秩投影 | 表示受瓶颈维数约束、位置分支必须解耦 |
| 核化线性注意力 | 求和顺序改为可累计状态 | 注意力的核函数写法 | 有限维特征装不下指数核 |
| RetNet | 状态上加逐头标量衰减 | 核化线性注意力 | 固定的衰减形状，与内容无关 |
| DeltaNet | 写入改为误差修正 | 线性注意力的加法写入 | 每步一次矩阵—向量读写、需要并行化算法 |
| GDN | 衰减改为输入相关，并与 delta 复合 | DeltaNet、Mamba2 | 转移矩阵带门控，分块算法要重推 |
| KDA | 衰减从每头标量细化到逐通道 | GDN、DPLR 结构 | 每头多一组低秩投影；三角逆仍串行 |
| Mamba／RWKV | 换掉注意力，用选择性状态或通道衰减 | 连续时间状态空间、线性注意力 | 依赖专用扫描内核，检索能力另有短板 |
| SWA | 把可读位置限制成固定窗口 | MHA | 远距离依赖只能靠层数堆积 |
| NSA | 压缩、选择、窗口三分支并联 | SWA、块选择类方法 | 三分支各有投影与门控，索引项仍是二次 |
| DSA | 用轻量索引器选 token，主分支走 MLA | MLA、Top-k 选择 | 索引扫描、选择误差、历史状态照旧保存 |
| MSA | 按 GQA 组选 token 块 | GQA、DSA 的选择框架 | 块内冗余、二次索引项 |

#### 表的用法

三者之间是一条因果链：MHA 的缓存随头数增长，于是有了共享；共享到极限就损失表示能力，于是有了低秩压缩；压缩只减宽度不减位置个数，于是有了递推与选择。

表中相邻两行不表示替代关系。同一时期的不同工作可以并行存在，例如 GDN 与 RWKV-7 都在 delta 规则上加门控，但一个把门控做成每头标量、另一个做成通道向量，落地方式也不同。各行报告的加速比与质量分数都带有各自的底座、数据与硬件条件，正文引用时保留这些条件，不做跨行排名。
