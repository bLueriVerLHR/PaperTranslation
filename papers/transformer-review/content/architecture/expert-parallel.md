### EP：专家怎么分布，token 怎么往返

MoE 决定用哪些参数，专家并行（Expert Parallelism，EP）决定这些参数放在哪张卡上、输入怎么送达。上万专家的权重放不进单卡，于是按专家切分到多设备，token 隐藏状态以数据的形式流动到专家所在地执行。单卡也能跑 MoE，采用 EP 也不要求一张卡只放一个专家。Switch 的并行分析和 DeepSeek-V3 的通信设计都把分派与返回当作关键成本。[31, 33]（分别见 §5.4–5.5、§3.2）

#### 一次前向要两次重排

设一个 EP 组内共有 T 个 token、隐藏维度 d、每个 token 选 k 个路由专家，且不发生容量丢弃。原始 token 矩阵是 `X: [T, d]`，路由给出 `expert_ids: [T, k]` 与 `gates: [T, k]`。本地的排列方式是“按原序列位置”，专家却要求输入按专家归组，中间必然有一次重排：

```text
原始 token、来源位置 [T, d]
    → 路由：每个 token 的 k 个专家编号与门值
    → 打包：按目标设备／专家重排，同时记下逆置换和有效长度
    → dispatch：把输入隐藏状态送到持有该专家权重的设备
    → 专家计算：本地专家对自己的 token 批做矩阵乘
    → combine：把各分支结果送回来源设备
    → 按逆置换还原并乘门值求和，恢复 [T, d]
```

发送端至少要保留原 token 编号、分支身份、门值和返回映射；接收端需要每个专家的有效计数与偏移，才能把零散 token 拼成规整的 token 批。输入先按目标分桶，到达后再按本地专家归组，逐 token 的小操作才可能合并成分组矩阵乘。dispatch 与 combine 一般走 all-to-all 或等价的分层／点对点通信，只把 token 送到它选中专家所在的设备。[31, 33]（分别见 §5.4、§3.2.1–3.2.2）

combine 做的是带权求和。一个 token 的 k 个返回值分别乘各自门值再相加，结果才等于 MoE 的数学定义。同设备上有多个入选专家时，输入和返回值都能在本地合并或归约，网络上的实际包数因此低于 T·k，逻辑分支数仍是 T·k。

举个具体例子：设备 A 持有专家 0、1，设备 B 持有专家 2、3。位于 A 的 token u 选中专家 1 与专家 3，门值 0.7 与 0.3。A 本地执行专家 1，同时把 u 的隐藏向量发给 B 的专家 3，返回后拼出 `0.7 * F1(u) + 0.3 * F3(u)`。这里跨卡移动的是激活，专家权重在前向期间一直驻留；返回映射若丢失，专家输出的数值仍然正确，却会写到错误的位置上。

反向传播沿相反的数据依赖走：输出梯度按原路回到各专家，专家输入梯度汇合，权重梯度在自己所在的设备上累积。训练整步的通信次数超出前向的两次重排，同一专家若在多个并行组里有副本，还要同步副本梯度。

#### EP、TP、DP、PP 各自划分什么

| 并行方式 | 划分或复制的对象 | 主要的数据关系 |
|---|---|---|
| 专家并行（EP） | 专家分布到不同设备 | token 按路由送到目标专家，再返回 |
| 张量并行（Tensor Parallelism，TP） | 同一个矩阵或算子的张量维度 | 多设备合力完成一次计算，交换或归约部分结果 |
| 数据并行（Data Parallelism，DP） | 参数副本处理不同数据 | 训练时同步相应参数梯度或分片状态 |
| 流水线并行（Pipeline Parallelism，PP） | 不同层位于不同阶段 | 激活与梯度在相邻阶段流动，依赖微批调度 |

四种划分可以叠加：一个专家内部再做 TP，不同 EP 组互为专家副本，不同层分给 PP 阶段。每层叠加都需要单独定义通信组与参数所有权，并行度不能简单相乘。[31]（§5）

#### 通信预算由跨设备分支数决定

设 R 为真正需要跨设备传输的 token—专家分支数，输入输出都是 d 维、每元素 b 字节。不做同目的地去重与本地归约时，一程输入加一程返回的有效载荷合计：

每条跨设备消息计一次，发送端与接收端不重复累加，得到的是张量载荷；链路累计字节是另一个量。计数、索引、门值、填充、分层转发、反向通信与重传另算。代入 T=4,096、k=2、d=4,096、b=2，并假设全部分支都跨设备且不合并，两程合计 128 MiB。这个数字只说明张量本身要搬多少，不预测时延。

总专家数增多并不直接抬高这个量：k 固定时，路由扇出的上界不随 E 变化。变化的是别的地方：每位专家分到的 token 变少，矩阵乘变碎，EP 组扩大后通信可能跨到更慢的互联层级。小批量解码同时受通信启动成本与小矩阵利用率的限制，大批预填充则更容易凑出可观的专家批。

DeepSeek-V3 把节点限制路由与节点内转发配合起来：先限制一个 token 的远端节点数，进入节点后再用节点内的高带宽链路分发给多个目标专家。[33]（§2.1.2、§3.2.2）“选中专家数”与“跨节点输入副本数”由此可以不同。限制路由收窄了可选专家集合；通信与计算重叠只在依赖允许、资源足够的条件下隐藏时间，要传的字节并不会因此减少。这些实现效果来自 H800 集群的具体配置，换一套互联、批量与负载分布，结论需要重新测。
