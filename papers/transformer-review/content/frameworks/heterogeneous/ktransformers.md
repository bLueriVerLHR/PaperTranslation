#### ktransformers：MoE 专家与主存旁的计算

MoE 为一个 token 选择少量专家，但全部专家权重仍须可访问。权重总容量可能远大于某次执行的激活量。ktransformers 的 `kt-kernel/`、`ktransformers/` 及历史实现，探索把部分专家权重留在主存并用 CPU 内核计算，把其他热点留在 GPU。具体放置随模型与配置而变。

它利用的是模型 router 给出的专家级选择，不需要像神经元稀疏方案那样猜测全部激活。CPU 计算可以避免每一步把完整专家权重搬入 GPU，却要传递激活和路由结果，受主存带宽、CPU 矩阵运算、NUMA 与同步限制。MoE 的瓶颈随 batch 与专家集中程度变化，容量之外还可能是算力或通信。

设一次路由所需专家权重为 We 字节、对应输入与输出激活合计为 A 字节。在专家留在 CPU 的组织下，跨设备传输主要趋向激活规模 A；先传输 We 再在 GPU 执行是另一种组织方式。容量收益来自总专家权重驻留主存。这个数据移动比较只覆盖搬运量与放置，时延还取决于 CPU 计算与同步。批量增加后，多个 token 访问同一专家可能更适合集中矩阵运算，热点分布变化也会改变放置收益。瓶颈从显存容量移到 CPU／主存之后仍然存在，这解释了容量门槛下降与全 GPU 吞吐之间的差异。
