#### vLLM-Ascend：框架接口之外的硬件适配

vLLM-Ascend 用 `vllm_ascend/platform.py` 对接平台，`attention/`、`quantization/`、`worker/` 与 `csrc/` 承担实际执行，CANN／ACLNN 和通信相关实现替代 CUDA 路径。这里迁移的是设备、内存、算子、图、状态布局和分布式约定，规模远超一个 Python 函数。

平台接口把设备差异集中起来，实际 kernel 仍要实现与上层相容的掩码、精度、布局和缓存更新语义。数学公式相同，归约顺序与低精度舍入也可能不同；换一个注意力后端又会改变哪些形状或 KV 格式可以执行。`patch/` 的覆盖实现说明部分行为仍依赖上游内部约定，内部对象和调度生命周期改变时，适配代码也可能需要同步修改。

后端迁移因此具有三层相容性：单算子的数值与边界、缓存及图执行的状态约定、分布式和服务的请求约定。相同 API 只覆盖最外层形式，不能证明页复用、异步取消或多 rank 采样仍保持一致。专用后端的价值在于把通用框架组织接到实际硬件能力，维护代价则来自这些跨层约定的持续耦合。
