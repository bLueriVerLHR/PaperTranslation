#### llama-server：共享批与状态线程

`tools/server/README-dev.md` 描述 server context、slot、请求／结果队列与 HTTP 层。多个兼容 slot 将提示词或上一轮生成 token 放入共享 batch，再调用 `llama_decode`，因此它已经包含连续批处理。批组成仍受配置相容性和容量约束。

模型状态由专用执行路径维护，JSON 解析、模板和响应格式化放在 HTTP 处理侧。把可并行的格式化移出状态热路径，能减少多序列生成互相干扰。流式重连若使用保留缓冲，需要限制会话容量并保持所有者隔离；它恢复的是输出传送，模型状态容灾是另一回事。

router 和 sleep 路线分别处理多模型入口与空闲资源释放。若偶发请求服务长期占内存，卸载上下文可以节约常驻量，但下一请求承担恢复成本；健康检查应避免意外触发模型重载。模型生命周期和每个 token 计算是两种优化对象。
