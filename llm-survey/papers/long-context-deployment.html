摘要译文

基于 Transformer 的长上下文生成模型支撑着诸如小时级视频理解与项目级编码 Agent 这类新兴 AI 应用。但部署长上下文 Transformer（例如 100K 到 10M token）相比短上下文（例如 4K token）的模型变体，成本高得令人却步。自 2024 年起，降低长上下文 Transformer 的成本已成为紧迫的研究与工程挑战。本工作描述了一个并发编程框架，用于定量分析在 GPU 高带宽内存（HBM）容量有限的条件下服务多个长上下文请求时面临的效率挑战。我们详细分析了：相比 4K 上下文，所有额外计算成本如何都追溯到同一个来源——KV cache 体积过大。我们以在 A100 NVLink 上运行的一个 50K 上下文、GPT-3.5 级别的 34B 模型为实例，描述其庞大的 KV cache 造成的四类部署挑战：(1) 预填充长输入相比短输入要花多得多的计算时间与 GPU 内存；(2) 预填充完成后，常驻 GPU HBM 的庞大 KV cache 大幅限制了可并发服务的用户数；(3) 解码期间反复把 KV cache 从 HBM 读入 SM 显著抬高延迟；(4) 当 KV cache 内存溢出时，把它从 HBM 换出到 DDR 会造成可观的上下文切换延迟。我们使用该框架分析已有工作，并识别出把它们组合成端到端系统的可能性。总体而言，本工作为分析长上下文 Transformer 部署提供了一个基础框架，并指出了把 1M 上下文的推理成本降到与 4K 一样便宜的方向。

阅读说明与边界

该文是理论峰值性能分析；成本归因依赖其模型与假设，不应把“所有额外成本来自 KV”当作一切长上下文架构的普遍定理。
