1 机器学习系统：执行效率优化

1.1 先定位瓶颈，不要先选加速库

预训练通常追求有效训练吞吐，后训练兼顾适配成本与行为质量，在线推理则同时受首 token 延迟（TTFT）、逐 token 延迟（TPOT）、尾延迟与成本约束。用户真正需要的是满足质量和延迟约束的吞吐，不是脱离服务目标的最大 tokens/s。

1.2 复读与文本退化：模型在推理时输出平淡、重复、无意义的文本

现象与原因。 这里指的不是模型答错，而是它在推理阶段生成平淡、重复、无意义的文本：重复可以发生在有限输出中，也可能演化成直到 token 上限仍不终止的循环。后者同时浪费预算、拉长尾延迟、阻止上层 Agent 进入下一步。困惑度与任务平均分不足以覆盖它，需要单独测循环率、结束率和结构合法率。虽然现象直到推理才暴露，修复却可能落在训练、解码或服务任一阶段。

三条研究线索互补：Holtzman 等研究似然最大化解码的退化；Unlikelihood 直接压低不希望出现的重复候选概率；SimCTG 从表示空间各向异性入手。解码一致性工作在其循环语言模型框架下证明某些常用不完全解码算法可能生成无限序列；这不是「所有现代 Transformer 每次都会无限复读」的定理，也不是唯一根因。

不能混淆惩罚参数。 frequency penalty 随出现次数变化；presence penalty 通常只看是否出现；常见 repetition penalty 则按已出现 token 调整 logits，未必按次数累积。它们都可能压制 JSON 中合法重复的字段或标点，但不是所有实现都有同一公式。结构化输出应配合 grammar/schema 约束与结束条件；一味加惩罚或降温未必有效。

1.3 MoE 批推理：单 token 稀疏，整批却几乎访问全部专家

生产现象。 单个 token 选 k 个专家，但批内不同 token 的路由并集随批增大而扩展。在均匀、独立选择的简化模型下，E 个专家、B 个 token 的期望激活专家数是 E × [1 − (1 − k/E)^B]；真实路由有相关性和偏斜，应以测量代替这个近似。这解释了为什么「单 token 激活参数少」不能直接推导出「整个批权重读取少」。

重要限定：批内访问所有专家并不会使每 token 都计算所有专家。 条件计算的 FLOPs 稀疏性仍然存在；变化的是权重访问覆盖、权重复用、每专家矩阵乘的形状，以及 all-to-all 和负载均衡成本。大批也可能改善专家 GEMM 的利用率，因此不能简单说批越大 MoE 越慢。

另一个约束是常驻专家权重与 KV cache 竞争 HBM。长上下文减少可容纳请求数，路由又把每专家的微批切碎，于是可能同时损失并发和权重复用。比较 MoE 与 dense 时，应同时对齐质量、精度、硬件、上下文、并发与延迟目标。

三个词的含义。 本方向的全篇都围绕这三件事：“装得下”指接口允许的上下文长度；“算得动”指 prefill 与 decode 的实际成本；“找得到”指模型能否真正用上窗口里的关键证据。三者互不代替——窗口放得进不等于算得起，算得起也不等于找得到。

2.2 线性自注意力：把注意力改写成递归状态，换取线性成本

为什么能线性？ 将注意力相似度写成特征映射的内积后，可先把历史 key 和 value 聚合，再由 query 读取。以带归一化的因果核注意力为例：

St=St−1+φ(kt)vtT,zt=zt−1+φ(kt)

yt=φ(qt)TStφ(qt)Tzt

其中 S 保存键值外积的累加，z 用于归一化；实现还需处理数值稳定性。在特征维度固定时，处理 N 个 token 的成本随 N 线性增长，decode 不必随历史长度保存每个位置的 KV。但状态矩阵仍有特征维度 × value 维度的成本；「长度线性」不是对隐藏维度也线性，更不表示训练激活完全不随长度增长。

为什么不是免费午餐？ 普通 softmax 不能直接靠交换括号得到完全相同的结果。Linear Transformer 更换了核形式，Performer 用随机特征近似 softmax。有限状态将多个关联叠加，彼此可能干扰；精确复制任意很早的标识符、检索大量键值，与压缩全局语义不是同一种难度。

验收矩阵。 图像覆盖尺寸、文字大小、对象数量、遮挡与不存在对象；视频覆盖时序反转、短时关键帧、多个相似事件；服务覆盖预处理队列、峰值显存、TTFT、TPOT 和多租户尾延迟。训练参数更少与在线视觉成本更低是两件不同的事。

5.5 VLA 是多模态的一种应用：输出从文字变成动作之后，要求发生了什么变化

前面四节的输出都是文本，写错了可以重生成。VLA 把同一条视觉—语言通路接到动作上：视觉观测和语言指令映射为动作，研究目标不只是识别物体，而是让机器执行任务。语言答案可以重生成，物理动作不能随意重试，这条差异把多模态的可靠性要求整体抬高了一档。

数据往往来自昂贵的真实机器人演示，失败还涉及设备和人员风险。因此「网页知识迁移到动作」与「跨机器人共享经验」成为两条主线。

本节同时纳入 RT-1、Octo 等通用机器人策略作为前置脉络；它们不都以大型语言模型为骨干，不应因接收语言指令就一概称为同类 LLM-VLA。

6 Agent：把一次回答变成有反馈、可验证的任务执行

内部指代。 下文的“行动”指模型请求调用的一次工具或一次环境操作，“观察”指工具或环境返回的结果；两者交替循环，就是 Agent 的执行过程。

6.1 生产问题：模型能说出步骤，却不能可靠地完成整件事

Agent 是 LLM 的通用应用形态，而不是必须新增一种模型架构。它围绕目标反复进行观察 → 决策 → 工具行动 → 检查结果，维护任务状态并决定继续、恢复或停止。固定流程适合边界清晰的任务；只有当下一步依赖运行中的观察时，才有充分理由引入更自由的 Agent。多 Agent 也不是默认升级：通信、重复上下文与责任划分会增加成本。

6.6 Agent 服务：一次用户请求会展开成多次模型调用，不再彼此独立

一个用户目标会产生多次模型调用、工具等待和不断增长的历史。模型 tokens/s 很高，端到端任务仍可能慢在搜索、浏览器、测试或串行依赖上。应同时记录任务成功率、每成功任务成本、总墙钟时间、工具等待比例、重复调用率、人工接管率与安全违规数。

缓存要区分三层：任务记忆保存语义状态；prefix/KV cache 保存可复用的模型计算；工具缓存保存外部结果。摘要压缩可能改变前缀并降低 KV 复用，外部工具缓存可能过期，语义记忆又不能替代真实环境状态。保留稳定系统提示、明确会话边界、在独立无副作用任务上并行，是可以评估的工程方案，不应直接假定一定更快。
