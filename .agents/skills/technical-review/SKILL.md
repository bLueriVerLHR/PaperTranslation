# 证据型技术综述

本 Skill 是研究到成稿的流程，不是固定章节模板。相对链接以本目录为基准；仓库根目录是本目录的上三级，命令从仓库根目录运行。

## 准备

1. 明确综述问题、研究对象、受众、范围与已有材料。若范围已经明确，不重复扩大成“搜齐整个领域”。按 [工作流](../../../docs/workflow.md) 优先复用本地来源和已有核对记录。
2. 完整阅读 [中文写作规范](../../../docs/chinese-writing.md) 和 [综述方法](../../../docs/review-method.md)；有实现分析时另完整阅读 [源码解读规范](../../../docs/source-analysis.md)。读取项目 `work/README.md`、词表、相关来源图谱和完整受影响章节。
3. 确认本任务是原创综合，而非给某篇原作换标题。源论文的“我们”不自动成为本文作者；原文译稿即使保存在本地，也不直接复制成原创综述。

## 证据与综合

1. 先写出要解决的问题，再选择来源和暂定分类。分类依据作用对象、机制或假设；允许资料迫使分类改变，不先固定栏目再编内容填空。
2. 在现有本地研究记录中保留最小证据联系：具体断言、来源身份与版本、章节/页码/代码定位、证据类型、关键条件和未决项。沿用已有结构，不要求每篇都新增一张相同表格。只核对过题名或摘要的条目不能标成全文/算法已核验。
3. 具体方法、数字和实现优先回到原始论文或固定源码。综述用于发现脉络；产品宣传、社区经验、静态代码与原论文实验分别归属。新增检索只解决一个明确缺口，超时就保留待查或收窄论断。
4. 按主题写共同问题、机制差别和条件，而不是“A 论文说、B 论文说”。解释设计改变为何可能带来收益，以及增加的计算、存储、同步、质量或维护成本。数学推导保留前提；数学性质不替代经验效果。
5. 跨研究比较先对齐任务、数据、模型、硬件、精度、批量和指标。无法对齐的结果分开陈述；负结果或相反结论不因破坏分类整齐而删除。
6. 引文检索服务是可选证据入口，不是质量裁判。按 [引文语境核查](../../../docs/review-method.md#引文语境与可选服务) 回读支持/反驳的具体句子及其条件；不把分类标签、引文语句数或引用量直接当成真伪、独立研究数量或性能排名。服务不可用时用本地原文继续，不能声称已调用。

## 成稿与验收

- 按论证需要安排问题、分类、方法、比较、局限与开放问题，不强制这些成为相同标题；没有证据时不编“趋势”或“未来方向”。来源与写作记录留在维护资料，不成为正文方法宣言。
- 统一项目术语但不合并不同概念；短代码摘录、原生 MathML、引用和离线资源沿用现有接口。稿件、证据记录与一次性检查报告按 [工作流](../../../docs/workflow.md) 分开保存。
- 做独立阅读检查：读者能否仅从章节中辨认比较对象、主要机制、证据条件及仍不确定的结论？同一模型自查不称为独立审稿；未获授权不自动启动新代理。
- 在交付消息中分开报告身份核对、具体断言核查、语言修订、结构/构建检查和剩余缺口。工程测试不能证明综述观点正确。
- 不默认安装插件、连接 Scite/Google Docs、上传私有稿件、跑上游测试或实验。原创稿是否公开仍需单独审查和授权。

## 小例子

两篇论文分别报告不同 GPU、不同批量下的时延。可以解释各自机制和报告条件，但不能把两组数直接排成“更快”的总榜。某条引文被服务标成 supporting，也不能替代阅读它究竟支持哪个结论。
