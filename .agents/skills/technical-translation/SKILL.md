# 忠实技术翻译

本 Skill 是原文对照流程，不是统一学术化或补写技术论证的模板。相对链接以本目录为基准；仓库根目录是本目录的上三级，命令从仓库根目录运行。

## 准备

1. 明确来源、实际版本、翻译范围、原作体裁和已有规范源稿。没有原文时不能声称完成忠实度审校；先询问必要材料，或明确只能做语言候选修订。
2. 完整阅读 [中文写作规范](../../../docs/chinese-writing.md) 及项目 `work/README.md`、`work/glossary.md`、相关来源记录和完整受影响章节。按 [工作流](../../../docs/workflow.md) 保留一次准备，不逐段重读全部手册。涉及实现解读的新增内容另遵循源码分析规范，不借翻译任务扩大范围。
3. 核对源身份与权利边界。受限发表版本先寻找身份和许可可核实的适配预印本；arXiv 可访问不等于允许改编。读取外部 PDF 原件，不复制进仓库。
4. 以既有术语表为准。术语记录采用现有格式，至少能辨认原词、本篇用语和概念范围；必要的语境说明可以保留，但写作指令、章节对应和批次记录放非渲染维护文件。

## 逐节翻译与对照

1. 按源顺序一次处理一节。保留原作者的定义、假设、推导、技术表格和题名讨论；随笔保留第一人称与试探语气，论文保留学术论证。不要把原作改成综述、访谈或答题脚本。
2. 为每个完整段落核对主体、否定、量词、条件、比较基线、因果和不确定性。允许拆分英文长句，但不得把 may 写成必然、up to 写成平均值，或删掉 when / only if 的适用条件。
3. 核对术语后再改善中文句法。标识符、产品/API 名、代码和稳定锚点保持原样；标准中的规范性要求按 [写作规范](../../../docs/chinese-writing.md#翻译保留原作体裁与边界) 处理。首次解释帮助理解，不强制每个词都加一对英文括号。
4. 原文疑似错误、身份歧义或资料缺失记录为待查，不静默“修好”。必要译者注应与原作者叙述明确区分；不因本项目重视机制解释，就给译文补入原作没有的证明、实验或历史动机。
5. 英文作者名单与参考文献保留；逐项对照数字、单位、公式结构、图表引用和引文。公式交付遵循原生 MathML；不借外部 Skill 改换数学运行时。

## 归属与验收

- 原作论述在 `work/content/`。必要译名与简短语体说明归标题下“出处与说明”：分别维护 `work/glossary.md` 和 `work/reader-meta.md`，不复制成正文第一章。
- 章节标题直接在对应位置翻译；中英章节对照、段落映射和写作约定只留非渲染维护资料，不能塞进出处说明。归属按来源与用途判断，不按“术语”“标题”关键词删掉原作者内容。
- 按工作流核对实际 HTML 的正文起点、目录、展开后的出处说明、锚点与离线资源。术语表显示开关按 [阅读页接口](../../../docs/reader.md#visible-terminology-from-one-canonical-glossary)，不发明新指令或局部 CSS。
- 区分原文对照审校、结构/语言覆盖和构建检查。结构计数一致不等于语义正确；交付消息说明实际核对范围和未决项，不把检查报告写进正文。
- 计划、一次性对照报告和试验在绝对系统 TEMP；规范译稿与有用参考记录保留在项目 `work/`。不默认上传全文到外部服务，不发布本地论文译文，不自动委派其他模型。

## 小例子

原文：“We suspect X may help only when Y holds.”
译文应保留“我们推测”“可能”“仅在 Y 成立时”，不能润色成“X 能够有效改善”。若要求精修一节，不能顺便新增全篇标题翻译表或更换所有术语。
