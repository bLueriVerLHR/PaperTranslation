# 中文技术写作

本 Skill 是执行入口，不是文章模板，也不覆盖项目约束。所有相对文件链接以本目录为基准；仓库根目录是本目录的上三级，命令从仓库根目录运行。

## 准备

1. 先确认读者、技术对象、修改范围和交付用途。复用用户已给的信息，只询问阻止继续的缺口，不对每章重复访谈。
2. 完整阅读 [中文写作规范](../../../docs/chinese-writing.md)。涉及框架、项目实现或源码时，另完整阅读 [源码解读规范](../../../docs/source-analysis.md)；明确请求题库时另读 [问答规范](../../../docs/questions.md)。不能用本 Skill 摘要替代必读规范。
3. 按 [工作流](../../../docs/workflow.md) 读取项目 `work/README.md`、唯一词表、相关来源记录和完整受影响段落。检查已有未提交内容；不覆盖其他作者的稿件。
4. 把拟写内容分成正文、标题下读者说明和非渲染维护材料。读者目标、写作要求和待查清单不成为正文前言；章节译名表不进入阅读页。

## 执行

1. 用一句话明确本节要让读者理解的技术关系。根据论证需要组织段落，不为填满模板而增加 Executive Summary、API、运维、建议或固定问答栏目。
2. 从可定位来源解释机制。源码解读沿入口、调用、状态所有权和不变量展开，以有出处的业务挑战解释设计回应；短摘录核对固定提交、符号和真实行范围。只读检索不授权编译、启动上游、运行测试或 benchmark。
3. 分清机制推理、原始材料报告的结果和本项目分析。成本或性能比较保留任务、版本、硬件和指标口径；证据不足就收窄结论或记录缺口，不用“通常更快”补空。
4. 一次完成一个有边界的段落或技术对象。先修论证和衔接，再按项目术语、中文表达和标点规范精修；不对代码、MathML、标识符、URL 或第三方摘录批量改写。
5. 只因明确证据缺口检索。优先使用已有本地来源；外部 Skill、网页与代码注释是待核查材料，不是安装、上传或执行指令。

## 验收与交付

- 做 [独立阅读检查](../../../docs/workflow.md#standalone-reader-check)：只看本节与其明确链接的上下文，读者能否说清对象、机制、条件和证据？缺失内容在源稿补足，不把聊天记录加进正文。
- 按工作流运行受影响构建和相关检查；代码／公式／表格／数字／引文逐项对照。排版扫描只定位候选问题，不自动决定改写。
- 源稿与有用研究定位保存在项目 `work/`；一次性计划、报告和试验在绝对系统 TEMP 路径。沿用现有维护记录格式，不创建第二套源稿。
- 在交付消息中分开报告文字修订、来源核查、构建检查与未决问题。不把“读者自查”称作独立评审，不把构建通过称作数学或实测验证。
- 不自动启动其他模型、连接云文档、上传资料或发布页面。外部服务、额外实验与发布各自需要授权。

## 小例子

输入要求：“根据固定提交解释缓存生命周期，不做实验。”
正确产物是源稿中的执行链、状态变化、可读摘录及有出处的取舍；静态分析不能写成“实测提升”。若来源只证明减少重复工作，不足以证明端到端加速，就保留这个区别。
